# aws01 IAM / 権限の基本 要件定義

## 1. 目的

AWSのユーザー、ロール、ポリシー、最小権限の考え方を、実AWS操作に入る前の設計知識として整理する。

## 2. 学習対象

- IAM User、IAM Role、Policyの違い
- identity-based policyとresource-based policyの違い
- allow、deny、明示的denyの優先
- 最小権限、権限境界、管理者権限の危険性
- アクセスキーをアプリに直書きしない理由

## 3. 要件

- 学習用の架空業務アプリを題材に、管理者、開発者、アプリ実行ロール、閲覧者を分ける。
- JSONポリシー例を読み、どの操作が許可されるかを説明できる。
- 実AWS認証情報は使わず、ポリシー読み取りと設計判断に限定する。
- 権限不足時に、何を確認すべきかをチェックリスト化する。

## 4. 成果物

- IAM概念整理
- 学習用ポリシー例
- 権限確認チェックリスト
- 実AWS利用時の注意事項

## 5. 完了条件

- User、Role、Policyの違いを説明できる。
- アプリ実行ロールに必要な権限だけを考えられる。
- アクセスキーをコードやGitに置かない理由を説明できる。
