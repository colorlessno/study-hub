# aws09 簡易デプロイの運用確認

小型APIのDocker imageをローカルでビルドしてコンテナを起動し、正常稼働、設定不足、実行中の障害、復旧を画面から確認します。クラウドへの公開は行いません。

## このテーマでできるようになること

- 利用者向けの応答と稼働確認用の応答を区別できる
- build時とruntime時の処理を区別し、環境変数を渡したコンテナを起動できる
- 必須設定が足りない状態を応答内容から特定できる
- 障害発生後のhealth応答と復旧後の応答を比較できる

## 最初に取り組むこと

1. Docker Desktopを起動し、StudyHubで「起動」を押す。
2. 実行ログで、`studyhub-aws09` imageのビルドと同名コンテナの起動を確認する。
3. 「正常時のhealth」を実行し、状態コード200と`ready`を確認する。
4. 「設定内容を確認」と「必須設定不足を確認」を実行し、状態コードの違いと不足した設定名を確認する。
5. 「実行中の障害を発生」を実行した後、「障害後のhealth」を実行する。
6. 「復旧」を実行し、もう一度「正常時のhealth」を実行する。
7. 実行ログで各要求のHTTPメソッドと経路を確認し、最後に「停止」でコンテナを削除する。

## 画面にある操作

| 操作 | 確認する内容 |
|---|---|
| 正常時のhealth | 稼働中は状態コード200と`state: ready`を返す |
| 利用者向け応答 | アプリ名、実行環境、利用者向けメッセージを返す |
| 設定内容を確認 | 標準で使う設定が揃っていることを返す |
| 必須設定不足を確認 | 存在しない`DEPLOY_TOKEN`を要求し、状態コード503と不足名を返す |
| 実行中の障害を発生 | 状態を`failed`へ変更し、状態コード500を返す |
| 障害後のhealth | 障害中は状態コード503を返す |
| 復旧 | 状態を`ready`へ戻す |

## 関連する教材

- `app/server.js`: 画面から操作するAPI本体
- `Dockerfile`: 本番相当のimage作成と非root実行の定義
- `.env.example`: ローカル起動に必要な環境変数の例
- `docs/deploy_checklist.md`: 公開前後に確認する内容
- `docs/cloud_service_comparison.md`: 公開先を比較するときの観点

教材全体の検証は、リポジトリ直下から次のコマンドで実行できます。

```bat
rtk node category\StudyAWS\scripts\validate-studyaws.mjs aws09
```

ローカルで正常に動くことは、クラウドへの公開成功を保証しません。実際に公開するときは認証情報、公開URL、ログ、費用、削除方法を別途確認します。
