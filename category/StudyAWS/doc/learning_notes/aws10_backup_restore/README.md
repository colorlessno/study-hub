# aws10 バックアップと復元

ダミーJSONを一時フォルダへコピーし、バックアップ、復元前確認、データ変更後の復元、内容比較を画面から実行します。教材内の元データや保存済みバックアップは変更しません。

## このテーマでできるようになること

- バックアップファイルの存在と内容一致を確認できる
- 復元前確認ではデータがまだ書き戻されないことを確認できる
- 変更したデータを復元し、元データと一致したことを確認できる
- バックアップがない場合に復元できない理由を説明できる

## 最初に取り組むこと

1. 「バックアップを作成」を実行し、作成結果と内容一致を確認する。
2. 「復元前確認」を実行し、変更後のデータが書き戻されずに残ることを確認する。
3. 「変更後のデータを復元」を実行し、復元前の変更と復元後の内容一致を確認する。
4. 「バックアップなしを確認」を実行し、`no_backup_found`を確認する。
5. 各操作の結果に`temporaryOnly: true`が含まれることを確認する。

各ボタンは独立した一時フォルダを使用します。ボタンを押すたびに元データを一時フォルダへコピーし、操作後はStudyHubが一時フォルダを削除します。

## 画面にある操作

| 操作 | 確認する内容 |
|---|---|
| バックアップを作成 | バックアップが作成され、元データと一致する |
| 復元前確認 | 変更後のデータとバックアップが異なり、復元処理はまだ行われない |
| 変更後のデータを復元 | 変更したデータがバックアップと元データの内容へ戻る |
| バックアップなしを確認 | 復元元がないため復元できないことを返す |

## 関連する教材

- `scripts/recovery_drill.js`: 画面から実行する一連の復旧確認
- `scripts/backup.js`: バックアップ作成の最小処理
- `scripts/restore.js`: 復元と復元前確認の最小処理
- `data/sample.json`: 復元対象に見立てたダミーデータ
- `docs/recovery_checklist.md`: 復元前後の確認内容
- `docs/rpo_rto_notes.md`: 復旧時点と復旧時間の考え方

教材全体の検証は、リポジトリ直下から次のコマンドで実行できます。

```bat
rtk node category\StudyAWS\scripts\validate-studyaws.mjs aws10
```

JSONファイルのコピーは、RDSのスナップショットやS3のバージョン管理を再現するものではありません。実データでは、復元対象、上書き範囲、暗号化、保持期間、復元後の確認方法を先に決めます。
