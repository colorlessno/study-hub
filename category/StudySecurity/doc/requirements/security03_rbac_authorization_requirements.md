# security03 RBAC認可 要件定義

## 1. 目的

roleによる操作権限の分離を学び、認証と認可の違いを理解する。

## 2. 学習対象

- RBAC
- role
- permission
- API guard
- 403

## 3. 作成する成果物

- RBACサンプル
- role / permission表
- 管理者API
- 一般ユーザー拒否例

## 4. 機能要件

| ID | 要件 |
|---|---|
| FR-01 | ユーザーにroleを持たせられる |
| FR-02 | 管理者だけ実行できるAPIを作れる |
| FR-03 | 一般ユーザーは403にできる |
| FR-04 | UI表示制御とAPI認可の違いを確認できる |

## 5. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | API側で必ず認可チェックする |
| NFR-02 | role定義を文書化する |
| NFR-03 | 権限不足時に内部情報を出さない |

## 6. 対象外

- ABAC
- 複雑な権限管理画面
- 組織階層権限

## 7. 受入条件

- 認証済みでも権限不足なら403になることを確認できる
- UI非表示だけでは不十分と説明できる
- roleとpermissionを分けて説明できる

## 8. 学習観点

- 認証は誰か、認可は何ができるか
- フロント制御だけでは守れない
- 403は権限不足を表す
