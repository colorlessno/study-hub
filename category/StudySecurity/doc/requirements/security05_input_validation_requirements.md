# security05 入力検証 要件定義

## 1. 目的

APIやファイル取込の境界で、型、必須、長さ、数値範囲、列数を検証し、エラーを利用者が扱える形で返す考え方を学ぶ。

## 2. 学習対象

- allowlist型の入力検証
- 型・形式・業務制約
- field単位のエラー
- CSV行と行番号
- サニタイズとの違い

## 3. 作成する成果物

- 商品入力validator
- CSV行validator
- 正常・異常サンプル
- 検証ケース表

## 4. 機能要件

| ID | 要件 |
|---|---|
| FR-01 | 商品名が必須の文字列であることを検証できる |
| FR-02 | 商品名を40文字以内に制限できる |
| FR-03 | 価格を0以上1,000,000以下の整数に制限できる |
| FR-04 | CSV行を3列に制限し、行番号付きエラーを返せる |
| FR-05 | 複数fieldのエラーを配列で返せる |

## 5. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | エラーへstack traceや内部例外を含めない |
| NFR-02 | 不正入力はローカルのダミーデータに限定する |
| NFR-03 | サニタイズだけで検証済みと扱わない |

## 6. 対象外

- HTTP APIと永続DB
- CSVファイルの読込・保存
- locale別の数値・文字正規化
- schema validation library

## 7. 受入条件

- 正常商品、必須違反、範囲違反を比較できる
- CSV列数違反に行番号が付くことを確認できる
- 型、形式、業務制約の違いを説明できる

## 8. 学習観点

- 信頼境界へ入った直後に検証する
- 利用者向けエラーと内部ログを分ける
- frontendの検証だけに依存しない
