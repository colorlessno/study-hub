# security12 監査ログ

重要な操作の成功と拒否を1行ずつJSONで記録し、追跡に必要な項目と秘密情報のマスクを確認するテーマです。

## このテーマでできるようになること

- 成功した操作と拒否された操作の記録を比較できる
- 誰が何を行ったかを追跡する項目を確認できる
- メールアドレスと秘密情報をログへ残さない処理を確認できる

## 最初に取り組むこと

1. 「成功と拒否の監査ログを比較」を実行する。
2. 2行のJSONで共通する項目と異なる項目を確認する。
3. 成功した操作と拒否された操作を個別に実行する。
4. 「監査ログの生成とマスク処理」を開き、出力結果と対応させる。
5. 「監査eventの項目定義」を開き、調査に必要な識別子と記録してはいけない値を区別する。

## 実行結果で確認すること

| 項目 | 役割 |
|---|---|
| `at` | 操作が発生したUTC時刻 |
| `actor` | 操作した利用者 |
| `action` | 行った操作 |
| `target` | 操作対象 |
| `result` | 成功または拒否 |
| `reason` | 拒否理由などの補足 |
| `requestId` | 同じリクエストに属する記録を追跡するID |

## マスク処理を確認する

- `demo@example.com`は`[email]`へ置き換える
- `example-api-token`は`[secret]`へ置き換える
- マスクは理由だけでなく全ての文字列項目へ適用する

この教材は標準出力へ表示するだけで、保存や検索は行いません。本番ではアクセス権限、保持期間、改ざんを防ぐ保存先、検索方法を別に設計します。
