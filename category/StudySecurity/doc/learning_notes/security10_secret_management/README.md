# security10 秘密情報管理

必須の秘密情報が未設定の状態と、環境変数から読み込める状態を比較するテーマです。値そのものを画面やログへ表示しない処理を確認します。

## このテーマでできるようになること

- 必須の環境変数がない場合に処理を止める理由を確認できる
- 設定名と秘密情報の値を分けて扱う実装を確認できる
- `.env.example`へ実際の秘密情報を書かない理由を確認できる

## 最初に取り組むこと

1. 「秘密情報が未設定の失敗を確認」を実行する。
2. 不足している設定名だけが表示され、値が表示されないことを確認する。
3. 「秘密情報を設定した成功を確認」を実行する。
4. 読み込んだ設定名と`values: masked`を確認する。
5. 「必須環境変数の検証処理」と「環境変数の記入例」を開いて結果と照合する。
6. 「秘密情報のローテーション手順」を開き、新値追加、切替確認、旧値失効、監査記録の順序を確認する。

## 実行結果で確認すること

| 操作 | 確認する結果 |
|---|---|
| 秘密情報が未設定 | `APP_SECRET`と`WEBHOOK_SECRET`が不足している |
| 秘密情報を設定 | 2つの設定名を読み込める |
| どちらの操作にも共通 | 秘密情報の値そのものを表示しない |

## 実装を確認する

- 必須の設定名を配列で管理する
- 空文字を未設定として扱う
- エラーには不足した設定名だけを含める
- 設定済みの場合も値を`masked`として扱う

環境変数へ置くだけで秘密情報が自動的に安全になるわけではありません。本番では秘密情報を保管・配布する仕組み、参照権限、更新手順、漏洩時の無効化が必要です。
