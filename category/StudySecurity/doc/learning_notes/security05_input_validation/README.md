# security05 入力検証

商品入力とCSV行を対象に、必須、型、長さ、数値範囲、列数を分けて検証する教材です。StudyHubから検証例と自動テストを実行し、結果と実装を対応付けます。

## このテーマでできるようになること

- 正常値、異常値、境界値で検証結果が変わることを確認できる
- 一つの入力に複数の問題がある場合のエラー配列を確認できる
- CSVのエラーへ行番号と項目名を付ける理由を説明できる
- 画面やCSVとは別に、サーバー側で入力検証が必要な理由を説明できる

## 最初に取り組むこと

1. StudyHubの「商品とCSVの入力検証を実行」を選ぶ。
2. 正常な商品、異常な商品、正常なCSV行、列数が不足したCSV行の結果を比較する。
3. 「境界値と異常値の自動テストを実行」を選び、すべて成功することを確認する。
4. 「入力検証の実装」と「境界値と異常値の自動テスト」を開き、各結果を返す条件を探す。
5. 「入力値と期待結果の対応表」で、境界値と期待結果を照合する。

## 画面で確認する内容

- 正常な商品では`errors`が空になる
- 空の商品名と負数価格では、nameとpriceのエラーが両方返る
- 価格0と1,000,000、商品名40文字は許可される
- 文字列の価格、1,000,001、小数は`invalid_range`になる
- CSVが3列でない場合は、行番号付きの`column_count`になる

## 実装との対応

`app/validators.js`の`validateProduct`が商品名と価格を検証し、`validateCsvRow`がCSVの列数と行番号を扱います。最初のエラーだけで終了せず、利用者が一度に修正できる項目を配列で返します。

## 学習用実装の範囲

- HTTP通信、実ファイルの読み込み、DB保存は行わない
- CSVの1列目にある商品IDは検証しない
- 文字の正規化、使用可能文字、言語別の入力規則は扱わない
