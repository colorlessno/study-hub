# security14 CORS

ブラウザ上のJavaScriptへ応答を公開してよい接続元、メソッド、要求ヘッダーを、サーバーがどのように判定するか確認します。

## このテーマで確認すること

- 許可された接続元の事前確認は204になる
- 許可されていない接続元は403になる
- 許可されていないメソッドと要求ヘッダーも403になる
- 許可された通常要求にはCORSヘッダーが付く
- CORSは認証や権限確認の代わりにはならない

## 最初に取り組むこと

1. StudyHubの「起動」を押す。
2. 「許可された事前確認」を実行し、204と`Access-Control-Allow-Origin`を確認する。
3. 「許可されていない接続元」を実行し、403と応答ヘッダーの違いを確認する。
4. 許可されていないメソッドと要求ヘッダーをそれぞれ実行する。
5. 「接続元と事前確認の判定処理」を表示し、許可条件と画面の結果を照合する。

## 画面で確認できる結果

| 操作 | 状態コード | 確認する内容 |
|---|---:|---|
| 許可された事前確認 | 204 | 接続元、認証情報、メソッド、要求ヘッダーの許可 |
| 許可されていない接続元 | 403 | 許可する接続元のヘッダーが付かない |
| 許可されていないメソッド | 403 | `DELETE`が許可対象外 |
| 許可されていない要求ヘッダー | 403 | `X-Internal-Secret`が許可対象外 |
| 許可されたGET要求 | 200 | 通常要求にも接続元別のヘッダーが付く |

## 実装の対応

- 接続元はscheme、host、portの組で完全一致させる。
- 事前確認では接続元、要求メソッド、要求ヘッダーをすべて確認する。
- `Vary`は接続元などによって応答が変わることをキャッシュへ伝える。

## 教材の範囲

CORSを強制するのはブラウザです。API自体の認証、権限確認、CSRF対策は別に必要です。
