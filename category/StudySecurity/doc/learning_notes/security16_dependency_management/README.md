# security16 依存関係の脆弱性確認

架空の監査結果を読み込み、重要度別の件数と対応候補へ整理します。外部のパッケージ登録先には接続しません。

## このテーマで確認すること

- 監査結果を重要度別に集計する
- 重要度が高い項目から並べる
- 修正版の有無を出力に残し、更新候補と調査候補へ分ける
- 不正な監査結果を処理せず、入力エラーとして拒否する
- 監査結果と変換後の出力を照合する
- 重要度だけで更新を決定しない

## 最初に取り組むこと

1. 「監査結果と対応候補」を実行し、件数と対応候補の全体を確認する。
2. 「重要度別の件数」を実行し、`high`と`moderate`が1件ずつ表示されることを確認する。
3. 「重要度順の対応候補」を実行し、`high`が先に表示されることを確認する。
4. 「不正な監査結果を拒否」を実行し、`vulnerabilities`が配列でない入力を拒否した結果を確認する。
5. 「監査結果の例」と「監査結果の集計と並べ替え」を表示し、`fixAvailable`が出力へ保持されることを確認する。
6. 「更新・調査・保留の判断基準」を表示し、自動更新だけでは判断できない項目を確認する。

## 画面で確認できる結果

| 操作 | 確認する結果 |
|---|---|
| 監査結果と対応候補 | `summary`と`actions`の両方を表示する |
| 重要度別の件数 | `high: 1`、`moderate: 1`を表示する |
| 重要度順の対応候補 | `high`、`moderate`の順と、それぞれの`fixAvailable`を表示する |
| 不正な監査結果を拒否 | `rejected: true`と入力エラーを表示する |

## 対応候補の意味

- `update`は修正版があるため、互換性とテスト結果を確認して更新を検討する。
- `review`は自動修正できないため、代替、緩和、保留を検討する。
- 保留する場合も、理由、担当者、期限、再確認条件を残す。

## 教材の範囲

架空の監査結果だけを使います。実際の依存関係、ロックファイル、SBOM、外部登録先は変更しません。
