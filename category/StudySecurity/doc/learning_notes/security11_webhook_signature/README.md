# security11 Webhook署名検証

正しい署名、改ざん、期限切れ、イベントID不足、同じイベントの再送をAPI操作で比較するテーマです。HMAC署名による改ざん検知と、イベントIDによる再送防止を分けて確認します。

## このテーマでできるようになること

- 正しい署名と改ざんされた本文の結果を比較できる
- 送信時刻の期限とイベントIDの役割を確認できる
- 署名検証だけでは同じイベントの再送を防げないことを確認できる

## 最初に取り組むこと

1. StudyHubで教材を起動する。
2. 「正しい署名を受け付ける」を実行し、status 200を確認する。
3. 改ざん、期限切れ、イベントID不足、64KiB超過を順に実行する。
4. 「同じイベントIDの再送を拒否」を実行し、1回目と2回目を比較する。
5. 署名処理と検証処理を開き、各結果を条件分岐と対応させる。
6. 「Webhookの再送防止」を開き、timestampとevent IDの役割を確認する。

## API操作で確認すること

| 操作 | 期待結果 | 意味 |
|---|---:|---|
| 正しい署名 | 200 | 本文と署名が一致する |
| 改ざんされた本文 | 401 | 署名対象の本文が変わっている |
| 期限切れ | 401 | 許容時間を超えている |
| イベントID不足 | 400 | 再送を識別できない |
| 64KiB超過 | 413 | 署名検証前に受信上限を超えている |
| 同じイベントIDを再送 | 1回目200、2回目409 | 処理済みイベントを拒否する |

## 実装を確認する

- timestamp、`.`、本文のバイト列を順にHMACへ渡す
- 署名は`timingSafeEqual`で比較する
- timestampは現在時刻との差が5分以内か確認する
- 署名検証に成功したイベントIDだけを処理済みとして記録する

処理済みイベントIDはメモリにだけ保存します。サーバーを再起動すると消えるため、本番では共有データベースなどへ保存し、業務処理と同じ単位で完了状態を管理します。
