# security19 データの保持と削除候補

データ種別ごとの保持日数、更新日、法的保全の有無から、削除候補を判定する教材です。実ファイルと実データベースは削除しません。

## このテーマでできるようになること

- 5件の保持判定と削除可否を確認できる
- 保持期間の境界、法的保全、不明種別の扱いを確認できる
- 全判定、理由別件数、削除候補、安全側の拒否結果を比較できる

## 最初に取り組むこと

1. 「全保持判定」を実行し、各データの経過日数、保持日数、理由、削除可否を確認する。
2. 「理由別の件数」を実行し、理由ごとの件数を確認する。
3. 「削除候補だけ」を実行し、期限超過かつ法的保全なしのデータだけが表示されることを確認する。
4. 「不正日付・未来日付」を実行し、どちらも削除候補にならないことを確認する。
5. 「保持期間と削除候補の判定」「保持判定に使う5件の例」「削除ワークフロー」を表示し、結果、実装、確認・承認・実行・証跡の流れを照合する。

## 5件の判定

| データ | reason | delete |
|---|---|---:|
| 期限超過の注文 | `retention_expired` | true |
| 保持期間内の問い合わせ | `within_retention` | false |
| 法的保全中の監査記録 | `legal_hold` | false |
| 保持期間と同じ365日の注文 | `retention_expired` | true |
| 不明なデータ種別 | `unknown_type` | false |

## 安全側に倒す2件

| データ | reason | delete |
|---|---|---:|
| 不正な更新日 | `invalid_updated_at` | false |
| 判定日より未来の更新日 | `future_updated_at` | false |

## 実装で確認すること

- `ageDays >= retentionDays`となった境界で期限超過とする
- 不明種別、不正日付、未来日付は自動削除しない
- 法的保全は期限超過より優先し、削除不可とする
- 削除候補にはIDだけでなく経過日数、保持日数、理由を残す
- 実運用では対象件数の上限、承認、再実行、部分失敗、監査記録も必要になる

## 学習用実装の範囲

- 固定の保持方針と判定日を使う
- 削除候補を表示するだけで、実データを更新しない
- バックアップ、キャッシュ、検索索引、分析データの削除は扱わない
