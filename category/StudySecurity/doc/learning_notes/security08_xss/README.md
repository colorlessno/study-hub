# security08 XSS対策

HTMLタグの形をした入力を`textContent`で文字として表示し、入力内容をHTMLとして解釈させない処理を確認する教材です。危険なHTMLは実行せず、安全な表示と危険な処理の違いを画面とソースで確認します。

## このテーマでできるようになること

- HTMLタグの形をした入力が文字として表示されることを確認できる
- `textContent`と`innerHTML`でブラウザの解釈が異なる理由を説明できる
- 出力先に応じて安全な処理を選ぶ必要性を説明できる
- CSPが危険なDOM操作の代わりにはならないことを説明できる

## 最初に取り組むこと

1. StudyHubでテーマを起動し、教材画面を表示する。
2. 初期値の`<b>sample</b>`で「安全に表示」を押す。
3. 安全な表示欄に、太字ではなく`<b>sample</b>`という文字が表示されることを確認する。
4. 引用符、記号、改行を追加して、入力内容が文字として表示されることを確認する。
5. 「安全な文字表示のJavaScript」を開き、`textContent`を使用している箇所を確認する。
6. 「出力先ごとの安全な処理」を開き、HTML本文・属性・URLの違いを確認する。

## 画面で確認する内容

- 入力値はHTMLとして実行されず、文字として表示される
- 安全な表示欄は`textContent`へ入力値を設定する
- 危険な処理の説明欄も文字表示だけを行い、`innerHTML`を実行しない
- 同じ入力でも、HTML本文・属性・URLでは必要な確認方法が異なる

## 実装との対応

`public/app.js`は入力値を取得し、安全な表示欄と説明欄へ`textContent`で設定します。`public/index.html`は確認用の入力欄、実行ボタン、結果欄を定義します。教材配信用の`app/server.js`は静的ファイルをローカルで配信します。

## 学習用実装の範囲

- 危険なHTMLを実行する比較画面は提供しない
- DBを使う格納型XSSと、サーバー応答を使う反射型XSSは再現しない
- CSP、sanitizer、framework固有APIは説明だけで扱う
