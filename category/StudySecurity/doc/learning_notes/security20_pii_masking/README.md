# security20 個人情報のマスキング

架空のメールアドレス、電話番号、顧客IDを種別ラベルへ置換し、ログやAI入力へ渡す前の処理と検出範囲を確認する教材です。実際の個人情報は使用しません。

## このテーマでできるようになること

- 3種類の架空情報が別々のラベルへ置換されることを確認できる
- 個人情報を含まない文章が変更されないことを確認できる
- 正規表現で検出できる範囲と、ログ・応答・評価データにも対策が必要なことを確認できる

## 最初に取り組むこと

1. 「3種類をまとめてマスク」を実行し、元の値が出力へ残らないことを確認する。
2. 「個人情報を含まない文章」を実行し、文章が変更されないことを確認する。
3. 「種類別の置換結果」を実行し、メール、電話番号、顧客IDの置換結果だけが表示され、マスク前の値が実行出力へ残らないことを確認する。
4. 「個人情報の置換処理」「置換結果の確認例」「マスキング方針」を表示し、結果と実装を照合する。

## 置換内容

| 種類 | 入力例 | 出力 |
|---|---|---|
| メールアドレス | `demo@example.com` | `[email]` |
| 電話番号 | `03-1234-5678` | `[phone]` |
| 顧客ID | `CUST-12345` | `[customer-id]` |

## 実装で確認すること

- 置換後の文章だけを出力し、置換前の値をデバッグログへ残さない
- メールアドレスと電話番号は国や表記によってパターンが変わる
- 顧客IDを個人情報として扱うかはデータ分類で決める
- 正規表現に一致しない表記は検出できず、数字の一律置換は業務データも失う
- AIへ送る入力だけでなく、応答、実行ログ、評価データも対象にする

## 学習用実装の範囲

- 日本の一部電話番号形式と架空IDだけを正規表現で扱う
- 実際の個人情報、実ログ、外部AI APIは使用しない
- 高度な固有表現抽出とDLP製品は扱わない
