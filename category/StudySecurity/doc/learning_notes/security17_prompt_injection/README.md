# security17 プロンプトインジェクション対策

入力を通常回答、要確認、拒否へ分類し、AIへ渡す入力と外部操作の間に必要な防御を確認する教材です。外部AI APIと実際の秘密情報は使用しません。

## このテーマでできるようになること

- 通常の問い合わせ、命令上書きの疑い、秘密情報の要求を画面で比較できる
- `answer`、`review`、`reject`と判定理由の対応を確認できる
- 信頼するsystem指示と、信頼しないuser入力が別の欄・別の値として扱われることを確認できる
- 判定結果が許可された`decision`と`reason`の組だけであることを検証できる
- 入力判定だけでは防げない範囲と、権限制限・実行前確認の必要性を確認できる

## 最初に取り組むこと

1. StudyHubで教材を起動する。
2. 「通常の問い合わせ」を選び、「判定する」を押す。
3. 「命令上書きの疑い」と「秘密情報の要求」も同じ手順で判定する。
4. 結果の`inputBoundary`でsystem指示とuser入力が分離され、user入力が`untrusted_data`であることを確認する。
5. `outputValid`が`true`であり、出力が`decision`と`reason`の許可された組であることを確認する。
6. 「入力の判定処理」「判定に使う入力例」「入力境界と出力検証の方針」を表示し、結果と実装を照合する。
7. 確認後に教材を停止する。

## 判定結果

| 入力例 | decision | reason |
|---|---|---|
| 通常の問い合わせ | `answer` | `normal` |
| 命令上書きの疑い | `review` | `instruction_override_pattern` |
| 秘密情報の要求 | `reject` | `secret_request` |

`review`は安全という意味ではなく、別の確認へ回す状態です。`reject`にしても、秘密情報をモデルへ渡さない設計と外部操作の権限制限は別に必要です。

画面のsystem指示は防御方針の例であり、user入力から書き換えません。判定後は`decision`と`reason`のキー、許可値、組み合わせを検証し、検証結果を`outputValid`へ表示します。

## 実装で確認すること

- 既知の文字列を判定するだけなので、言い換えや別言語をすべて検出できない
- モデルの応答を拒否させるだけでなく、利用できるツールと権限を制限する
- 外部操作の直前に、対象、引数、権限、承認状態を検証する
- 入力と判定結果のログへ秘密情報や個人情報を残さない

## 学習用実装の範囲

- キーワードを使う決定的な分類だけを行う
- LLMと外部ツールを実行しない
- 判定結果から実際の変更処理を行わない
