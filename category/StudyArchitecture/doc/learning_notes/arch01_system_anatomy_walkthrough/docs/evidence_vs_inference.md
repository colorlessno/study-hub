# arch01の証拠と推測

## 直接確認できる証拠

- `app/server.js`は`127.0.0.1`で待ち受ける。
- `POST /api/orders`は入力を検証し、注文をSQLiteへ保存する。
- `request_logs`はTrace ID、method、path、statusを保存する。
- 障害モード中も`/health`は200を返し、`/ready`と注文登録は503を返す。
- 同じSQLiteファイルを指定して再起動すると、保存済み注文とログを再読込できる。

## 設計意図としての推測

- 1プロセス構成は、学習者が処理経路を追いやすくする目的だと推測できる。
- SQLite採用は、別DBサーバーなしで永続化を観察する目的だと推測できる。
- healthとreadyの分離は、運用上の受付可否を説明する目的だと推測できる。

## 主張を分類する

| 主張 | 種別 | source / 次の確認 |
|---|---|---|
| arch01が`/health`を公開する | 証拠 | route実装とHTTP応答 |
| 注文が停止・再起動後も残る | 証拠 | 同じSQLiteを使った再起動後の一覧 |
| 1プロセス構成は教材を簡単にするためである | 推測 | 要件・設計の目的と照合する |
| 大規模運用でもSQLiteが最適である | 未確認 | 性能・可用性要件がないため断定しない |

推測を消す必要はない。推測であることを明記し、確認または反証に必要な証拠を決める。
