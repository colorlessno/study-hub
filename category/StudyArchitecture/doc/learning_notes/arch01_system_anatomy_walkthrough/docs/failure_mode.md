# arch01の失敗時の動き

## 実際に観察できる失敗

| 失敗 | 見える症状 | 確認する証拠 | 復旧 |
|---|---|---|---|
| 商品名が空 | 注文登録が400を返す | API応答、`request_logs`の400 | 商品名を入力して再送する |
| 数量が0以下または整数でない | 注文登録が400を返す | API応答、`request_logs`の400 | 正整数へ修正して再送する |
| 教材用障害モード | `/health`は200、`/ready`と注文登録は503 | health / ready応答、API応答、503ログ | 障害モードを解除する |
| SQLiteへアクセスできない | 起動またはAPI処理が失敗する | サーバー標準出力、保存先パス | 保存先のパスと権限を直して再起動する |
| 未定義route | 404を返す | API応答、`request_logs`の404 | 正しいpathへ修正する |

## 障害モードの確認順

1. 正常時に`/health`、`/ready`、注文登録が成功することを確認する。
2. 画面から障害モードを開始する。
3. `/health`が200のまま、`/ready`と注文登録が503になることを確認する。
4. 実行ログで503のpathとTrace IDを確認する。
5. 障害モードを解除し、`/ready`と注文登録が正常へ戻ることを確認する。

## 読み解くポイント

プロセスが生きていることと、新しい注文を安全に受け付けられることは同じではない。arch01は`health`と`ready`を分け、この境界を実行結果で観察できるようにしている。
