# arch02の残リスク

| risk | 残る理由 | 後で下げる方法 |
|---|---|---|
| 201 / 202の解釈が未決定 | 教材fixtureとして意図的に差を残している | API契約の採用値を決定し、設計・実装・利用側を統一する |
| 大量データ時の性能が未確認 | 教材は小さなSQLiteデータだけを扱う | 別の性能要件とデータ量を定義して順番に測定する |
| 不正入力の網羅性が限定的 | 必須値とレビュー状態だけを検証する | 文字数や許可文字など必要な契約を追加する |

## review終了ルール

残リスクがあってもレビュー結果は保存できる。ただし、未実行の確認を通過扱いにせず、残る理由と次の確認方法をSQLiteのレビュー記録へ残す。
