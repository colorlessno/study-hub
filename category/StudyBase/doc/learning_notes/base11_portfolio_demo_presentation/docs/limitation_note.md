# 制限メモ

## ひな形

```text
現在の制限:
<この成果物がまだ扱っていないこと>

なぜ重要か:
<広く使う場合の影響。>

次の改善:
<1つの具体的な改善または確認作業>
```

## 例

| 制限 | 良い次の改善 |
| --- | --- |
| ローカルのDocker環境だけで確認済み | 継続的インテグレーションで基本動作テストを実行する |
| 疑似データだけを使用 | 実際に近い初期データと境界条件を追加する |
| 1人での操作だけを確認 | 複数利用者が同時に操作する場合を確認する |
| 手動確認だけを実施 | 変更後の動作を自動確認するテストを追加する |

## ルール

制限を具体的に書き、次の改善へつなげることで、確認した範囲を正確に説明できます。
