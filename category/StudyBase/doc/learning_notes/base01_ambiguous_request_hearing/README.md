# base01 曖昧依頼のヒアリング

曖昧な依頼を、目的、現状、課題、制約、成功条件、確定情報、仮定、未確定事項へ分け、要件定義へ渡す前の情報を整えるテーマです。

## このテーマでできるようになること

- 依頼者の言葉と自分の解釈を分けて記録できる
- 解決策を決める前に、目的、現状、課題、制約、関係者、成功条件を整理できる
- 確定情報、仮定、未確定事項を分けられる
- 未確定事項について、確認内容、確認先、期限、次の対応を残せる
- ヒアリングメモと要件定義入力メモをMarkdownで作成できる

## 最初に取り組むこと

1. 「教材を表示」でヒアリングメモ作成画面を開く。
2. 「固定シナリオを読み込む」を押し、依頼原文と既知情報を確認する。
3. 目的、現状、課題、成功条件が、解決策を決め打ちした内容になっていないことを確認する。
4. 確定情報、仮定、未確定事項の違いを確認する。
5. 未確定事項の確認先と次の対応を確認する。
6. ブラウザ内へ保存し、再読み込み後に入力が復元されることを確認する。
7. 二種類のMarkdownを表示し、ヒアリング内容と要件定義への引き継ぎ内容の違いを確認する。

入力内容はブラウザ内だけに保存されます。実在する秘密情報、個人情報、顧客情報は入力しないでください。

## 整理するときの判断基準

| 分類 | 判断基準 |
|---|---|
| 依頼原文 | 依頼者から受け取った言葉を加工せずに残す |
| 確定情報 | 根拠や確認済みの事実がある |
| 仮定 | 作業を進めるために暫定的に置いた条件である |
| 未確定事項 | 関係者への確認や追加調査が必要である |
| 成功条件 | 達成したかどうかを関係者が判断できる |

## 自分の言葉で説明する

- 「取りこぼしをなくす」という依頼だけでは、なぜ実装へ進めないか。
- CRM導入は確定情報、仮定、解決案のどれに当たるか。
- 未確定事項に確認先と期限が必要なのはなぜか。
- ヒアリングメモと要件定義入力メモは、用途がどう違うか。
