# base07 ブランチ・マージ・競合解消

mainとfeature/aで同じ行を別々に変更し、履歴の分岐、競合の発生、両方の意図を残す解消、解消後の確認を実際のGitで体験します。

## このテーマでできるようになること

- ブランチを作成し、現在位置と分岐した履歴を確認できる
- 競合中のGit状態と競合マーカーを読める
- mainとfeature/aの変更意図を統合して競合を解消できる
- 解消後のファイル、Git状態、コミット履歴を確認できる

## 最初に取り組むこと

1. 「ブランチを作成」を実行し、mainとfeature/aの位置を確認する。
2. 「ブランチ別のコミットを確認」を実行し、2本に分かれた履歴を読む。
3. 「競合を発生」を実行し、`UU`と`<<<<<<<`、`=======`、`>>>>>>>`を確認する。
4. 「競合を解消」を実行し、両方の意図を含む差分と解消コミットを確認する。
5. 「解消後を確認」を実行し、競合マーカーがなく、変更一覧が空であることを確認する。

「すべての手順を確認」では、分岐から解消後の確認までを一つの実行結果で追えます。各操作は一時フォルダ内の練習用リポジトリで行われ、教材原本と本体リポジトリは変更されません。

## 実行結果の読み方

- `git branch`は現在のブランチと存在するブランチを示す。
- `git log --all --graph`はmainとfeature/aの履歴が分かれた位置を示す。
- `UU conflict_target.txt`は、両側で変更され、まだ解消されていない状態を示す。
- 競合マーカーの上側が現在のブランチ、下側が取り込むブランチの内容を示す。
- 解消後の`git status --short`が空なら、解消内容がコミット済みである。
