# base11 詳細設計

## 入力項目と内部名

| 画面表示 | 内部名 | 必須 |
|---|---|---|
| 成果物の名前 | `title` | 必須 |
| 想定する聞き手 | `audience` | 必須 |
| 解決する問題 | `problem` | 必須 |
| 利用者が行う主な操作 | `mainFlow` | 必須 |
| 主な構成 | `components` | 必須 |
| 確認できた事実 | `verified` | 必須 |
| 見せる証拠 | `evidence` | 1件以上、3件まで使用 |
| 現在の制限 | `limitation` | 必須 |
| 次に改善すること | `nextStep` | 必須 |

## 説明案の作成処理

`presentation.js` が入力値の前後の空白と連続する空白を整理します。証拠は改行で分割し、空行を除き、先頭から3件だけを使用します。

`validatePresentationInput` は必須項目を確認し、未入力の画面表示名を返します。`buildPresentationArtifacts` は検証済みの入力から、次の4種類を同時に作成します。

| 戻り値 | 内容 |
|---|---|
| `sixty` | 60秒の説明案 |
| `three` | 3分の説明案 |
| `five` | 5分の説明案 |
| `recording` | 録画構成 |

## 画面制御

`main.js` は入力欄を内部名でまとめます。「記入例を読み込む」は固定の記入例を入力欄へ設定します。説明案の各ボタンは現在の入力を作成処理へ渡し、結果を `textContent` で表示します。

必須項目が不足している場合は説明案を表示せず、不足している項目名を表示します。「入力を消す」はすべての入力、メッセージ、表示結果を初期状態へ戻します。

## セキュリティと安全な表示

- 入力と出力は `textContent` またはフォームの `value` として扱う
- 入力文字列をHTMLとして解釈しない
- 外部通信、ファイル保存、ブラウザの記憶領域への保存を行わない
- 画面に個人情報、秘密情報、顧客情報を入力しないよう明記する

## 確認方法

- 記入例から4種類の説明案を作成する
- 空の入力で不足項目が返ることを確認する
- 証拠を4件入力し、出力が3件になることを確認する
- 説明案に成果物名、確認した事実、制限、次の改善が含まれることを確認する
- 狭い画面幅で入力欄とボタンが縦に並ぶことを確認する
