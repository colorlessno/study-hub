# base04 テスト成立条件チェック 要件定義

## 目的

テストを実施する前に、環境、データ、手順、権限、外部連携、判定基準がそろっているか確認できるようにする。

## 利用者が画面で行うこと

- テスト名、テスト対象、対象の状態を記録する。
- URL、DB、外部連携、アカウント、ログ確認先の内容と状態を記録する。
- アカウント、必要な権限、最大2件のテストデータを記録する。
- 期待結果、合否基準、中止条件、証拠の保存先、判定者、代替確認を記録する。
- 各項目の状態から開始可能、開始不可、保留の判定を確認する。
- 入力内容を保存し、3種類の文書をプレビューまたはダウンロードする。

## 入力

| 入力 | 内容 |
|---|---|
| 対象 | テスト名、テスト対象、対象の状態 |
| 環境 | URL、DB、外部連携、アカウント、ログ確認先と各状態 |
| アカウント・権限 | 利用するアカウント、必要な権限、状態 |
| テストデータ | データID、作成方法、初期状態、期待状態、後片付け、状態 |
| 判定条件 | 期待結果、合否基準、中止条件、証拠の保存先、判定者、代替確認 |

## 出力

- テスト成立条件チェックリスト
- テスト環境確認表
- テストデータ確認表

出力はMarkdownとし、選択中の文書をファイルとして保存できるようにする。

## 判定

- 1件でも「不足」があれば「開始不可」とする。
- 「不足」がなく、「保留」または「未確認」があれば「保留」とする。
- すべて「確認済み」であれば「開始可能」とする。

## 保存と復元

入力内容はブラウザのローカルストレージへ保存する。画面を再表示したときに復元し、利用者の操作で消去できるようにする。

## 安全性

- 入力値をHTMLとして実行しない。
- 外部サービスへ入力内容を送信しない。
- 秘密情報、個人情報、実顧客情報を入力しない注意を表示する。
- 条件不足をテスト失敗として扱わない。

## 対象外

- 詳細なテストケース全量作成
- 自動テスト実装
- テスト管理ツール導入
- 環境項目とテストデータ行の追加・削除

## 受入確認

- 固定シナリオを読み込める。
- 状態変更に応じて開始可否が更新される。
- 必須項目や使用中のデータ行に不足がある場合は保存とダウンロードを行わない。
- 3種類の文書を切り替えて確認できる。
- 保存後の再表示で入力内容を復元できる。
- 保存内容を消去できる。
