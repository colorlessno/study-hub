# base11 要件定義

## 目的

学習成果物について、作ったもの、利用者の操作、構成、確認した事実、未確認の範囲を分けて説明できるようにします。StudyHubのテーマ画面内で説明内容を入力し、説明時間に合わせた台本と録画構成を作成します。

## 利用する場面

- 学習した内容を他の人へ説明する
- ポートフォリオで成果物の動作と構成を見せる
- 実装済みの範囲と今後の予定を区別して伝える

## 画面で行うこと

- 記入例を読み込める
- 成果物、聞き手、問題、主な操作、構成、確認結果を入力できる
- 見せる証拠を3件まで入力できる
- 現在の制限と次の改善を別々に入力できる
- 60秒、3分、5分の説明案を作成できる
- 録画時に画面を見せる順番を作成できる
- 入力を消して最初からやり直せる
- 未入力の項目がある場合は、項目名を表示して作成を中止する

## 入力

| 入力 | 内容 |
|---|---|
| 成果物の名前 | 説明するテーマやアプリの名前 |
| 想定する聞き手 | 学習者、採用担当者、開発者など |
| 解決する問題 | 誰の何が不便なのか |
| 利用者が行う主な操作 | 実際に見せる一連の操作 |
| 主な構成 | 画面、API、データ保存などの関係 |
| 確認できた事実 | テストや実行で確認した結果 |
| 見せる証拠 | 画面、API応答、実行ログ、テスト結果、ソースなど |
| 現在の制限 | 未実装または未確認の範囲 |
| 次に改善すること | 制限に対する具体的な次の作業 |

## 出力

60秒版は要点だけを示します。3分版は問題から制限までの説明順を加えます。5分版は設計上の説明と、失敗時に示す事実を加えます。録画構成は、実際に画面で見せる順番を示します。

## 安全性

- 個人情報、秘密情報、顧客情報を入力しない
- 実装していない機能を実績として書かない
- 未確認の内容を確認済みとして書かない
- 入力内容はブラウザ内で処理し、外部へ送信しない
- テキストファイルはUTF-8（BOMなし）で管理する

## 受入条件

- 記入例から4種類の説明案を作成できる
- 60秒、3分、5分で説明内容の詳しさが変わる
- 証拠は入力順に最大3件だけ表示される
- 必須項目が未入力の場合は、不足項目が分かる
- StudyHubの教材欄で画面、README、記入例、ソースを切り替えられる
