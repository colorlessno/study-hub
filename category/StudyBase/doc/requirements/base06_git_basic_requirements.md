# base06 Git基本操作 要件定義

## 目的

Gitの基本操作を、実際の状態と差分を見ながら理解できるようにします。AIが変更したソースをそのままコミットせず、対象と内容を確認してから履歴へ残すための基礎を扱います。

## 利用者が行うこと

StudyHubのテーマ画面から確認したいGit状態を選び、実行結果を読みます。操作は一時フォルダ内の練習用リポジトリで行い、本体リポジトリには影響させません。

## 必要な機能

| 機能 | 内容 |
|---|---|
| 変更前の確認 | 変更がない`git status --short`を表示する |
| 未ステージの確認 | ファイル変更後の`git status`と`git diff`を表示する |
| ステージ済みの確認 | `git add`後の状態と`git diff --staged`を表示する |
| コミットの確認 | コミット後の状態と直近の履歴を表示する |
| 除外の確認 | `.gitignore`へ一致したファイルと、変更一覧へ出ない状態を表示する |
| 一括確認 | 各状態を正しい順番でまとめて表示する |

## 安全性

- 教材原本へ`.git`を作らない
- StudyHub本体のGit状態を変更しない
- 一時フォルダ以外のファイルを追加、変更、削除しない
- リモート接続、push、既存ブランチの変更を行わない
- Gitの利用者名とメールアドレスは練習用リポジトリ内だけに設定する

## 画面へ表示する情報

- 選択できる操作名
- 実行したGitコマンド
- コマンドの標準出力と標準エラー
- 状態の意味を補う短い説明
- README、練習原本、記録ひな形、ソース、設計文書

## このテーマで扱わないこと

ブランチ、マージ、競合解消、GitHub上のIssue・Pull Request、CI/CDは後続テーマで扱います。

## 確認する結果

- 変更前、未ステージ、ステージ済み、コミット済みを区別できる
- `git diff`と`git diff --staged`の対象を説明できる
- `.gitignore`に一致したファイルが変更一覧へ出ないことを確認できる
- コミット前に`git status`とステージ済み差分を確認する理由を説明できる
