# base07 ブランチ・マージ・競合解消 要件定義

## 目的

別々のブランチで作成された変更の競合解消までを、実際のGit状態とファイル内容を見ながら理解できるようにします。AIや他の開発者が作った変更を取り込む際に、片方を機械的に選ばず、両方の意図を確認して統合する基礎を扱います。

## 利用者が行うこと

StudyHubのテーマ画面から確認したい段階を選び、ブランチ、履歴、競合状態、競合マーカー、解消内容、解消後の状態を読みます。操作は一時フォルダ内の練習用リポジトリで行い、本体リポジトリには影響させません。

## 必要な機能

| 機能 | 内容 |
|---|---|
| ブランチ作成 | mainからfeature/aを作成し、現在位置と一覧を表示する |
| 分岐した履歴 | mainとfeature/aへ異なる変更をコミットし、グラフを表示する |
| 競合の再現 | 同じ行を変更した2本をマージし、失敗結果、`UU`、競合マーカーを表示する |
| 競合の解消 | 両方の変更意図を含む内容へ修正し、ステージ済み差分と解消コミットを表示する |
| 解消後の確認 | ファイル内容、変更のない状態、解消を含む履歴を表示する |
| 一括確認 | 分岐から解消後の確認までを正しい順番でまとめて表示する |

## 安全性

- 教材原本へ`.git`を作らない
- StudyHub本体のブランチ、履歴、ファイルを変更しない
- 一時フォルダ以外のファイルを追加、変更、削除しない
- リモート接続、fetch、pull、pushを行わない
- Gitの利用者名、メールアドレス、除外設定は練習用リポジトリ内だけに設定する

## 画面へ表示する情報

- 選択できる段階名
- 実行したGitコマンド
- コマンドの標準出力と標準エラー
- 分岐したコミット履歴
- 競合中と解消後のファイル内容
- README、練習原本、記録ひな形、ソース、設計文書

## このテーマで扱わないこと

Pull Request、GitHub上のレビュー、rebase、履歴の書き換え、リモートリポジトリへの反映は後続テーマで扱います。

## 確認する結果

- ブランチがコミット履歴の別々の位置を指すことを確認できる
- 同一行を別々に変更するとマージ競合になることを確認できる
- 3種類の競合マーカーと`UU`の意味を説明できる
- 両方の意図を統合した解消内容を差分で確認できる
- 解消後に競合マーカーがなく、Git状態が変更なしになることを確認できる
