# base04 テスト成立条件チェック 基本設計
## 画面の役割

テスト前提を入力し、対象、環境、アカウント、データ、判定条件の状態から開始可否を判断して3種類の文書へ変換する静的Web画面とする。

## 画面の流れ

| 手順 | 画面で扱う内容 |
|---|---|
| 対象・環境 | テスト名、テスト対象、URL、DB、外部連携、アカウント、ログ確認先 |
| アカウント・データ | アカウント、権限、2件分のテストデータと各状態 |
| 判定条件 | 期待結果、合否基準、中止条件、証拠の保存先、判定者、代替確認 |
| 開始可否・保存 | 開始可否、状態別件数、保存、出力 |

画面上部の4つの手順ボタンと、画面下部の「前の手順」「次の手順」で移動する。

## 主な操作

| 操作 | 結果 |
|---|---|
| 固定シナリオを読み込む | 受注照会画面の結合テスト条件を各入力欄へ設定する |
| 状態を変更する | 確認済み、不足、保留、未確認から開始可否を再判定する |
| ブラウザ内に保存 | 必須項目と使用中のデータ行を確認し、入力値をローカルストレージへ保存する |
| 出力文書を切り替える | 3種類のMarkdownプレビューを切り替える |
| 表示中の文書をダウンロード | 選択中の文書をUTF-8のMarkdownとして保存する |
| 保存内容をクリア | 保存値と入力欄を消去し、最初の手順へ戻る |

## 出力文書

| 文書 | 内容 |
|---|---|
| テスト成立条件チェックリスト | 対象、環境、アカウント、データ、判定基準、開始可否、中止条件、証拠、代替確認 |
| テスト環境確認表 | URL、DB、外部連携、アカウント、ログ確認先の内容と状態 |
| テストデータ確認表 | データID、作成方法、初期状態、期待状態、後片付け、状態 |

## 表示と保存の方針

- 画面は単一ページ内の4手順に分割し、一度に全入力欄を表示しない。
- 入力はプレーンテキストとして扱い、HTMLを実行しない。
- ローカルストレージのキーはテーマ専用とし、他テーマの保存値と混在させない。
- 外部通信は行わない。
