# base01 曖昧依頼のヒアリング 基本設計

## 画面の役割

曖昧な依頼を四つの手順で整理し、ヒアリングメモと要件定義入力メモを作る静的Web画面とする。

| 手順 | 入力する内容 |
|---|---|
| 依頼 | 依頼原文、既知情報 |
| 整理 | 背景、目的、現状、課題、制約、関係者、成功条件 |
| 未確定事項 | 確定情報、仮定と根拠、未確定事項、確認先、期限、次の対応 |
| 要約・保存 | 要件定義へ渡す要約、推奨する次工程 |

## 保存と出力

- ブラウザ内保存には`localStorage`を使う。
- 保存済みの入力は画面再読込後に復元する。
- ヒアリングメモと要件定義入力メモは、それぞれプレビューとMarkdownダウンロードを提供する。
- クリア操作はこのテーマの保存内容だけを削除する。

## 教材との対応

- 固定シナリオは曖昧依頼サンプルと記入例を画面入力へ展開する。
- 二種類のMarkdownは既存テンプレートの項目構成に対応させる。
- README、テンプレート、記入例、画面制御、記録変換、設計文書をStudyHubの関連ファイルとして表示する。

## 安全性

- 通信処理やサーバー保存を持たせない。
- 外部サービスへ接続しない。
- ダウンロードするファイルは利用者が入力した教材用データだけで作る。
