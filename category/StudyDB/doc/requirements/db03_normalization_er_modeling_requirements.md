# db03 要件定義
## 正規化とERモデリング

## 1. 目的

業務の名詞と関係からテーブル候補を洗い出し、正規化、ER図、リレーションを使って重複や更新不整合を減らす設計を学ぶ。

## 2. 学習対象

- 要件からエンティティを抽出する手順
- 1対多、多対多
- 第1正規形、第2正規形、第3正規形
- 逆正規化の入口
- ER図とテーブル定義

## 3. 機能要件

| ID | 要件 |
|---|---|
| FR-01 | 顧客・注文・注文明細・商品を題材にエンティティを抽出する |
| FR-02 | 非正規な表を正規化する手順を用意する |
| FR-03 | 1対多、多対多、中間テーブルを説明する |
| FR-04 | ER図またはテキストER表を作る |
| FR-05 | 逆正規化が必要になる条件を整理する |
| FR-06 | 正規化の判断、ER表、逆正規化の判断を記録するひな形を用意する |

## 4. 非機能要件

- 正規化は暗記ではなく、更新不整合を避ける目的から説明する。
- ER図はツール依存にせず、Markdown表でも表現できるようにする。
- 作成するテキストファイルは UTF-8 BOMなしとする。

## 5. 対象外

- 大規模データモデリング
- DDD詳細
- 物理設計の深掘り

## 6. 成果物

```text

  doc/basic_design/db03_basic_design.md
  doc/detailed_design/db03_detailed_design.md
  doc/learning_notes/db03_normalization_er_modeling/
```

## 7. 受入条件

- 非正規な表の問題点を説明できる。
- 正規化後のテーブル分割理由を説明できる。
- 多対多を中間テーブルで表現できる。
- 設計結果をひな形から作成したUTF-8 Markdownファイルへ記録できる。
