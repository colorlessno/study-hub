# db02 SQLの基本操作とテーブル設計 要件定義

## 学習者が体験すること

学習者はStudyHubのdb02画面から教材用PostgreSQLを起動し、顧客・商品・注文・注文明細のテーブルを対象にSQLを実行する。SQLの成功結果と制約違反のエラーを実際に確認し、テーブル定義と実行結果を対応付ける。

## 画面に必要な内容

- テーブルと制約の役割を確認する学習項目
- 教材DBの起動、停止、状態更新
- SQLを目的別に選択する操作欄
- SQLの標準出力とエラーを表示する実行結果
- 実行環境の処理状況を表示する実行ログ
- SQLソース、説明、記録用ひな形、設計文書の切り替え表示

## 画面から実行する操作

| 操作 | 実行する処理 | 学習者が確認すること |
|---|---|---|
| スキーマと初期データを準備 | スキーマの再作成と初期データの登録 | テーブル作成とデータ登録の順序 |
| 検索・登録・更新・削除を確認 | 4種類のSQLを順番に実行 | 操作前後のデータの変化 |
| テーブルの結合結果を確認 | INNER JOINとLEFT JOINを実行 | 関連データの結合方法と結果の違い |
| メールアドレスの重複拒否を確認 | 一意制約に反する登録 | 重複値が拒否される理由 |
| 必須項目の拒否を確認 | 必須制約に反する登録 | 顧客名の欠落が拒否される理由 |
| 存在しない顧客参照の拒否を確認 | 外部キー制約に反する登録 | 存在しない親データの参照が拒否される理由 |
| 負の価格の拒否を確認 | 価格の制約に反する登録 | 業務ルールに反する値が拒否される理由 |
| 数量0の拒否を確認 | 数量の制約に反する登録 | 0件の注文明細が拒否される理由 |

## 教材と記録に必要な内容

- スキーマ、初期データ、基本操作、テーブル結合、制約違反のSQLソース
- 各テーブルの役割と制約の対応を整理した説明
- 予想、実際の結果、理由を残す実行記録
- 制約違反のエラーと拒否理由を残す記録

## 安全性と実行環境

- 接続先はDocker Desktop上の教材用PostgreSQLに限定する。
- 教材DBはdb02専用のDocker Composeプロジェクト名で起動する。
- 停止時はdb02専用のコンテナ、ネットワーク、ボリュームだけを削除する。
- 教材データに実在の個人情報や顧客情報を使用しない。

## 受入確認

- db02画面から起動・停止できる。
- 8種類の操作を個別に選択できる。
- 正常なSQLの結果と、意図した制約違反のエラーを画面に表示できる。
- 11件の教材・ソース・記録用ひな形・設計文書を切り替えて表示できる。
- 7件の学習項目を個別に保存、一括選択、リセットできる。
