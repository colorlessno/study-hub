# db02 SQLの基本操作とテーブル設計 基本設計

## 全体構成

db02はStudyHubのテーマ画面、教材用PostgreSQL、SQLソース、記録用文書で構成する。StudyHubがDocker Composeを介してPostgreSQLを管理し、学習者が画面で選択したSQLだけを実行する。

```text
db02テーマ画面
  ├─ 起動・停止・状態更新
  ├─ SQL操作の選択と実行
  ├─ 実行結果と実行ログ
  └─ 教材・ソース・記録用ひな形の切り替え
          ↕
StudyHubサーバー
          ↕ Docker Compose
db02専用PostgreSQL
```

## 画面の構成

| 画面部品 | 表示する内容 | 学習者の操作 |
|---|---|---|
| テーマ情報 | テーマ名、表示方法、実行方法、必要な環境 | 学習対象と前提を確認する |
| 学習項目 | 7件の確認項目と進捗 | 個別選択、一括選択、リセットを行う |
| 操作 | 実行環境の状態 | 起動、停止、状態更新を行う |
| 実行 | 8種類のSQL操作 | 操作を選択して実行する |
| 実行結果 | コマンドの終了コードと出力 | 予想と実際の結果を比較する |
| 教材 | README、SQLソース、説明、記録用ひな形、設計文書 | ボタンで表示対象を切り替える |
| 実行ログ | DockerとPostgreSQLの出力 | 起動失敗やSQLエラーの原因を確認する |

## 操作の分け方

スキーマ作成と初期データ登録は、後続操作の前提を揃えるため1つの操作にまとめる。基本操作、テーブル結合、5種類の制約違反は、目的と結果を比較しやすくするため個別の操作に分ける。

制約違反のSQLは非0で終了するが、学習用の期待した結果として出力を保持し、次の操作を続行できるようにする。

## データの構成

| テーブル | 主なデータ | 主な制約 |
|---|---|---|
| `customers` | 顧客名、メールアドレス | メールアドレスの一意性、顧客名の必須性 |
| `products` | 商品名、価格 | 価格が0以上 |
| `orders` | 顧客、注文日時、状態 | 存在する顧客の参照 |
| `order_items` | 注文、商品、数量、単価 | 存在する注文と商品の参照、数量は1以上 |

## 環境の管理

- Docker Composeプロジェクト名は `studyhub-db02` に固定する。
- ホスト側のPostgreSQLポートは自動割当てとし、既存環境との衝突を避ける。
- 起動時はPostgreSQLが利用可能になるまで待つ。
- 停止時はdb02専用のボリュームも削除し、次回の実行を初期状態から開始する。
