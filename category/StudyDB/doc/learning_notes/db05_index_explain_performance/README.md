# db05 索引・EXPLAIN・性能比較

索引を作成する前後の実行計画を比較し、PostgreSQLが選んだ検索方法を根拠に性能を考えるテーマです。

## このテーマでできるようになること

- Seq ScanとIndex Scanの違いを実行計画から読み取れる
- 索引作成前後の推定行数、実測行数、除外行数を比較できる
- 索引があっても使われにくい検索条件を説明できる
- 実行時間だけでなく、実行計画全体から改善効果を判断できる

## 最初に取り組むこと

1. Docker Desktopが起動していることを確認し、画面の「起動」を押す。
2. 「比較用データを準備」を実行し、注文データが20004件作成されることを確認する。
3. 「索引作成前の実行計画を確認」を実行し、Seq Scanが使われている箇所を探す。
4. 「比較用の索引を作成」を実行する。
5. 「索引作成後の実行計画を確認」を実行し、前の結果と比較する。
6. 「索引が使われにくい検索を確認」を実行し、列の型変換や関数が計画へ与える影響を確認する。
7. 確認後に「停止」を押す。

## 実行計画で比較する項目

- Seq Scan、Index Scan、Bitmap Scanなどの検索方法
- plannerが見積もった行数と実際に処理した行数
- Filterで除外された行数
- 並べ替えやテーブル結合を含む計画全体の変化

実行時間はPCの状態でも変わります。「実行計画の記録」を使い、索引作成前後の構造の違いを中心に比較します。

## StudyWebとの関係

「StudyWebとの関係」では、`web50` のN+1問題、`web51` のWeb側の索引比較と、このテーマで扱うDB側の実行計画確認の役割を整理しています。Web側の症状だけで判断せず、DBが選んだ検索方法と照合してください。
