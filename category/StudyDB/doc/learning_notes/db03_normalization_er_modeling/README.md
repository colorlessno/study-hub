# db03 正規化とERモデリング

非正規な注文表を分解し、データの重複と更新時の不整合を減らすテーブル構成を考えるテーマです。

## このテーマでできるようになること

- 非正規な表で起きる更新・追加・削除時の問題を具体例で説明できる
- 第1正規形、第2正規形、第3正規形で何を分離したか説明できる
- ERモデルの主キーと外部キーをたどり、テーブル間の関係を説明できる
- 読み取りを優先して非正規化する場合の利点と同期の危険を説明できる

## 最初に取り組むこと

1. 「非正規な注文表」を開き、同じ意味の値が繰り返されている箇所を探す。
2. 「正規化の手順」を開き、問題のある列がどのテーブルへ分離されたか確認する。
3. 「ERモデル」を開き、主キーと外部キーでテーブル同士がどう結ばれているか確認する。
4. 「非正規化の検討」を開き、複製する値と正本として残す値を区別する。
5. 「設計結果を記録する」を開き、任意の作業フォルダーへ別名のUTF-8 Markdownファイルとして保存してから、自分の判断を記入する。

## 確認すること

- 顧客情報を1か所で管理すると、顧客名の変更漏れを防げること
- 注文明細を分離すると、1件の注文に複数商品を持たせられること
- 商品名などを注文時点の記録として残す場合は、現在値とは別の意味になること
- 非正規化した値は、正本との同期方法が必要になること

このテーマでは外部サービスやDockerを起動しません。StudyHubは資料とひな形の参照に使用し、設計結果はブラウザ内に閉じず、自分で保存したMarkdownファイルへ記録します。
