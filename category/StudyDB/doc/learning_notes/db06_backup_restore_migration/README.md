# db06 バックアップ・復元・マイグレーション

バックアップを取得するだけで終えず、別のデータベースへ復元できることと、構造変更後も必要なデータが保たれることを確認するテーマです。

## このテーマでできるようになること

- バックアップと復元を別の操作として説明できる
- 元のデータベースを変更せず、別のデータベースで復元結果を確認できる
- マイグレーション前後で守る件数、NULL、既定値を確認できる
- 失敗した場合の中止条件と切り戻し方針を整理できる

## 最初に取り組むこと

1. Docker Desktopが起動していることを確認し、画面の「起動」を押す。
2. 「変更前のデータを準備して確認」を実行し、顧客と注文の件数を確認する。
3. 「バックアップを別DBへ復元」を実行し、復元先の顧客件数が3件であることを確認する。
4. 「マイグレーションを適用して確認」を実行し、追加された列と既定値を確認する。
5. 「バックアップ・復元記録」と「マイグレーション確認表」に実行結果を整理する。
6. 確認後に「停止」を押す。

## 実行結果の見方

- バックアップは `db06` スキーマを一時ファイルへ保存する
- 復元先には元DBと異なる `studydb_restore` を使う
- 復元先の顧客件数が3件なら、保存したデータを読み戻せている
- マイグレーション後は顧客のメールアドレスがNULLではなく、注文状態が `created` になる

バックアップの存在だけでは復元可能とは判断できません。画面の復元結果と変更後確認SQLの両方を根拠にします。

## StudyAWSとの関係

「StudyAWSとの関係」では、`aws10` が扱うクラウド側のバックアップ運用と、このテーマで扱うDBスキーマ変更・復元確認の役割を整理しています。復元できるかを実データ件数で確認する工程は、このテーマで実行します。
