# db02 SQLの基本操作とテーブル設計

顧客、商品、注文、注文明細のテーブルを使い、SQLによる検索・登録・更新・削除、テーブル結合、制約違反の動きを確認するテーマです。

## このテーマでできるようになること

- テーブル定義と初期データの役割を説明できる
- SELECT、INSERT、UPDATE、DELETEでデータがどう変わるか確認できる
- INNER JOINとLEFT JOINの結果の違いを説明できる
- 主キー、外部キー、一意制約、必須制約、値の制約が何を守るか説明できる
- エラーの内容から、どの制約に反したか判別できる

## 最初に取り組むこと

1. 「テーブル定義SQL」と「テーブルと制約の整理」を開く。
2. customers、products、orders、order_itemsの関係を確認する。
3. 同じメールアドレスの重複、存在しない顧客への参照、負の価格がどの制約で拒否されるか予想する。
4. Docker Desktopを起動し、StudyHubの「起動」を押す。
5. 操作欄から「スキーマと初期データを準備」を選び、実行する。

## 画面から確認できる操作

| 操作 | 確認する内容 |
|---|---|
| スキーマと初期データを準備 | テーブルの作成と教材データの登録 |
| 検索・登録・更新・削除を確認 | SQLの操作と処理前後のデータ |
| テーブルの結合結果を確認 | 注文から顧客・商品・明細を追う結果と、関連する注文がない顧客の扱い |
| 各制約の拒否を確認 | 一意制約、必須制約、外部キー、値の制約が返すエラー |

操作ごとに結果を予想し、実行後に「実行結果を記録する」へ実際の結果と理由を記入します。制約違反は意図したエラーです。

## 教材を直接検証する場合

リポジトリルートで次を実行すると、スキーマ、基本操作、テーブル結合、制約違反を自動確認できます。

```cmd
rtk node category\StudyDB\scripts\validate-studydb.mjs db02
```

接続先はローカルの教材用PostgreSQLに限ります。確認後はStudyHubの「停止」で教材DBを停止します。
