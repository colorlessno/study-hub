# テーブルと制約の整理

## テーブルの役割

| テーブル | 役割 | 主な関係 |
|---|---|---|
| `db02.customers` | 顧客 | 1人の顧客が複数の注文を持つ |
| `db02.products` | 商品 | 1つの商品が複数の注文明細から参照される |
| `db02.orders` | 注文 | 1件の注文が1人の顧客と複数の注文明細を持つ |
| `db02.order_items` | 注文明細 | 注文と商品を結び、数量と注文時の単価を持つ |

## 制約が守る内容

| 制約 | 対象の例 | 拒否するデータ |
|---|---|---|
| 主キー | 各テーブルの `id` | 同じ行を識別する値の重複 |
| 外部キー | `orders.customer_id` | 存在しない顧客を指す注文 |
| 一意制約 | `customers.email` | 同じメールアドレスの重複 |
| 必須制約 | `customers.name` | 顧客名の欠落 |
| 値の制約 | `products.price >= 0` | 負の価格 |
| 値の制約 | `order_items.quantity > 0` | 0以下の数量 |

制約は、アプリの入力確認を通り抜けた場合でも、DB内の最低限の整合性を守ります。
