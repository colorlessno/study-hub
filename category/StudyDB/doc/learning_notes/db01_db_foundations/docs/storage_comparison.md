# 保存方式を比較する

保存方式は「何を入れられるか」だけでなく、「誰が更新するか」「どのように探すか」「どこを正本にするか」で選びます。

| 保存方式 | 得意なこと | 不得意なこと | 主な用途 |
|---|---|---|---|
| ファイル | 単純な保存、配布、差分管理 | 複数処理から届く更新要求の調整、複雑な検索、データ同士の整合性 | 設定、ログ、エクスポート |
| Excel | 人が表を直接編集、計算、確認 | 大量の更新要求の順序管理、厳密な履歴管理、細かな権限制御 | 小規模管理、集計の下書き |
| オブジェクトストレージ | 大きなファイルの保存、大量保管 | 複雑な条件検索、行単位の更新 | 画像、PDF、バックアップ |
| RDB | 整合性、SQLによる条件検索、表同士の結合、取引処理 | 頻繁に形が変わる階層データ、全文検索専用の処理 | 顧客、注文、在庫などの業務データ |
| 全文検索用DB | 文書内の単語検索、表記揺れ、検索順位 | 正本の厳密な更新、複数データを一つの取引として確定する処理 | 商品検索、文書検索 |
| DWH | 大量の履歴集計、分析 | 頻繁な1件更新、業務処理の即時確定 | 売上分析、BI |
| Vector DB | 意味が近い文書の検索 | 完全一致検索、正本の整合性管理 | AI検索、RAGの候補取得 |

全文検索用DB、DWH、Vector DBは、RDBなどの正本からデータを複製して使うことがあります。検索や分析を速くするための保存先を、正本と混同しないことが重要です。
