# devops04 Playwrightによる画面操作テスト

ブラウザで入力、ボタン操作、結果表示を行い、利用者と同じ流れを自動確認するテーマです。

## このテーマでできるようになること

- Playwrightで画面操作テストを実行できる
- 正常な入力と未入力の二つの動作を確認できる
- テスト対象画面の要素とテストの操作を対応付けられる
- 失敗時のscreenshot、trace、reportの保存先を説明できる

## 最初に取り組むこと

1. 「テスト対象画面」で入力欄、送信ボタン、結果欄を確認する。
2. 「画面操作テスト」で二つの利用手順を確認する。
3. 「Playwrightの設定」でテスト対象画面の起動方法を確認する。
4. 「画面操作テストを実行」を選び、二つのテスト結果を確認する。
5. 「実際のGitHub Actions定義」で、失敗時artifactを保存するstepを確認する。

## 確認する内容

一つ目のテストは名前を入力して送信し、あいさつが表示されることを確認します。二つ目のテストは入力せずに送信し、入力エラーが表示されることを確認します。

Playwrightの設定がテスト対象画面を自動起動するため、画面用の別サーバーを手作業で起動する必要はありません。

二つのテストはworker数1で一つずつ実行します。失敗時は`test-results/`にscreenshotとtrace、`playwright-report/`にHTML reportが保存されます。GitHub Actionsではこれらを`devops04-playwright-failure`というartifactとしてアップロードします。画面や入力に秘密情報を使わないため、artifactにも秘密情報を残しません。

## 自分の言葉で説明する

- APIのテストだけでは画面操作の成功を確認できない理由
- テスト用の識別子で画面要素を選ぶ利点
- 正常な操作と入力エラーの両方を確認する理由
- screenshot、trace、HTML reportを使い分ける理由
