# devops05 データベースを含む自動テスト

PostgreSQLの起動準備、テーブル作成、初期データ投入、データ操作の確認を一続きで実行するテーマです。

## このテーマでできるようになること

- DBの受付準備完了を待ってからテストを実行できる
- テーブル定義、初期データ、テスト処理を対応付けられる
- 毎回同じ初期状態から確認する理由を説明できる
- DB接続失敗時のログと後片付け手順を説明できる

## 最初に取り組むこと

1. 「テーブル定義」でtasksテーブルの項目を確認する。
2. 「初期データ」でテスト開始前に登録される内容を確認する。
3. 「データベースのテスト」で追加、読み取り、削除の順序を確認する。
4. DBを起動し、「データベースの自動テストを実行」を選ぶ。
5. 「実際のGitHub Actions定義」で、失敗ログ表示と保存領域削除の順序を確認する。

## 確認する内容

コンテナが起動しただけでは、DBがSQLを受け付けられるとは限りません。Docker ComposeはDBの受付準備完了を待ってからテストを実行します。

テストは初期データを確認し、新しいデータを追加して読み取り、最後にテストで追加したデータを削除します。停止時に保存領域を削除するため、次回も同じ初期状態から確認できます。

DB接続に失敗した場合は、GitHub Actionsの`Show container logs after failure`でdbサービスのhealthcheck、認証値、初期化SQLのエラーを確認します。その後は成功・失敗にかかわらず`docker compose down --volumes`を実行し、教材用DBの保存領域を削除します。

## 自分の言葉で説明する

- DBの受付準備完了を待つ必要がある理由
- 初期データとテスト中に追加するデータを分ける理由
- 停止時にDBの保存領域を削除する理由
- DB接続失敗時にhealthcheckと初期化SQLのログを確認する理由
