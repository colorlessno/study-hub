# devops09 障害対応記録

固定されたローカル教材シナリオを使い、障害の受付、証拠の保存、原因の仮説、対応判断を順番に記録します。

## このテーマでできるようになること

- 初動で確認する順序を説明できる
- 事実・仮説・判断を分けて記録できる
- 一時対応、恒久対応、再発防止を区別して整理できる
- 調査結果をMarkdownの障害対応記録として残せる

## 最初に取り組むこと

1. 教材画面の「1. 受付」で、固定シナリオの概要、影響、Severityを記入する。
2. 「2. 証拠」で、変更前に保存するhealth、ready、container、request IDの情報を記入する。
3. 「3. 判断」で、確認できた事実、原因の仮説、実施する対応の判断を分けて記入する。
4. 「4. 対応・保存」で、一時対応、回復確認、恒久対応、再発防止を記入して保存する。
5. Runbook、Docker調査チェックリスト、記入例と自分の記録を比較する。
6. 「CI workflow」で、Runbook、記入例、記録変換処理を順番に検査するstepを確認する。

## 教材画面の使い方

- 上部の4つの手順ボタンで、表示する記録欄を切り替える。
- 「ブラウザ内に保存」を押すと、入力内容がこのブラウザのlocalStorageへ保存される。
- ページを再読み込みし、保存した内容が復元されることを確認する。
- 「Markdownをダウンロード」を押し、記録をテキストファイルとして確認する。
- 「保存内容をクリア」を押すと、ブラウザ内に保存した記録だけが削除される。

入力内容はサーバーへ送信されません。秘密情報、個人情報、実顧客情報は入力せず、固定の教材シナリオだけを使用します。

## 記録するときの区別

| 種類 | 記録する内容 |
|---|---|
| 事実 | 実際に確認した応答、状態、ログ、時刻 |
| 仮説 | 原因として考えていることと、その反証方法 |
| 判断 | 実施すること、見送ること、その根拠とリスク |
| 一時対応 | 影響を抑えるために先に行う対応 |
| 恒久対応 | 原因を取り除くための修正 |
| 再発防止 | 再発を検知または防止するテスト、監視、手順 |

## 初動で確認する順序

1. 対象環境、担当、判断者を確定する。
2. 利用者影響と未確認の範囲を分ける。
3. Severityを仮決定する。
4. 変更前にhealth、ready、containerの状態、request ID、重要ログを保存する。
5. 仮説ごとに根拠と反証方法を記録する。
6. 一時対応の期待効果、リスク、戻し方を記録してから判断する。

回復確認と原因特定は別々に判断します。応答が戻っても、原因や再発防止が未確認ならその状態を記録に残します。
