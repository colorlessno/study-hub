# devops08 Dockerログによる障害調査

正常、起動失敗、処理失敗の三つのコンテナを比較し、状態、応答、ログから障害を区別するテーマです。

## このテーマでできるようになること

- コンテナの状態から起動失敗を見分けられる
- 応答とログをリクエストIDで対応付けられる
- 起動失敗と処理中の失敗を別々に調査できる

## 最初に取り組むこと

1. 「3種類のコンテナ構成」で各コンテナの設定を確認する。
2. Docker環境を起動し、三つのコンテナ状態を表示する。
3. 正常応答とcontainer内診断を順に実行し、正常系の状態と安全に表示する項目を確認する。
4. 起動失敗のログを表示し、処理開始前に終了した理由を確認する。
5. 処理失敗の応答とログを表示し、状態コード、エラーコード、リクエストIDを対応付ける。
6. 「port競合の切り分け」でbind errorと使用中processの確認順を確認する。
7. 三つの障害信号を自動テストする。

## 確認する内容

app-missing-envは必要な設定値がないため、サーバーを開始する前に終了します。app-runtime-errorはサーバーを起動できますが、リクエスト処理中に500を返します。

コンテナ状態、終了コード、応答、構造化ログを組み合わせると、起動前の失敗と処理中の失敗を区別できます。調査結果は「障害調査メモ」で、確認した事実と原因の推測を分けて整理します。

container内診断は、教材用の`APP_MODE`、`PORT`、作業ディレクトリだけを表示します。環境変数の全件や秘密値は表示しません。port競合の調査でも、PIDの所有者を確認せずprocessを停止しません。

## 自分の言葉で説明する

- 再起動する前にログと終了コードを残す理由
- 起動失敗と処理中の失敗で確認する情報が異なる理由
- Docker全体ではなく対象のCompose環境だけを停止する理由
