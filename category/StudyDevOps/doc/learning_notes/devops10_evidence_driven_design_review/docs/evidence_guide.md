# リリース判定で使う証拠

## 自動確認

| 証拠 | 確認する内容 | 記録例 |
|---|---|---|
| build | 配布物を作成できるか | `npm run build` 成功 |
| test | 変更の影響を自動確認できるか | 103件成功 |
| CI | 同じ確認を共有環境で再現できるか | workflow成功 |
| API | 主要な要求へ期待した状態コードを返すか | `GET /api/health` が200 |
| DB変更 | 適用手順と後戻り方法が確認済みか | migration確認済み |

## 運用確認

| 証拠 | 確認する内容 | 注意点 |
|---|---|---|
| health | プロセスが応答できるか | 依存先の利用可否とは分ける |
| readiness | 要求を受け付けられるか | DBや外部サービスも含める |
| ログ | 失敗をrequest IDで追えるか | 秘密情報を含めない |
| 監視 | 異常を検知できるか | 通知先と判断者を明確にする |
| ロールバック | 変更前へ戻せるか | 手順だけでなく実行条件も確認する |

## 判定

- リリース可: 必須証拠がそろい、未解決リスクが受容範囲にある。
- 条件付き可: 期限、担当者、追加確認を明記した条件がある。
- リリース不可: 必須証拠の失敗または未確認があり、影響を受容できない。
