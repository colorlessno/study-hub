# web31 基本設計
## Issue / PR 風 作業記録

---

## 1. システム構成設計

### 1.1 全体構成

```text
StudyHubテーマ画面（読み取り専用）
  ├─ doc/templates/web31_issue_pr_style/
  │    ├─ issue-template.md
  │    └─ pr-template.md
  └─ doc/learning_notes/web31_issue_pr_style/
       ├─ README.md
       ├─ gitea-practice-entry.md
       └─ examples/
```

### 1.2 コンポーネント一覧

| コンポーネント | 役割 |
|---|---|
| `issue-template.md` | 作業開始前の整理 |
| `pr-template.md` | 変更後の説明 |
| `examples/` | 記入例 |
| `README.md` | 使い方説明 |
| `gitea-practice-entry.md` | 実際のIssue・PR操作を行うbase08への案内 |
| StudyHubテーマ画面 | 保存済み文書を読み取り専用で切り替えて表示 |

---

## 2. 主要設計方針

- 背景、目的、やること、完了条件を Issue で整理する
- 変更概要、理由、影響範囲、確認結果を PR で整理する
- 就活・実務の両方で使える簡潔な形式にする

---

## 3. IF仕様

### 3.1 Issue項目IF

| 項目 | 内容 |
|---|---|
| 背景 | なぜ必要か |
| 目的 | 何を達成するか |
| やること | チェックリスト |
| 完了条件 | 何をもって完了か |

### 3.2 PR項目IF

| 項目 | 内容 |
|---|---|
| 変更概要 | 何を変えたか |
| 変更理由 | なぜ変えたか |
| 影響範囲 | どこに影響するか |
| 確認結果 | どう確認したか |
| 未対応事項 | 残り作業 |

---

## 4. 処理フロー

```text
作業前
  ↓
Issueテンプレートに背景/目的/完了条件を書く
  ↓
作業実施
  ↓
PRテンプレートに変更概要/確認結果を書く
  ↓
振り返り
```

---

## 5. データ設計

DBは使用しない。Markdownテンプレートの記録項目を管理対象とする。作成したIssue・PR文書は、ひな形を別ファイルへコピーしてエディターで保存する。

---

## 6. プロンプト・AI制御設計

AI処理は使用しない。

---

## 7. ガードレール・エラー処理設計

- 変更理由と変更内容を混ぜない
- 確認していないことを確認済みと書かない
- 影響範囲が不明な場合は不明と明記する

---

## 8. 非機能・運用設計

- Markdownで作成する
- チェックリストを使う
- 小さな作業にも使える分量にする

---

## 9. 技術スタック

| 用途 | 技術 |
|---|---|
| ドキュメント | Markdown |
| 運用想定 | GitHub Issue / Pull Request |

---

## 10. 画面一覧

単独アプリ画面は持たない。StudyHubテーマ画面でREADME、ひな形、記入例、Gitea演習案内、正式設計文書を読み取り専用で表示する。

---

## 11. 権限制御

認証・認可は扱わない。

---

## 12. 主要導線

| 導線 | 内容 |
|---|---|
| Issue作成 | 背景と完了条件を整理 |
| 作業 | チェックリストを進める |
| PR記録 | 変更と確認結果を書く |

---

## 13. 画面遷移図

StudyHubテーマ画面内で教材ボタンを選び、表示文書を切り替える。実際のGitea操作は案内先のbase08で行う。

---

## 14. 画面項目定義

StudyHubテーマ画面には教材切替ボタンと文書表示領域を持つ。テンプレート項目は IF仕様に記載する。

---

## 15. シーケンス図

```text
学習者 -> issue-template: 作業前整理
学習者 -> 作業: 実装/修正
学習者 -> pr-template: 変更説明
学習者 -> examples: 記入例確認
```
