# web47 PDFファイル選択時の検証 基本設計

## 画面の構成

画面は、説明、用意された確認データ、自分のファイル選択、検証結果の順に表示します。

用意された確認データには「小さいPDF」「PDF以外」「容量超過PDF」を置き、ファイルを準備しなくても判定を再現できるようにします。自分のファイル選択では、手元のPDFを選択できます。

検証結果には、判定、ファイル名、容量、ファイルの種類、問題の内容を表示します。

## 操作と画面の変化

| 操作 | 画面の変化 |
|---|---|
| 確認データを押す | 対応するファイル情報を検証して表示する |
| 自分のPDFを選ぶ | 選んだファイルの情報を検証して表示する |
| 結果をリセットする | ファイル選択と検証結果を初期状態へ戻す |

## 処理の分担

| ファイル | 担当 |
|---|---|
| `app/index.html` | 操作と結果表示の構造 |
| `app/src/main.js` | 操作受付と画面更新 |
| `app/src/file-validation.js` | 確認データ、判定、容量表示 |
| `app/src/style.css` | 配置、ボタン、正常・問題ありの見た目 |

## 画面内で扱うデータ

画面内の確認データと利用者が選んだ`File`は、どちらも`name`、`size`、`type`を持つ入力として同じ判定処理へ渡します。ファイル本体は送信または保存しません。

## 確認する状態

- 初期状態
- 問題なし
- 拡張子と種類に問題あり
- 容量に問題あり
- 自分のファイルを選択した状態
- リセット後の初期状態
