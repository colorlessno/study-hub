# web12 基本設計
## shadcn/ui風ダッシュボード

---

## 1. システム構成設計

### 1.1 全体構成

```text
React App
  ├─ AppSidebar
  ├─ Header
  ├─ StatCard
  └─ DataTable
```

### 1.2 コンポーネント一覧

| コンポーネント | 役割 |
|---|---|
| `AppSidebar` | 管理画面のナビゲーション |
| `Header` | 選択中セクションのタイトルと画面種別ラベル |
| `StatCard` | 指標カード |
| `DataTable` | 一覧テーブル |
| `App.tsx` | ダッシュボード全体を構成 |

---

## 2. 主要設計方針

### 2.1 画面設計方針

- 管理画面らしい情報密度を保つ
- サイドバー、ヘッダー、指標、テーブルを明確に分ける
- ランディングページ風の装飾は避ける

### 2.2 UI部品方針

- shadcn/ui の考え方に寄せた再利用可能な部品構成にする
- Tailwind CSS で見た目を調整する
- Button / Card / Table 相当の部品を使う

---

## 3. IF仕様

### 3.1 コンポーネントIF

| コンポーネント | 入力 | 出力 |
|---|---|---|
| StatCard | タイトル、数値、補足 | 指標カード |
| DataTable | 固定行データ | テーブル |
| AppSidebar | `currentSection`、`onSelect` | ナビゲーションと選択通知 |
| Header | `currentSection` | 選択中セクションの見出し |

### 3.2 画面操作IF

| 操作 | 処理 | 出力 |
|---|---|---|
| メニュー選択 | 選択stateを更新 | 選択状態、Header見出し、結果文を更新 |
| テーブル確認 | 固定データを表示 | 一覧確認 |

---

## 4. 処理フロー

```text
アプリ起動
  ↓
固定の指標データと一覧データを読み込む
  ↓
Sidebar / StatCard / DataTable に渡す
  ↓
ダッシュボードを表示
```

---

## 5. データ設計

| データ | 型 | 用途 |
|---|---|---|
| Stat | `{ label, value, note }` | 指標カード |
| TableRow | `{ id, name, status, updatedAt }` | 一覧表示 |
| MenuItem | `{ label, icon, active }` | サイドバー |

DBは使用しない。

---

## 6. プロンプト・AI制御設計

AI処理は使用しない。

---

## 7. ガードレール・エラー処理設計

- テーブルが狭い画面で崩れないようにする
- 情報量を増やしすぎない
- コンポーネントの props 型を定義する

---

## 8. 非機能・運用設計

- Vite + React + TypeScript を使う
- Tailwind CSS を使う
- 管理画面として読みやすい余白と文字サイズにする
