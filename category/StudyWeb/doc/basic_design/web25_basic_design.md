# web25 基本設計
## Next.js フォーム送信

---

## 1. システム構成設計

### 1.1 全体構成

```text
Browser
  ↓ form submit
Next.js App
  ├─ app/page.tsx
  └─ app/actions.ts
```

### 1.2 コンポーネント一覧

| コンポーネント | 役割 |
|---|---|
| `page.tsx` | フォーム表示 |
| `actions.ts` | Server Actions による送信処理とバリデーション |
| README | 分離構成との違いを説明 |

---

## 2. 主要設計方針

- Next.js 内でフォーム送信を処理する
- 入力値をサーバー側で検証する
- DB保存は必須にせず、成功/エラー表示を優先する
- React + NestJS 分離構成との違いを README に記載する

---

## 3. IF仕様

### 3.1 入力IF

| 項目 | 型 | 必須 |
|---|---|---|
| `title` | string | yes |
| `description` | string | no |

### 3.2 送信結果

| 状態 | 表示 |
|---|---|
| 正常 | 成功メッセージ |
| 異常 | エラーメッセージ |

---

## 4. 処理フロー

```text
フォーム入力
  ↓
送信
  ↓
Next.js側のactionで入力取得
  ↓
バリデーション
  ├─ OK: 成功表示
  └─ NG: エラー表示
```

---

## 5. データ設計

DBは使用しない。フォーム入力値と結果メッセージのみ扱う。

---

## 6. プロンプト・AI制御設計

AI処理は使用しない。

---

## 7. ガードレール・エラー処理設計

- 空タイトルはエラーにする
- サーバー側検証を必ず行う
- 本格的な永続化は対象外とする

---

## 8. 非機能・運用設計

- Next.js + TypeScript を使う
- App Router を使う
- 最小構成でフォーム処理を確認する

---

## 12. 主要導線

| 導線 | 内容 |

| 入力 | フォームに入力 |

| 結果確認 | 成功/エラーを見る |

---

## 13. 画面遷移図

```text
フォーム画面
  └─ 同一画面で結果表示
```

---

## 14. 画面項目定義

| 項目 | 種別 | 内容 |
|---|---|---|
| タイトル | input | 必須 |
| 説明 | textarea | 任意 |
| 送信ボタン | button | 送信 |
| 結果表示 | alert | 成功/エラー |

---

## 15. シーケンス図

```text
学習者 -> Browser: フォーム送信
Browser -> Next.js Action: form data
Next.js Action -> Next.js: validation
Next.js -> Browser: result
```
