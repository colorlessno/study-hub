## 2. 主要設計方針

### 2.1 UI設計方針

- カードにはタイトル、説明、タグ、操作ボタンを配置する
- Tailwind のユーティリティクラスで余白、色、枠線、影を指定する
- `hover:` とレスポンシブクラスを使い、状態変化と画面幅対応を確認する
- 操作ボタンで選んだカード名をstateへ保持し、結果領域へ表示する

### 2.2 スタイル設計方針

- 独自CSSは最小限にする
- クラスの羅列が読みにくくなりすぎないよう、UIを小さく分ける
- 色は複数の役割で使い分け、単調な配色にしない

## 3. IF仕様

### 3.1 表示IF

| 条件 | 表示 |
|---|---|
| PC幅 | カードを複数列表示 |
| スマートフォン幅 | カードを1列表示 |
| hover | ボタンまたはカードの状態を変化 |

### 3.2 コンポーネントIF

| データ | 用途 |
|---|---|
| カードタイトル | 見出し表示 |
| 説明文 | 本文表示 |
| タグ | 分類表示 |

### 3.3 イベントIF

| イベント | 処理 | 出力 |
|---|---|---|
| カードの「表示例」をクリック | `selectedTitle`を更新 | 選択したカード名を結果領域へ表示 |

---

## 4. 処理フロー

```text
npm run dev
  ↓
Vite起動
  ↓
Reactがカード配列を表示
  ↓
Tailwindクラスでスタイル適用
  ↓
画面幅やhoverに応じて見た目が変化
  ↓
操作ボタンで選択stateと結果を更新
```

## 7. ガードレール・エラー処理設計

- Tailwind が反映されない場合は設定ファイルと CSS 読み込みを確認する
- 長い文字列でカード幅が破綻しないようにする
- レスポンシブ表示で横スクロールが出ないことを確認する
