# web37 業務用入力フォーム

依存パッケージを使わない静的HTMLとJavaScriptで、入力検証、項目別エラー、内容確認、送信中制御、成功、送信失敗、修正・再試行の導線を確認する。要件にあるAPI送信風処理として1秒の待機を使い、成功と失敗を安全に再現する。

## このテーマでできるようになること

- 顧客名未入力・メール形式誤り・備考文字数超過の3種類のエラーを確認できる
- 正しい内容を入力して確認画面を開き、値を見直してから送信または入力修正を選べる
- 成功を選び、送信中の表示から成功表示へ変わることを確認できる
- 送信中は送信・修正ボタンが無効になり、同じ操作を繰り返せないことを確認できる
- 送信失敗を選び、フォーム全体エラー、入力値の保持、再試行導線を確認できる

## 最初に取り組むこと

1. StudyHubの「教材を表示」で入力フォームを開く。
2. すべて空欄で「入力内容を確認」を押し、顧客名とメールのエラーを確認する。
3. 顧客名を入力し、メールに`example`を入れて形式エラーを確認する。
4. 備考に201文字を入れ、文字数エラーを確認する。
5. 正常値で「入力内容を確認」を押し、確認画面の値を見直す。「入力を修正」で値を保持して戻れることも確認する。
6. 成功を選んで確認画面から送信し、`送信中...`の表示、送信・修正ボタンの無効化、成功表示を確認する。
7. 「別の内容を入力」でフォームへ戻り、送信失敗を選んで再度送信する。
8. フォーム全体エラーが表示され、入力値を失わずに修正または再試行できることを確認する。

## 画面で確認できる状態

| 状態 | 確認方法 | 現在の表示 |
|---|---|---|
| input | 初期表示・入力中 | フォーム |
| validation error | 不正値で確認 | 項目別メッセージ、最初のエラー項目へフォーカス |
| confirm | 正常値で確認 | 入力値、送信結果、送信・修正操作 |
| submitting | 確認画面から送信 | `送信中...`、送信・修正ボタン無効 |
| success | 成功を選んで待機完了 | 完了案内、顧客名・メール |
| form error | 送信失敗を選んで待機完了 | フォーム全体エラー、入力値保持 |

このテーマは要件にある「API送信風処理」を扱うため、実API・DBへの送信と永続化は行わない。実通信を行うフォームでは、同じ画面状態に加えてHTTP状態コード、通信例外、サーバー側の入力検証、二重登録対策を扱う。

## 観察ポイント

- 検証に失敗した場合は確認・送信へ進まず、入力値はそのまま残る
- メール検証は学習用の単純な正規表現であり、完全なメール仕様検証ではない
- 備考は任意だが、入力した場合は200文字以内に制限される
- 確認画面から入力へ戻っても値を失わない
- ボタンを無効化することで、送信待機中の送信・修正を繰り返しにくくしている
- 送信失敗後も値を保持するため、原因を確認して再試行できる

## 自分の言葉で説明する

- field error と form error は何が違うか
- 送信中にボタンを無効化しても、サーバー側の二重登録対策が別に必要なのはなぜか
- 入力値を失わずにエラーを表示することが重要なのはなぜか
- API送信風処理と、実APIへ送信する業務フォームの違いを説明できるか

## うまく動かないとき

- 確認画面へ進めない場合は、各入力欄の下に出ているエラーを先に確認する。
- 備考のエラーが消えない場合は、200文字以内になっているか確認する。
- 成功表示がすぐに出ないのは、送信中の状態を確認するため1秒待つ実装だからである。
- 送信失敗後は入力値が残るため、内容を修正するか同じ内容で再試行する。
