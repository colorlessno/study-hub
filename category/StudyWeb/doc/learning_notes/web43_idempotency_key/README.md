# web43 二重登録を防ぐ識別キー

注文登録APIへ識別キーを付け、同じ要求が再送されても登録結果を増やさない仕組みを確認するテーマです。

## このテーマでできるようになること

- 識別キーがない要求を拒否できる
- 同じキーと同じ内容の再送で、初回結果を再利用できる
- 同じキーで異なる内容を送った場合に競合として拒否できる
- 別のキーを使った場合は別の登録として扱える
- メモリ保存の識別キーがサーバー再起動で消えることを確認できる

## 最初に取り組むこと

1. StudyHubでAPIを起動する。
2. 「キーなしで登録」を実行し、400と`idempotency_key_required`を確認する。
3. 「同じキーで初回登録」を実行し、201、`replay: false`、`count: 1`を確認する。
4. 「同じキーと内容で再送」を実行し、200、`replay: true`、同じ結果ID、`count: 1`を確認する。
5. 「同じキーで異なる内容を送信」を実行し、409と`idempotency_key_payload_conflict`を確認する。
6. 「別のキーで登録」を実行し、新しい結果IDと`count: 2`を確認する。
7. APIを停止して再起動し、もう一度「同じキーで初回登録」を実行する。結果が再び初回登録になることを確認する。

## 識別キーごとの動作

| 操作 | 状態コード | 結果 |
|---|---:|---|
| キーなし | 400 | 登録しない |
| 新しいキー | 201 | 新しい結果を作る |
| 同じキー・同じ内容 | 200 | 保存済みの結果を返す |
| 同じキー・異なる内容 | 409 | `idempotency_key_payload_conflict`として拒否する |
| 別のキー | 201 | 別の登録を作る |

この教材ではキーと結果をメモリに保存します。有効期限、同時要求への排他制御、処理中や失敗状態の保存は扱いません。不正なJSONの400応答は自動テストで確認します。

## 手動で起動する場合

```bat
cd /d category\StudyWeb\src\backend\src\studyweb\systems\web43_idempotency_key
rtk npm.cmd run build
rtk npm.cmd test
rtk npm.cmd start
```

APIは`http://127.0.0.1:3043/orders`で待ち受けます。終了するときは`Ctrl+C`を押します。

## うまく動かないとき

- 初回登録が再送扱いになる場合は、APIを停止して再起動する。
- 409にならない場合は、同じ識別キーで異なる内容を送っているか確認する。
- 登録件数が想定と違う場合は、実行ログで操作順を確認する。
