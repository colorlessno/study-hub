# web30 エラー記録の残し方

発生したエラーを貼るだけで終わらせず、再現条件、予想、確認した事実、原因、対応結果、次回の確認箇所まで記録するテーマです。

## このテーマでできるようになること

- エラー記録ひな形と2件の記入例の役割を説明できる
- 環境、エラー原文、再現手順を記録できる
- 調査中の予想、確認した事実、確定した原因を分けて記録できる
- 対応内容、対応結果、次回の確認箇所を記録できる
- パスワード、トークン、個人情報を記録から除外できる

## 最初に取り組むこと

1. StudyHubで「エラー記録ひな形」と2件の記入例を開き、各見出しの役割を確認する。
2. 保存済みの事例または実際に遭遇したエラーを1件選ぶ。
3. ひな形をエディターで別ファイルへコピーし、環境、エラー原文、再現手順を記録する。
4. 調査中の予想と確認した事実を分け、原因だと判断した根拠を記録する。
5. 対応内容、対応結果、次回の確認箇所を記録し、秘密情報が含まれていないことを確認する。

StudyHubはひな形と記入例を読み取り専用で表示します。記録の作成と保存は、ひな形を別ファイルへコピーし、そのファイルをエディターで開いて行います。

## 記録の流れ

```text
現象を保存
  ↓
最小の再現手順を作る
  ↓
予想を立てる
  ↓
コンソール / 通信 / ログ / 差分で確認
  ↓
原因と対応内容を分けて書く
  ↓
再発時の最初の確認箇所を残す
```

## 書き分ける内容

| 項目 | 書く内容 |
|---|---|
| 発生した現象 | 実際の動作と期待していた動作の違い |
| エラー原文 | 改変していない主要メッセージとステータス |
| 再現手順 | 別の人が同じ現象を出せる操作 |
| 調査中の予想 | 調査中に考えた原因候補 |
| 確認した事実 | 画面、通信、ログ、差分から確認した内容 |
| 原因 | 証拠から確定した理由 |
| 対応内容 | 実際に行った変更や操作 |
| 対応結果 | 対応後に確認した結果 |
| 次回の確認箇所 | 同じ症状で最初に見る場所 |

## 記録を作成する

1. 2件の記入例から、記録する項目と情報量を確認する。
2. エラー記録ひな形を別ファイルへコピーする。
3. 保存済みのエラー情報を使い、原因を先に決めずに予想と確認した事実を記録する。
4. 原因、対応内容、対応結果を記録し、同じ現象が起きたときに最初に見る場所を残す。

## 自分の言葉で説明する

- 現象、予想、確認した事実、原因、対応内容の違いを説明する。
- エラー記録に環境と関連ファイルが必要な理由を説明する。
- 同じ現象が起きたときに、記録から最初の確認箇所を判断する。

## 記録時の注意

- APIキー、パスワード、Cookie、個人情報、実在の接続文字列を貼らない。
- 長いログを全部貼らず、原因調査に必要な箇所と取得方法を残す。
- 解決していない場合は「未解決」と明記し、推測を事実として書かない。
- 画面キャプチャだけに依存せず、検索可能なテキストも残す。
