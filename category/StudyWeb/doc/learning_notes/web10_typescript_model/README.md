# web10 TypeScriptのデータ型

ユーザー、タスク、記事のデータ構造をTypeScriptで定義し、React画面へ安全に渡す流れを確認するテーマです。

## このテーマでできるようになること

- ユーザー・タスク・記事の3種類のデータが画面に表示されることを確認できる
- `models`フォルダに、各データの型定義が分けて保存されていることを確認できる
- サンプルデータが型定義に沿って作られていることを確認できる
- 親から子へ渡す値にも型が指定され、`any`を使用していないことを確認できる

## 最初に取り組むこと

次の順番で確認する。

1. 画面を起動し、ユーザー、タスク、記事の3つの領域にサンプルデータが表示されることを確認する。
2. `data/sampleData.ts`で各配列に指定された型を確認する。
3. `models`フォルダの3ファイルを開き、画面に表示される項目と型定義を対応させる。
4. `App.tsx`で、親部品から子部品へ渡す値に`User`、`Task[]`、`Article[]`が指定されていることを確認する。
5. 任意項目、複数候補から選ぶ型、真偽値が画面表示へどう反映されるか確認する。

## 起動方法

StudyHubのテーマ画面で「起動」を押します。手動で確認する場合は、実装ディレクトリで`npm ci`を実行してから`npm run dev`を実行します。

## 観察ポイント

- `bio?`と`assigneeId?`は、値がなくてもよい任意項目になっているか
- `UserRole`と`TaskStatus`は、使用できる文字列を限定しているか
- `published`の真偽値が「公開済み」「下書き」の表示へ変換されるか
- 親から子へ渡す値に`User`、`Task[]`、`Article[]`の型が付いているか
- `any`を使わずに画面を組み立てているか

## 自分の言葉で説明する

- 画面で扱うデータの形を型として先に決める利点
- 任意項目と必須項目の違い
- 使用できる文字列を限定すると入力間違いを見つけやすくなる理由

## うまく動かないとき

- 画面が起動しない場合は、最初のTypeScriptエラーと対象ファイルを確認します。
- データが表示されない場合は、`sampleData.ts`の項目名と型定義を照合します。
- 子部品で型エラーが出る場合は、受け取る値の型と親から渡す値を比較します。
