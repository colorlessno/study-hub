# web50 N+1問題の再現

SQLiteへ保存した親子データをPrismaで取得し、親ごとに子データを取得するN+1方式と、relationを含めて取得する方式の実SQLを比較するテーマです。

## このテーマでできるようになること

- SQLiteへ親子データを用意し、Prismaから実際に発行されたSQLを確認できる
- 取得方法が違っても、返される利用者とタスクが同じことを確認できる
- 親の件数を増やすと、N+1方式だけ問い合わせ回数が増えることを確認できる
- Prismaのquery logを読み、1回とN回が何を取得しているか確認できる

## 最初に取り組むこと

1. 「起動」を押す。
2. 「N+1の処理を実行する」を選び、親データの件数へ`3`を入力して実行する。
3. 問い合わせ記録に親一覧1回と親ごとの子取得3回があることを確認する。
4. 「改善後の処理を実行する」を同じ件数で実行し、SQL回数が親件数に比例しないことを確認する。
5. 両方の親データの件数を`10`へ変え、N+1方式だけSQL回数が増えることを確認する。
6. 「N+1問題の仕組み」と「取得方法を比較する処理」を開き、画面の問い合わせ記録とソースを照合する。

## 問い合わせ回数の違い

| 親データの件数 | N+1方式 | 改善後 |
|---:|---:|---:|
| 3 | 4回 | 2回 |
| 10 | 11回 | 2回 |
| N | 1+N回 | 2回 |

`queryLog`はPrismaのquery eventから取得した実SQL、parameter、実行時間です。SQLiteへの学習データ準備処理は比較対象から外し、2つの取得処理だけを記録します。

## この教材で扱わないこと

- 大規模負荷試験
- DB索引と実行計画の詳細
- 本番データ量での性能保証

## うまく動かないとき

- 親データの件数は1から20までの整数を入力する。
- 2つの方式を比較するときは、同じ件数を指定する。
- 結果の`queries`だけでなく、`queryLog`、`durationMs`、`result`も確認する。
