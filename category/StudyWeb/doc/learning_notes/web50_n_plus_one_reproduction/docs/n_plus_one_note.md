# N+1問題の仕組み

```text
1回: 親データの一覧を取得
N回: 親データごとに子データを取得
```

親が3件なら合計4回、親が10件なら合計11回です。子が0件の親でも、子がないことを確認する問い合わせが発生します。

## 改善方法の例

| 方法 | 考え方 | 確認すること |
|---|---|---|
| 先読み | 関連データも先に取得する | 不要な関連まで取得していないか |
| 結合 | 1つのSQLで親子を結合する | 親の行が重複しないか |
| 一括取得 | 親IDをまとめて子データを取得する | ID数とSQLの大きさ |
| DataLoader | 同じ要求内の取得をまとめる | 保存範囲とデータの整合性 |

問い合わせ回数を減らせば必ず速くなるとは限りません。実際のSQL、取得行数、通信量、実行計画、処理時間を測って判断します。
