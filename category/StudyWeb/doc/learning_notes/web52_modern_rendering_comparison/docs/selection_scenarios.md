# 利用場面の例

表示方式に唯一の正解はありません。ここでは条件を固定し、採用案と不採用案の両方を説明します。

## 公開ドキュメント

| 条件 | 内容 |
|---|---|
| 認証 | 不要 |
| 更新頻度 | 低い |
| 検索結果・共有 | 重要 |
| 画面操作 | 検索と小さな操作 |

SSGを基本にすると、作成済みのHTMLを安定して配信できます。更新頻度が高くなった場合はSSRや再生成も比較します。検索等の一部だけにIslandsを使う構成も考えられます。

## 認証済みダッシュボード

| 条件 | 内容 |
|---|---|
| 認証 | 必須 |
| 更新頻度 | 高い |
| 検索結果・共有 | 不要 |
| 画面操作 | 絞り込み・更新・リアルタイム表示 |

SSRやServer Componentsで最初のデータ取得をサーバー側へ寄せる案と、SPAで操作をブラウザ中心にする案を比較します。非公開データを共有キャッシュへ置かないことが重要です。

## オフライン対応の現場用ツール

| 条件 | 内容 |
|---|---|
| 認証 | 必要 |
| 通信 | 不安定 |
| データ更新 | 後から同期 |
| 端末 | インストールできると便利 |

基本となる表示方式にPWAを組み合わせます。未送信データの保持、再送時の重複防止、競合、古いデータの扱いを検討します。

## 社内向けの単純な登録・一覧画面

| 条件 | 内容 |
|---|---|
| 認証 | 社内利用 |
| 更新頻度 | 中程度 |
| 検索結果・共有 | 不要 |
| 画面操作 | 登録と一覧表示 |

MPAやSSRなら処理の流れを単純にしやすくなります。画面内に複雑な状態を保持する明確な理由がある場合にSPAを比較します。
