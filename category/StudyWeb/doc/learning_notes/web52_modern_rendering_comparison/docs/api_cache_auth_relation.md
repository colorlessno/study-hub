# API・キャッシュ・認証の関係

## 表示方式を選ぶ前に確認すること

| 観点 | 確認する内容 |
|---|---|
| API | ブラウザが直接呼ぶか、サーバーが画面用データを組み立てるか |
| キャッシュ | 公開情報か、利用者ごとの非公開情報か、古い内容を許容できるか |
| 認証 | 画面の内容を作る前に利用者を特定する必要があるか |
| ブラウザ側処理 | HTML到着後にどの部分を操作可能にするか |
| 更新処理 | 閲覧中心か、登録や更新を頻繁に行うか |

## 注意する失敗

- 非公開データを共有キャッシュから別の利用者へ返す
- 認証結果が決まる前に、空の画面や誤解を招く画面を表示する
- サーバーから複数のAPIを順番に呼び、表示開始を遅らせる
- サーバーで作ったHTMLとブラウザの最初の状態が一致しない
- オフライン用キャッシュから古い認証状態を返す

表示方式の名前から選び始めず、データの所有者とキャッシュする範囲を先に決めます。
