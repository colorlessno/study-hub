# web52 Web表示方式の比較

公開ページ、認証が必要な管理画面、オフライン対応の現場用ツール、社内向けの登録・一覧画面を題材に、Web画面の表示方式を選びます。画面上で条件を比較し、選んだ方式と理由を判断メモとしてブラウザ内に保存します。

## このテーマでできるようになること

- MPA、SPA、SSR、SSGの違いを説明できる
- Server Components、Islands、PWAは、基本となる表示方式と組み合わせる仕組みであることを説明できる
- 認証、更新頻度、検索結果への掲載、画面操作、オフライン利用から表示方式を選べる
- 採用する方式だけでなく、採用しなかった方式と理由も記録できる
- サーバーとブラウザの役割、キャッシュする範囲、運用上の注意点を整理できる

## 最初に取り組むこと

1. 教材画面で「公開ドキュメント」を選び、表示された条件を確認する
2. 基本となる方式を1つ選び、選定理由を入力する
3. 必要に応じて組み合わせる仕組みを選び、役割分担とキャッシュ範囲を入力する
4. 採用しなかった案と運用上の注意点を入力し、「この判断メモを保存」を押す
5. 別の利用場面へ切り替えて同じ操作を行い、保存した判断メモを比較する

## 画面の操作

| 操作 | 確認する内容 |
|---|---|
| 利用場面を選ぶ | 認証、更新頻度、画面操作等の条件が切り替わる |
| 基本となる方式を選ぶ | MPA、SPA、SSR、SSGから判断の土台を1つ選ぶ |
| 組み合わせる仕組みを選ぶ | Server Components、Islands、PWAを必要に応じて追加する |
| 判断メモを入力する | 選定理由、役割分担、キャッシュ範囲、不採用案、運用上の注意点を整理する |
| この判断メモを保存 | 現在の利用場面の入力内容をブラウザ内に保存する |
| このメモをクリア | 現在の利用場面について保存した内容だけを削除する |

入力内容はブラウザの `localStorage` に保存します。サーバーへの送信やファイルへの書き込みは行いません。

## 比較するときの考え方

MPA、SPA、SSR、SSGは完全に同じ軸の選択肢ではありません。MPAとSPAは主に画面遷移とブラウザ側の状態管理を、SSRとSSGは主にHTMLを作る時点を表します。実際のシステムでは、画面や経路ごとに組み合わせることがあります。

Server ComponentsとIslandsは、画面のどの部分をサーバーとブラウザで処理するかを決める考え方です。PWAは、オフライン利用やインストール等の機能を追加する考え方です。

## ソースと構成を確認する

| ファイル | 役割 |
|---|---|
| `index.html` | 利用場面、方式選択、判断メモの入力欄を定義する |
| `src/main.js` | 画面の切り替え、入力、保存、削除を制御する |
| `src/decision-memo.js` | 利用場面と方式の定義、入力検証、表示文の作成を担当する |
| `src/style.css` | 比較しやすい配置と画面幅に応じた表示を定義する |

StudyHubの教材欄から各ファイルを開き、画面上の操作と処理の対応を確認します。

## 自分の言葉で説明する

- 公開ドキュメントと認証済みダッシュボードで、キャッシュする範囲が異なる理由
- SPAを選ぶだけでは、最初のHTMLをいつ作るかが決まらない理由
- ブラウザで動かすJavaScriptを減らす利点と制約
- 表示方式の選定理由に、実装だけでなく運用や障害調査も含める理由

## うまく動かないとき

- 保存できない場合は、基本となる方式と選定理由が入力されているか確認する
- 利用場面を切り替えて内容が消えた場合は、その利用場面で一度保存したか確認する
- 保存件数が変わらない場合は、ブラウザで `localStorage` が利用可能か確認する
