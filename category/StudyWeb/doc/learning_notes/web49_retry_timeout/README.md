# web49 再試行と時間切れ

正常応答、遅い応答、一時エラー、入力を直すまで回復しないエラーを使い分け、待ち時間と再試行の判断を確認するテーマです。

## このテーマでできるようになること

- 正常応答が1回で成功することを確認できる
- 遅い応答を1秒で打ち切ることを確認できる
- 一時エラーだけを上限3回まで再試行し、成功までの履歴を確認できる
- 入力誤りを表す400は再試行しないことを確認できる

## 最初に取り組むこと

1. 「起動」を押す。
2. 「正常応答」を実行し、1回目で状態番号200が返ることを確認する。
3. 「遅い応答を1秒で打ち切る」を実行し、`request_timeout`と1000ミリ秒の上限を確認する。
4. 「一時エラーを再試行する」を実行し、503、503、200の3回分が`attempts`へ残ることを確認する。
5. 「恒久エラーを確認する」を実行し、400と`retryable: false`を確認する。
6. 「再試行の判断基準」と「応答を切り替える処理」を開き、再試行する条件としない条件を照合する。

## StudyHubが行う再試行

「一時エラーを再試行する」では、StudyHubがAPIの呼び出し側になります。

- 最大試行回数: 3回
- 試行間隔: 100ミリ秒
- 再試行する状態番号: 503だけ
- 1回目と2回目: 503
- 3回目: 200

回数、1回ごとの制限時間、待ち時間をすべて無制限にしないことが重要です。副作用のある操作を再試行する場合は、同じ処理を重複実行しない仕組みも必要です。

## この教材で扱わないこと

- 通信経路の切断や名前解決エラー
- 複数利用者が同時に再試行する状況
- 待ち時間のばらつき、サーバー負荷、冪等性キー

## 手動で確認する場合

```bat
cd /d C:\work\work20260617\category\StudyWeb\src\backend\src\studyweb\systems\web49_retry_timeout
rtk npm.cmd test
rtk npm.cmd start
```

別のコマンドプロンプトから次を実行します。

```bat
curl.exe -i "http://127.0.0.1:3049/?mode=success"
curl.exe --max-time 1 -i "http://127.0.0.1:3049/?mode=slow"
curl.exe -i "http://127.0.0.1:3049/?mode=temporary&key=manual"
curl.exe -i "http://127.0.0.1:3049/?mode=permanent"
```

## うまく動かないとき

- 一時エラーは、同じ`key`の1回目と2回目に503、3回目に200を返す。
- 遅い応答は2秒後に返るため、1秒の制限では応答を受け取れない。
- 試行履歴は、実行結果の`attempts`を上から順に確認する。
