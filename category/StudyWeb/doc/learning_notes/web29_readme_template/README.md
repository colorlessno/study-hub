# web29 学習用READMEの書き方

学習用READMEに、テーマの目的、実行方法、確認する内容、学んだことを整理するテーマです。

## このテーマでできるようになること

- READMEのひな形と記入例の違いを確認できる
- 既存テーマ1件のREADMEに、目的、前提、実行方法、確認方法、終了方法を記載できる
- READMEの手順だけで教材を起動し、確認後に終了できることを確かめられる
- 秘密情報や未確認の結果をREADMEへ書かない理由を説明できる

## 最初に取り組むこと

1. StudyHubの「READMEひな形」を開き、用意されている見出しを確認する。
2. 「README記入例」を開き、各見出しへ具体的に何が書かれているか確認する。
3. 最近触ったテーマを1件選び、ひな形を参考にREADMEを書く。
4. 書いた手順だけを使って教材を起動し、確認後に終了する。不足していた説明はREADMEへ追記する。

StudyHubではひな形と記入例を読み取り専用で表示する。READMEの作成と保存は、対象テーマのファイルをエディターで開いて行う。

## READMEの推奨構成

| セクション | 読者が判断できること |
|---|---|
| 概要 | 何を学ぶテーマか |
| このテーマでできるようになること | 何を確認し、何を説明するか |
| 前提 | 必要な環境と準備は何か |
| 使用技術 | どの技術を扱うか |
| 実行方法 | どのフォルダーで何を実行するか |
| 確認すること | どの操作と結果を確かめるか |
| 学んだこと | 実際の体験から何を理解したか |
| うまく動かないとき | どこから原因を確認するか |
| 注意 | 秘密情報やデータの扱いに問題がないか |

## 作成手順

1. テーマ名と学習目的を1〜2文で書く。
2. 必要な環境、ツール、準備済みの状態を書く。
3. 作業フォルダーを明記し、cmd.exeで実行できるコマンドを書く。
4. 画面、API、DB、Network等で確認する操作と結果を書く。
5. 教材の終了方法と、必要な後片付けを書く。
6. 実際に手順を実行し、確認した事実と未確認の内容を区別する。

## 記述を確認する

- 作業フォルダー、コマンド、URL、終了方法が一つの手順としてつながっているか確認する。
- コマンドを実行した結果と、実行前の想定を区別する。
- APIキー、パスワード、個人情報、実在の接続文字列を書かない。
- `.env.example`にはダミー値だけを置く。
- 環境に依存する手順には、OS、シェル、前提ツールを記載する。

## 自分の言葉で説明する

- READMEだけで学習内容と実行手順を把握できる必要があるのはなぜですか。
- 起動方法と確認方法を分ける理由は何ですか。
- ポートフォリオ向け説明と学習者向け説明の共通点・相違点は何ですか。
