# web31 IssueとPRによる作業説明

作業前にIssueで目的と完了条件を定義し、作業後にPRで変更理由、影響範囲、確認結果、未確認事項を説明するテーマです。

## このテーマでできるようになること

- Issueひな形と記入例で、背景、目的、対象範囲、完了条件、確認方法の役割を説明できる
- PRひな形と記入例で、関連Issue、変更内容、変更理由、影響範囲、確認結果の役割を説明できる
- 今回の対象外、未確認事項、今後の対応を分けて記載できる
- 第三者が変更理由と再確認方法を理解できる文章を作成できる
- 秘密情報や個人情報をIssueとPRから除外できる

## 最初に取り組むこと

1. 「Issueひな形」と「Issue記入例」を開き、背景、目的、対象範囲、対象外、完了条件、確認方法を対応させる。
2. 「PRひな形」と「PR記入例」を開き、Issueの完了条件とPRの確認結果が対応している箇所を確認する。
3. ひな形を別ファイルへコピーし、小さな変更作業を題材にIssueとPRを記入する。
4. 実際のGit操作を行う場合は「Gitea演習案内」を開き、IT基礎のbase08へ移動する。
5. 未確認事項を成功扱いにせず、秘密情報や個人情報が含まれていないことを確認する。

StudyHubはひな形、記入例、Gitea演習案内を読み取り専用で表示します。IssueとPRの作成・保存は、ひな形を別ファイルへコピーしてエディターで行います。

## IssueとPRの役割

| 文書 | 時点 | 主な問い |
|---|---|---|
| Issue | 作業前 | なぜ必要か、何を達成するか、何をしないか |
| PR | 作業後 | 何を変えたか、なぜその変更か、どう確認したか、何が未確認か |

## 作業サイクル

```text
Issueで背景・目的・完了条件を定義
  ↓
実装・文書変更
  ↓
完了条件に沿って検証
  ↓
PRへ変更・理由・影響・結果を記録
  ↓
未対応事項を次のIssue候補へ残す
```

## IssueとPRを作成する

1. 保存済みの変更例または次に行う小さな作業を1件選ぶ。
2. Issueひな形へ背景、目的、対象範囲、対象外、完了条件、確認方法を書く。
3. PRひな形へ関連Issue、変更内容、変更理由、影響範囲、実際の確認結果を書く。
4. 実行していない確認は未確認事項へ残し、追加要望は今後の対応へ分ける。
5. 記入例と見比べ、第三者が同じ確認を行える情報があることを確認する。

## レビュー観点

- 目的と変更内容が対応しているか
- 完了条件が検証可能な表現か
- 影響範囲に漏れがないか
- 確認結果に操作またはコマンド、対象、期待結果、実際の結果があるか
- 未確認事項を成功扱いにしていないか
- 対象外の変更が混ざっていないか

## 自分の言葉で説明する

- Issueの完了条件とPRの確認結果を対応させる方法を説明する。
- 変更内容と変更理由の違いを説明する。
- レビューする人が再確認できるPRに必要な情報を説明する。

## 記入時の注意

- 背景、目的、変更内容、変更理由を混ぜない。
- 実際に確認した内容だけをチェック済みにする。
- 秘密情報や個人情報をIssue・PRへ貼らない。
- 大きな作業は、独立して検証できる単位へ分ける。
