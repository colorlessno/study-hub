# web38 URLと登録・参照・更新・削除画面の対応

React RouterでURLの`#`以降（ハッシュ）と画面状態を対応させ、登録・参照・更新・削除の各画面を操作する。

## このテーマでできるようになること

- React Routerで一覧・詳細・新規作成・編集・削除確認・対象なしの6画面を開ける
- 各画面を開いたとき、画面内の「現在のURL」が切り替わることを確認できる
- 新しい項目を登録し、一覧と詳細画面に反映できる
- 項目名を更新し、項目を削除できる
- 教材内の戻る・進むボタンで、URLと表示画面が一緒に切り替わることを確認できる

## 最初に取り組むこと

1. StudyHubの「教材を表示」で一覧画面を開く。
2. 「新規作成」で項目を登録し、一覧と詳細画面に反映された内容を確認する。
3. 登録した項目を編集して保存し、名前が変わることを確認する。
4. 編集した項目を削除し、一覧から消えることを確認する。
5. 「対象なし例」を押し、`#/items/999`と対象なし画面を確認する。
6. 教材内の戻る・進むボタンを使い、URLに対応して画面が切り替わることを確認する。

## 現在のURLと画面

| URLの#以降 | 画面 | 実装状態 |
|---|---|---|
| `#/items` | 一覧 | 項目と詳細・編集・削除のリンクを表示 |
| `#/items/new` | 新規作成 | 名前を入力してstateへ追加 |
| `#/items/:id` | 詳細 | IDと名前を表示 |
| `#/items/:id/edit` | 編集 | 名前を変更してstateへ反映 |
| `#/items/:id/delete` | 削除確認 | 対象を確認してstateから削除 |
| その他・存在しないID | 対象なし | 見出しと一覧へのリンクを表示 |

`HashRouter`、`Routes`、`Route`、`Link`、`useParams`、`useNavigate`を使用している。要件でDB連携は対象外としているため、作成・更新・削除の結果はReactのstateへ保持し、ページを再読み込みすると初期データへ戻る。

## 観察ポイント

- `Route`がURLに対応するcomponentを選ぶ
- `Link`と`useNavigate`でURLと画面を同時に切り替える
- URL に ID があるため、詳細・編集画面を直接指定できる
- 数字形式でも `items` に存在しない ID は not found になる
- formの保存後は一覧画面へ戻り、変更後のstateを表示する
- stateで保持するため、ページの再読み込み後には初期状態へ戻る

## 自分の言葉で説明する

- URL と画面状態を対応させる利点は何か
- URL内のIDを数値へ変換してから検索する理由は何か
- 不正なURLと、形式は正しいが存在しないIDをどう扱うか
- DB保存を行う業務システムと、stateでCRUD導線を学ぶ本テーマの違いは何か

## うまく動かないとき

- 外側のStudyHubのURLは変わらないため、教材内に表示される「現在のURL」を確認する。
- 戻る・進むで変化しない場合は、先に詳細や編集など複数の画面を開いて履歴を作る。
- 対象なしを確認する場合は、`#/items/999`のように存在しない番号を指定する。
- 保存できない場合は、名前が空欄になっていないか確認する。
