# 状態確認の流れ

```text
利用者 → ジョブを受け付ける → 202とジョブID
利用者 → ジョブIDで状態確認 → queuedまたはrunning
利用者 → 少し待って状態確認 → succeededと処理結果
利用者 → 失敗するジョブを受付 → queued、running、failedと失敗理由
```

## 状態確認を止める条件

- 成功・失敗・中止など、処理が終わった状態になった
- 最大確認回数に達した
- 全体の制限時間に達した
- 利用者が画面を離れた、または中止した
- 404など、確認を続けても回復しない応答が返った

短い間隔で無制限に確認するとAPIの負荷が増えます。固定間隔、待ち時間を少しずつ延ばす方法、サーバーから次の確認時刻を返す方法などを、処理時間と利用者数に合わせて選びます。

現在のStudyHub画面では自動pollingを行いません。一回の状態確認の応答を読んでから、必要な場合だけ次の確認を実行します。
