# web48 長時間処理の受付と状態確認API

時間のかかる処理を受け付けるAPIと、処理の状態を後から確認するAPIを分けて動かすテーマです。

## このテーマでできるようになること

- 処理の受付時にHTTP状態番号202とジョブIDが返ることを確認できる
- 同じジョブIDを使い、受付済み・実行中・成功の状態変化を確認できる
- 成功したジョブの応答に処理結果が加わることを確認できる
- 失敗するジョブで、受付済み・実行中・失敗の状態変化と失敗理由を確認できる
- 存在しないジョブIDでは404が返ることを確認できる
- サーバーを再起動すると、メモリに保存したジョブが消えることを確認できる

## 最初に取り組むこと

1. 「起動」を押す。
2. 「ジョブを受け付ける」を実行し、状態番号202、ジョブID、`queued`を確認する。
3. 表示されたジョブIDを「ジョブの状態を確認する」へ入力し、一回の応答を確認してから時間を空けて次の状態確認を実行する。
4. `queued`、`running`、`succeeded`の順で変化し、最後に`result`が加わることを確認する。
5. 「失敗するジョブを受け付ける」を実行し、そのジョブIDを使って`queued`、`running`、`failed`と`error`を確認する。
6. 「存在しないジョブを確認する」を実行し、404を確認する。
7. 「ジョブの状態」と「ジョブを管理する処理」を開き、画面で確認した状態とソースを照合する。

## 状態の変化

```text
POST /jobs
  ↓ 202 Accepted
queued
  ↓ 約300ミリ秒
running
  ↓ 約900ミリ秒
succeeded + result

POST /jobs?outcome=failed
  ↓ 202 Accepted
queued
  ↓ 約300ミリ秒
running
  ↓ 約900ミリ秒
failed + error
```

状態を確認する側は、成功・失敗・中止などの終了状態、確認回数、待ち時間に上限を設けます。この教材は短時間で変化を確認できるように、サーバー内のタイマーで処理を再現しています。

StudyHubの実行欄が進捗確認画面です。自動pollingは行わず、利用者が一回ずつ要求して`queued`、`running`、終端状態を比較します。サーバー側もrunningへの遷移が完了してから、成功または失敗への次のタイマーを設定します。

## この教材で扱わないこと

- 実際の長時間処理、ワーカー、メッセージキュー
- ジョブの永続化、進捗率、中止、期限切れ
- 利用者ごとの参照権限

## 手動で確認する場合

```bat
cd /d C:\work\work20260617\category\StudyWeb\src\backend\src\studyweb\systems\web48_job_status_api
rtk npm.cmd test
rtk npm.cmd start
```

起動後は`http://127.0.0.1:3048`へ要求を送ります。終了するときは`Ctrl+C`を押します。

## うまく動かないとき

- 状態確認には、受付結果に表示されたジョブIDを入力する。
- 状態がすぐ成功になる場合は、新しいジョブを受け付けて直後に確認する。
- 操作順が分からなくなった場合は、停止してから起動し直す。
