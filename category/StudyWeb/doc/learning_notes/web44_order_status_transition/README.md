# web44 注文状態の遷移

注文の現在状態と変更先を照合し、許可された変更だけを実行する画面で状態遷移を確認するテーマです。

## このテーマでできるようになること

- 許可されている状態変更と許可されていない状態変更を実行できる
- 完了と取消が、それ以上変更できない終端状態であることを確認できる
- 拒否された変更では、現在状態と変更履歴が変わらないことを確認できる
- 状態遷移表と実ソースの`allowed`を照合できる

## 最初に取り組むこと

1. 初期状態が「下書き」、変更履歴も「下書き」だけであることを確認する。
2. 変更先に「発送済み」を選び、許可されていない変更として拒否されることを確認する。
3. 「確認済み」から「発送済み」「完了」の順に変更する。
4. 完了後に別の状態へ変更しようとし、現在状態と履歴が変わらないことを確認する。
5. 「初期状態に戻す」を押し、「下書き」から「取消」へ変更する。
6. 「状態遷移表」と「状態変更を判定する処理」を開き、画面の結果と照合する。

## 状態遷移

```text
下書き ──> 確認済み ──> 発送済み ──> 完了
  └────────> 取消
       確認済み ────────> 取消
```

完了と取消は終端状態です。許可されていない変更では、エラーメッセージだけを更新し、注文状態と変更履歴は更新しません。

## この教材で扱わないこと

- APIやDBへの保存
- 変更日時、操作者、変更理由を含む監査履歴
- 権限、在庫、決済などを含む実務上の判定

## 手動で確認する場合

`category\StudyWeb\src\frontend\static\studyweb\systems\web44_order_status_transition\app\index.html`をブラウザで開きます。構文確認は次のコマンドです。

```bat
rtk node --check category\StudyWeb\src\frontend\static\studyweb\systems\web44_order_status_transition\app\src\main.js
```

## うまく動かないとき

- 状態を変更できない場合は、「状態遷移表」で現在状態から選べる変更先を確認する。
- 別の経路を試す場合は、「初期状態に戻す」を押してから操作する。
- 表示と処理の関係は、「状態変更を判定する処理」で確認する。
