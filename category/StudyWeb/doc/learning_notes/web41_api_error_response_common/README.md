# web41 APIエラー形式の共通化

正常応答と3種類のエラー応答を実際に呼び出し、HTTP状態コードとJSONの共通形式を比較するテーマです。

## このテーマでできるようになること

- 正常・入力エラー・業務エラー・内部エラーの状態コードを確認できる
- エラー応答の`code`・`message`・`details`・`requestId`を比較できる
- StudyHubの「フロント表示例」で、エラーの種類に応じて画面上の表示先を分ける処理を確認できる
- 内部エラーの応答に、スタックトレースやファイルパスを含めない理由を説明できる

## 最初に取り組むこと

1. StudyHubでAPIを起動する。
2. 「正常応答」「入力エラー」「業務エラー」「システムエラー」を順番に実行する。
3. 200・400・409・500の違いと、3種類のエラーに共通するJSON項目を確認する。
4. 3種類のエラーで「フロント表示例」が、入力項目の近く、画面上部、共通通知欄へ切り替わることを確認する。
5. 「エラー種別と表示先」を開き、実画面の判定と規則が一致することを確認する。
6. 「エラー応答を返す処理」を開き、内部情報を応答へ含めていないことを確認する。

## 応答の比較

| 操作 | 状態コード | 主な結果 |
|---|---:|---|
| 正常応答 | 200 | `{ "ok": true }` |
| 入力エラー | 400 | `VALIDATION_ERROR`と項目別の詳細 |
| 業務エラー | 409 | `ORDER_ALREADY_CLOSED` |
| システムエラー | 500 | `INTERNAL_ERROR` |

`code`は画面側の処理分岐、`message`は利用者への説明、`details`は入力項目などの補足、`requestId`はサーバーログとの照合に使います。

StudyHubは生の応答に加えて、`VALIDATION_ERROR`を入力項目の近く、業務エラーをフォームまたは画面の上部、`INTERNAL_ERROR`を共通通知欄へ割り当てたフロント表示例を示します。入力エラーの`details`にある項目名とメッセージも一覧表示します。

## 手動で起動する場合

リポジトリのルートから次を実行します。

```bat
cd /d category\StudyWeb\src\backend\src\studyweb\systems\web41_api_error_response_common
rtk npm.cmd run build
rtk npm.cmd start
```

別のコマンドプロンプトから確認します。

```bat
curl.exe -i http://127.0.0.1:3041/validation
curl.exe -i http://127.0.0.1:3041/business
curl.exe -i http://127.0.0.1:3041/system
```

終了するときは起動したコマンドプロンプトで`Ctrl+C`を押します。

## うまく動かないとき

- 接続できない場合は、APIが起動済みか確認する。
- 想定と異なる応答の場合は、選択した操作と状態コードを確認する。
- JSONの意味が分からない場合は、「エラー応答の共通形式」と実ソースを照合する。
