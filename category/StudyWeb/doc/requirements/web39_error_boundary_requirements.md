# web39 Error Boundary 要件定義

## 1. 目的

React画面で例外が起きたときに、画面全体が真っ白にならないよう Error Boundary を学ぶ。

## 2. 学習対象

- React Error Boundary
- render error
- fallback UI
- reset / retry
- error logging の考え方

## 3. 作成する成果物

- Error Boundaryサンプル
- 例外発生ボタン
- fallback UI
- 復旧導線
- エラー記録メモ

## 4. 機能要件

| ID | 要件 |
|---|---|
| FR-01 | 意図的に画面例外を発生できる |
| FR-02 | Error Boundaryでfallback UIを表示できる |
| FR-03 | 復旧または再読み込み導線を提供できる |
| FR-04 | 例外内容を開発者向けに確認できる |

## 5. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | 利用者向けに内部詳細を出しすぎない |
| NFR-02 | 開発者が原因調査できる情報は残す |
| NFR-03 | 既存画面の一部だけを保護できる構成にする |

## 6. 対象外

- 本格監視サービス連携
- サーバーサイド例外処理
- 非同期処理の全エラー捕捉

## 7. 受入条件

- 画面例外時にfallback UIが表示される
- 例外発生箇所と復旧導線を説明できる
- 内部情報を利用者へ出しすぎない方針を説明できる

## 8. 学習観点

- 画面例外は必ず起きる前提で扱う
- 利用者向け表示と開発者向けログを分ける
- Error Boundaryには捕捉できないエラーもある
