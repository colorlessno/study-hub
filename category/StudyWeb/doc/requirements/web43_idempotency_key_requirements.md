# web43 idempotency key 要件定義

## 1. 目的

登録ボタン連打や通信再送による二重登録を防ぐため、idempotency key の考え方を学ぶ。

## 2. 学習対象

- idempotency
- POST retry
- duplicate submission
- key storage
- conflict response

## 3. 作成する成果物

- idempotency key 対応API
- 二重送信再現手順
- 成功・重複レスポンス例
- 設計メモ

## 4. 機能要件

| ID | 要件 |
|---|---|
| FR-01 | POST時にidempotency keyを受け取れる |
| FR-02 | 同じkeyの再送時に二重登録を防げる |
| FR-03 | 初回成功結果を再返却または重複として扱える |
| FR-04 | keyなしの場合の扱いを定義できる |
| FR-05 | フロント側で送信中制御と併用できる |

## 5. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | 学習用にメモリまたは簡易DBで管理できる |
| NFR-02 | keyの保持期間を説明できる |
| NFR-03 | 完全な決済レベル実装は対象外にする |

## 6. 対象外

- 決済システム相当の厳密性
- 分散ロック
- 本格永続化

## 7. 受入条件

- 同じkeyで二重登録が起きないことを確認できる
- keyなし、key重複、初回登録の違いを説明できる
- フロント側二重送信防止との違いを説明できる

## 8. 学習観点

- ボタン無効化だけでは再送を防ぎきれない
- API側で二重実行耐性を持つ
- 冪等性は長時間処理や外部連携でも重要
