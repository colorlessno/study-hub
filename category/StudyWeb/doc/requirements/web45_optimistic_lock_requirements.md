# web45 楽観ロック 要件定義

## 1. 目的

同じデータを複数人が更新したときの競合を検出し、上書き事故を防ぐ楽観ロックを学ぶ。

## 2. 学習対象

- optimistic lock
- version column
- updated_at check
- conflict
- 409 response

## 3. 作成する成果物

- 楽観ロック付き更新サンプル
- 競合再現手順
- 409エラーレスポンス
- 再読込・再編集の導線

## 4. 機能要件

| ID | 要件 |
|---|---|
| FR-01 | データにversionを持たせられる |
| FR-02 | 更新時にversion一致を確認できる |
| FR-03 | version不一致時に409を返せる |
| FR-04 | 競合発生時に再読込を促せる |
| FR-05 | 競合再現手順を確認できる |

## 5. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | 学習用に再現しやすい構成にする |
| NFR-02 | 上書き事故を防ぐ目的を明示する |
| NFR-03 | 悲観ロックとの違いを簡単に説明できる |

## 6. 対象外

- DBロック詳細
- 分散トランザクション
- 高度な同時実行制御

## 7. 受入条件

- version一致時のみ更新できる
- 競合時に409を確認できる
- 再読込が必要な理由を説明できる

## 8. 学習観点

- 同時更新は業務アプリで普通に起きる
- 最後に保存した人が勝つ設計は危険
- conflict は利用者に分かる形で返す
