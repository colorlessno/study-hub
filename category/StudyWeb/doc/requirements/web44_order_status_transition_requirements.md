# web44 注文ステータス遷移 要件定義

## 1. 目的

業務ルールを状態遷移として表現し、不正な状態変更を防ぐ設計を学ぶ。

## 2. 学習対象

- status transition
- business rule
- allowed transition
- invalid transition
- audit fields

## 3. 作成する成果物

- 注文ステータス遷移サンプル
- 状態遷移表
- APIまたは関数による遷移制御
- 不正遷移テスト

## 4. 機能要件

| ID | 要件 |
|---|---|
| FR-01 | 注文ステータスを定義できる |
| FR-02 | 許可された遷移だけ実行できる |
| FR-03 | 不正遷移を業務エラーにできる |
| FR-04 | 遷移履歴を記録できる |
| FR-05 | 取消や完了など終端状態を扱える |

## 5. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | 状態遷移表として読める |
| NFR-02 | 業務エラーと入力エラーを区別する |
| NFR-03 | 後続の監査ログ学習へ接続できる |

## 6. 対象外

- 本格注文管理
- 在庫引当
- 決済連携

## 7. 受入条件

- 許可遷移と不正遷移を説明できる
- 不正遷移時のエラーを確認できる
- 状態遷移が業務ルールであることを説明できる

## 8. 学習観点

- CRUDだけでは業務ルールを表現しきれない
- 状態は自由入力にしない
- 変更履歴は後からの調査に必要
