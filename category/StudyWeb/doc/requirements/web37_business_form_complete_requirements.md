# web37 業務フォーム完全版 要件定義

## 1. 目的

業務アプリで必要な入力、検証、確認、送信中制御、エラー表示、完了表示を含むフォームを作る。

## 2. 学習対象

- controlled form
- validation
- submit loading
- field error
- form error
- 確認画面
- 二重送信防止

## 3. 作成する成果物

- 業務フォーム画面
- 入力検証
- 確認ステップ
- API送信風処理
- エラー表示パターン

## 4. 機能要件

| ID | 要件 |
|---|---|
| FR-01 | 必須、文字数、形式の入力検証ができる |
| FR-02 | 項目別エラーを表示できる |
| FR-03 | 確認ステップを表示できる |
| FR-04 | 送信中は二重送信を防止できる |
| FR-05 | 成功、失敗、通信中の状態を表示できる |
| FR-06 | エラー時に該当項目へ戻れる |

## 5. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | キーボード操作を妨げない |
| NFR-02 | label と input を対応づける |
| NFR-03 | 業務画面として過度な装飾を避ける |

## 6. 対象外

- 本格的なフォームライブラリ比較
- 認証認可
- DB永続化

## 7. 受入条件

- 入力ミスを安全に修正できる
- 送信中と完了状態が分かる
- 二重送信を防げる

## 8. 学習観点

- フォームは入力欄だけでは成立しない
- エラー表示はユーザーが直せる形にする
- 業務UIではミス防止が重要
