## 2. 画面項目

| 項目 | 種別 | 役割 |
|---|---|---|
| 顧客名 | input | 必須入力 |
| メール | input | 必須・形式確認 |
| 備考 | textarea | 任意・200文字以内 |
| 確認する送信結果 | select | 成功または送信失敗の再現を選択 |
| 入力内容を確認 | submit button | 検証後に確認画面を表示 |
| 項目別エラー | span | 各入力の修正内容を表示 |
| 入力内容の確認 | section | 入力値、確認用送信結果、送信・修正操作を表示 |
| フォーム全体エラー | paragraph | 送信失敗と再試行方法を表示 |
| 処理結果 | pre | 送信中・成功・送信失敗を表示 |

## 3. Validationルール

| 項目 | 現在の判定 |
|---|---|
| 顧客名 | `trim()` 後が空ならエラー |
| メール | `^[^@]+@[^@]+$` に一致しなければエラー |
| 備考 | 201文字以上ならエラー |

メール判定は学習用の最小実装であり、メールアドレス仕様を完全に検証するものではない。

## 4. 処理手順

1. submit event の既定動作を停止する。
2. 前回の項目別エラーを消去する。
3. `validate()` で入力値を検証する。
4. エラーがあれば項目別メッセージを表示し、最初のエラー項目へフォーカスを移して確認へ進まない。
5. 正常なら入力値を確認画面へ表示する。
6. 「入力を修正」では値を保持したまま入力画面へ戻る。
7. 「送信する」では送信・修正ボタンを無効化し、送信中を表示する。
8. 1秒の待機後、選択した確認用結果に応じて成功画面またはフォーム全体エラーを表示する。
9. 成功後の「別の内容を入力」ではフォームを初期化する。送信失敗では値を保持して入力画面へ戻す。

## 5. 状態

| 状態 | 実装状況 | 表示・制御 |
|---|---|---|
| input | 実装済み | フォーム入力 |
| validation error | 実装済み | 項目別エラー、最初のエラー項目へフォーカス |
| confirm | 実装済み | 入力値の確認、送信または入力修正 |
| submitting | 実装済み | 送信中、送信・修正button無効 |
| success | 実装済み | 完了表示、顧客名・メール、次の入力操作 |
| form error | 実装済み | 送信失敗、入力値保持、再試行案内 |

## 6. 実装範囲

- 要件にある入力、項目別エラー、確認、送信中、成功、フォーム全体エラー、修正導線を実装する。
- 「確認する送信結果」は学習時に成功と失敗を安全かつ再現可能に切り替えるための操作である。
- 作成成果物の「API送信風処理」として1秒の待機で通信状態を模擬する。API・DBへの実送信と永続化は要件の対象外である。

## 7. 確認手順

1. 空欄送信で顧客名・メールの項目別エラーを確認する。
2. 不正なメールと201文字の備考で各ルールを確認する。
3. 正常入力で確認画面を開き、「入力を修正」で値を保持して戻ることを確認する。
4. 成功を選び、送信中表示、button無効化、成功表示を確認する。
5. 送信失敗を選び、フォーム全体エラー、入力値保持、再試行導線を確認する。

## 8. 完了条件

- 入力、項目別エラー、確認、送信中、成功、フォーム全体エラーを再現できる。
- validationに失敗した場合は送信処理へ進まない。
- 送信待機中の二重操作を画面上で防げる。
- エラー発生時に値を失わず、修正または再試行できる。
