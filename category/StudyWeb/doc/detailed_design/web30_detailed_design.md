# web30 詳細設計
## エラー記録サンプル

---

## 1. 実装ディレクトリ構成

```text
doc/templates/web30_error_log_note/
└── error-log-template.md
doc/learning_notes/web30_error_log_note/
├── README.md
└── examples/
    ├── css-not-loaded.md
    └── api-404.md
```

## 2. モジュール詳細

| ファイル | 役割 | 主な内容 |
|---|---|---|
| `error-log-template.md` | 記録様式 | 発生日時、現象、再現手順、予想、事実、原因、対応、次回確認 |
| `css-not-loaded.md` | 記入例 | 相対パスが原因のCSS未読込 |
| `api-404.md` | 記入例 | フロントとAPIの経路不一致 |
| 学習用`README.md` | 使い方 | StudyHubでの確認と別ファイルへの記録手順 |

## 3. API 詳細

HTTP API は使用しない。記録項目をIFとして定義する。

## 4. 詳細API I/O 定義

| 項目 | 必須 | 内容 |
|---|---|---|
| 発生日時 | ○ | いつ起きたか |
| 環境 | ○ | OS/ブラウザ/Node等 |
| エラー内容 | ○ | 原文 |
| 再現手順 | ○ | 手順 |
| 原因 |  | 判明内容 |
| 解決方法 | ○ | 対応 |
| 次回確認 |  | 見る場所 |

## 5. 入力チェック仕様

| 対象 | ルール |
|---|---|
| エラー原文 | code block |
| 秘密情報 | 記載しない |
| 再現手順 | 箇条書き |

## 6. エラー応答仕様

| error_code | 発生条件 | 対応 |
|---|---|---|
| `secret_in_log` | APIキー等記載 | マスク/削除 |
| `missing_reproduction` | 再現手順なし | 追記 |

## 7. バリデーション一覧

| 対象 | 確認 |
|---|---|
| template | 必須項目あり |
| examples | 2件以上 |
| README | 使い方あり |

## 8. データベース詳細

DBは使用しない。

## 9. AI 処理詳細

AI処理は使用しない。

## 10. エラー・監査設計

- 個人情報や秘密情報の混入を確認する
- 監査ログは扱わない

## 11. DDL

DBを使用しないため DDL はない。

## 12. 実装メモ

- 原因が推測の場合は「推測」と明記する
- 解決済みと未解決を分けて書けるようにする
- StudyHubはひな形と2件の記入例を読み取り専用で表示し、実際の記録と保存はひな形を複製した別ファイルで行う
