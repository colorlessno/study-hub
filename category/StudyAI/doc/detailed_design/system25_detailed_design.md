# System 25 詳細設計

## 対象機能

出力上限とTemperatureの比較を、実モデルへの通信、条件別集計、履歴保存まで含めて実行する。

## 実行API

`POST /api/system25/execute`へ次のJSONを送る。

```json
{
  "prompt": "返品手順を初めて利用する人向けに説明してください。",
  "model": "qwen3-27b-q4",
  "max_tokens_values": [32, 128],
  "temperatures": [0.2, 0.8],
  "trial_count": 2,
  "mode": "model",
  "learning_note": {
    "observation": "",
    "decision": "",
    "risk_note": ""
  }
}
```

入力値は次の順に検証する。

1. `prompt`が1～8000文字であること。
2. `model`が空でないこと。
3. `max_tokens_values`が1～5件で、各値が1～4096の重複しない整数であること。
4. `temperatures`が1～5件で、各値が0～2の重複しない数値であること。
5. `trial_count`が1～5の整数であること。
6. `mode`が`model`または`mock`であること。
7. `learning_note`がオブジェクトであること。

## 実モデルの実行

`mode=model`の場合は、出力上限、Temperature、試行番号の順にループする。各試行で`LLMClient.generate_text_with_metadata`へ固定指示、Temperature、モデル名、出力上限を渡し、応答を`await`して結果へ追加した後にだけ次の試行へ進む。同時送信や並列処理は行わない。

OpenAI互換APIへ送る主な値は次のとおり。

```json
{
  "model": "入力で指定したモデル",
  "messages": [{ "role": "user", "content": "固定した指示" }],
  "temperature": 0.2,
  "max_tokens": 32,
  "stream": false
}
```

各応答から回答本文、応答モデル、入力・出力トークン数、`finish_reason`を取得する。通信開始から完了までを計測し、ミリ秒で記録する。

## 途中切れ判定

`finish_reason`が`length`の場合だけ`cutoff=true`とする。回答文字数と出力上限の単純比較だけで途中切れを決めない。`finish_reason`が取得できない場合は値を保持し、途中切れとは断定しない。

## 条件別集計

出力上限とTemperatureが同じ試行をまとめ、次を計算する。

- 試行数
- 途中切れ回数と途中切れ率
- 異なる回答数
- 平均回答文字数
- 平均出力トークン数
- 平均応答時間

候補設定は、途中切れ回数が0の条件を優先する。その中から平均出力トークン数、平均応答時間の順で小さい条件を選ぶ。途中切れがない条件が存在しない場合は、途中切れ率が低い条件から同じ順で選ぶ。

## モック

`mode=mock`の場合だけ、固定した模擬回答を用いる。出力上限に合わせて模擬回答を短縮し、`finish_reason`と途中切れを設定する。Temperatureが高い条件では試行ごとに回答例を変え、比較画面の操作を確認できるようにする。実通信の失敗をモックへ置き換えない。

## 応答データ

応答の`result`には次を含める。

- `generation_mode`と表示名
- 固定した指示、モデル名、試行回数
- `matrix_results`
- `setting_summaries`
- 候補設定と選定理由
- 学習メモ
- 保存状態
- 比較時の注意事項

## 履歴保存

実行結果は`data/ai_learning/system25_runs.json`へ保存する。メモリ上とファイル上の履歴は直近20件に制限する。JSONはUTF-8で一時ファイルへ書き、保存先へ置き換える。起動時に配列と各要素の形式を確認し、不正な場合は読み込みエラーにする。

## エラー処理

- 実モデルの同期実行入口が使われた場合は、非同期実行入口を使用するようエラーを返す。
- 入力値が範囲外または重複している場合は、該当項目を示すエラーを返す。
- LM Studioへの接続失敗、タイムアウト、応答形式不正は呼び出し元へ返す。
- 履歴ファイルの読み書きに失敗した場合は、対象ファイルを示すエラーにする。

## テスト観点

- 全条件が指定試行回数だけ実行される。
- モデル名、Temperature、出力上限がLLMクライアントへ渡る。
- `finish_reason=length`だけが途中切れになる。
- 条件別の試行数、途中切れ回数、異なる回答数が一致する。
- 候補設定が比較対象の中から選ばれる。
- モックは明示指定時だけ動作する。
- 保存した直近20件を再起動後に復元できる。
