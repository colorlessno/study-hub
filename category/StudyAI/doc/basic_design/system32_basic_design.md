# System 32 基本設計

## RAG評価セット

### 全体構成

```text
利用者
  ↓ StudyAI system32画面
  ↓ POST /api/system32/execute
LearningSystemService
  ├─ 評価セットの入力検証
  ├─ ケース別の検索・生成評価
  ├─ 全体指標の集計
  ├─ 同じ評価セットの直前実行との比較
  └─ JSON実行履歴の保存
```

system32はStudyAIの共通学習画面、共通API、共通サービスへ組み込む。system32専用の別アプリは作らない。

### 実装の配置

| ファイル | 役割 |
|---|---|
| `src/backend/src/studyai/systems/ai_learning/catalog.py` | 既定入力、比較サンプル、画面説明を定義する |
| `src/backend/src/studyai/systems/ai_learning/service.py` | 入力検証、評価、集計、前回比較、保存を行う |
| `src/backend/src/studyai/systems/ai_learning/router.py` | metadata、execute、runsのAPIを提供する |
| `src/backend/src/studyai/common/config/settings.py` | 実行履歴の保存先を定義する |
| `src/frontend/src/pages/SystemLearningPage.tsx` | 入力、ケース別結果、集計、差分、保存状態を表示する |
| `src/backend/tests/systems/test_ai_learning_systems.py` | 評価、比較、保存、入力エラーを検証する |
| `scripts/validate-ai-learning.py` | 既定入力で教材全体の成立を検証する |

### 画面構成

| 画面領域 | 表示・操作内容 |
|---|---|
| 実験条件 | 評価セット名、実行名、RAG設定、正解データ、検索結果、生成回答、学習メモをJSONで編集する |
| サンプル | 基準実行、検索悪化、生成悪化を選択する |
| 集計 | 評価件数、検索成功率、生成成功率、検索失敗件数、生成失敗件数、保存状態を表示する |
| ケース別結果 | 正解文書、上位検索結果、生成回答、失敗箇所、回答評価を表示する |
| 前回との差 | 比較対象の実行名、指標差分、悪化した指標を表示する |
| 学習メモ | 観察結果、設計判断、残る注意点を表示する |
| 実行履歴 | 保存した実行を一覧表示する |

### ケース別の判定

検索成功は、`top_k`件までの検索結果に正解文書番号が1件以上含まれることとする。生成成功は、生成回答に期待する回答が含まれることとする。

判定は次の優先順で表示する。

1. 正解文書が取得できていない場合は検索失敗。
2. 正解文書を取得できたが回答が期待を満たさない場合は生成失敗。
3. 両方を満たす場合は成功。

検索成功率と生成成功率は別々に集計するため、検索失敗ケースでも生成回答自体が期待語を含むか確認できる。

### 前回比較

同じ `dataset_name` と同じ `rag_config` を持つ直前の実行を比較対象とする。検索成功率、生成成功率、回答評価の平均について現在値から前回値を引き、負の差となった指標を悪化した指標として表示する。初回実行、またはRAG設定を変更した実行では比較対象なしと表示する。

### 保存

実行履歴は `data/ai_learning/system32_runs.json` に新しい順で最大20件保存する。保存時は一時ファイルを作成してから置き換え、途中書き込みのファイルを残さない。起動時にJSONを読み込み、形式が不正な場合は起動エラーとして報告する。

### API

| メソッド | パス | 用途 |
|---|---|---|
| `GET` | `/api/system32/metadata` | 画面名、既定入力、サンプルを取得する |
| `POST` | `/api/system32/execute` | 入力を評価し、結果を保存する |
| `GET` | `/api/system32/runs` | 保存済みの実行履歴を取得する |

入力エラーは400、存在しないsystem番号は404、処理中の予期しないエラーは500として、共通エラー形式で返す。

### 実行環境

system32の評価ロジックは固定したサンプルデータだけで実行できる。LM Studioや外部APIは必須としない。StudyAIの既存バックエンド、フロントエンド、Docker構成を利用する。
