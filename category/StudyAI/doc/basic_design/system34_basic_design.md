# System 34 基本設計

## 回答内容の評価

## 設計目的

AI回答を好みや印象ではなく、正確性、根拠性、網羅性、簡潔性の四つに分けて評価する。質問に必要な回答要素、回答内の主張、参照した根拠の対応を画面で確認できるようにし、回答不足、根拠のない主張、不要な補足を区別する。

## StudyAI内の構成

system34は、system17以降で共用している学習システムの構成へ組み込む。

```text
SystemLearningPage
  ↓ POST /api/ai-learning/system34/runs
LearningSystemService._answer_eval
  ↓ 入力・結果・学習メモをまとめる
data/ai_learning/system34_runs.json
  ↑ GET /api/ai-learning/system34/runs
実行履歴
```

テーマ定義と実行例は `ai_learning/catalog.py`、評価処理と保存は `ai_learning/service.py`、結果表示は `SystemLearningPage.tsx` が担当する。system34だけの別APIや別画面は作らない。

## 入力

| 項目 | 内容 |
|---|---|
| `evaluation_name` | 評価結果を識別する名前 |
| `question` | AIへ与えた質問 |
| `expected_answer` | 人が確認するときの期待する回答 |
| `expected_points` | 必要な回答要素、必要語句、矛盾語 |
| `evidence` | 根拠番号と根拠文 |
| `generated_answer` | 評価するAI回答 |
| `answer_claims` | 回答内の主張、参照した根拠、対応する回答要素、根拠確認用の語句 |
| `learning_note` | 観察結果、設計判断、残る注意点 |

主張の本文は `generated_answer` に含まれている必要がある。主張から参照する根拠番号と回答要素番号は、入力内に存在する値だけを許可する。

## 評価処理

| 観点 | 判定方法 |
|---|---|
| 正確性 | 各回答要素の矛盾語がAI回答に含まれていない割合 |
| 根拠性 | 各主張の確認用語句を、参照した根拠文で確認できる割合 |
| 網羅性 | 必要な回答要素の語句がAI回答に含まれている割合 |
| 簡潔性 | 質問に必要な回答要素へ対応する主張の割合 |

点数は0から1で表し、四観点の平均を総合点とする。判定は同じ入力から同じ結果を再現できる規則ベースとし、意味の妥当性まで自動確定しない。

## 回答分類

| 分類 | 条件 |
|---|---|
| 不正確な回答 | 矛盾語が含まれる回答要素がある |
| 回答不足 | 必要語句が含まれない回答要素がある |
| 根拠のない主張 | 参照した根拠で確認用語句を確認できない主張がある |
| 不要情報を含む回答 | 根拠はあるが必要な回答要素へ対応しない主張がある |
| 要件を満たす回答 | 上記の問題がない |

一つの回答に複数の問題がある場合は、該当する分類をすべて表示する。

## 画面

画面には入力JSON、実行例、実行結果、実行履歴、READMEを表示する。結果領域には次を順に表示する。

- 総合点と四観点の点数
- 質問、期待する回答、評価する回答
- 回答の分類と判定理由
- 必要な回答要素の充足・矛盾判定
- 回答内の主張と根拠の対応
- 使用した根拠
- 改善内容と学習メモ
- 評価方法と保存状態

## 保存

実行入力、評価結果、学習メモ、実行日時を `system34_runs.json` にUTF-8で保存する。保存時は一時ファイルを置き換え、最大20件を保持する。再起動後は保存ファイルを読み込み、実行履歴へ戻す。

## エラー

- 必須文字列が空の場合は、その項目名を示して実行を拒否する。
- 回答要素、根拠、主張が配列でない場合や件数範囲外の場合は実行を拒否する。
- 番号が重複する場合、または存在しない根拠・回答要素を参照する場合は実行を拒否する。
- 主張本文がAI回答に含まれない場合は実行を拒否する。
- 保存ファイルがJSON配列でない場合は、対象ファイルを示して起動時にエラーとする。

## 実行環境

StudyAIの既存Docker構成でバックエンド、フロントエンド、PostgreSQLを起動する。system34の評価自体は外部AI APIを必要とせず、固定した入力で評価規則と保存結果を確認できる。
