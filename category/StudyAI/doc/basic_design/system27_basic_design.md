# System 27 基本設計

## 画像サイズとVLM精度比較

## 設計目的

同じ内容の画像をサイズとJPEG品質だけ変えてVLMへ送り、回答、読み取れた要点、読み落とし、処理時間、データ量を比較する。外部通信を行う実VLM動作と、画面・評価手順を通信なしで確認する明示的なモック動作を分け、モック結果を実モデルの性能と誤認させない。

## システム構成

```text
SystemLearningPage.tsx
  ↓ POST /api/system27/execute
ai_learning/router.py
  ↓
LearningSystemService
  ├─ 同一のサンプル画像を生成
  ├─ サイズ・JPEG品質別に画像を変換
  ├─ model: VLMClientからLM StudioのOpenAI互換APIへ画像送信
  ├─ mock: 入力された模擬回答を使用
  ├─ 必須要点の網羅率と読み落としを集計
  └─ data/ai_learning/system27_runs.jsonへ比較結果を保存
```

実装は `src/backend/src/studyai/systems/ai_learning/` の共通カタログ、サービス、ルーターと、`src/frontend/src/pages/SystemLearningPage.tsx` を使用する。system27専用の別画面や別APIは増やさない。

## 入力

| 項目 | 内容 |
|---|---|
| `mode` | `model`は実VLM通信、`mock`は明示的な模擬回答 |
| `model` | LM Studioへ指定するVLMモデル名 |
| `task_prompt` | 画像を見て実行する指示 |
| `sample_image` | 同一条件で比較する画像の見出しと文字列 |
| `image_variants` | 画像ID、表示名、横幅、JPEG品質を2～6件指定 |
| `expected_points` | 回答に含まれるべき要点 |
| `mock_responses` | mock時に画像IDごとに使う模擬回答 |
| `learning_note` | 観察結果、採用判断、注意点 |

組み込みサンプルは、返品期限、商品の状態、申請に必要な情報を含むOCR混在画像を生成する。各条件で画像内容と指示を固定し、サイズとJPEG品質だけを変える。

## 処理

1. 入力値、画像IDの重複、横幅、JPEG品質を検証する。
2. 1280×720の同一サンプル画像を生成する。
3. 各条件の横幅へ縮小し、指定したJPEG品質で圧縮する。
4. `model`では画像データURLを入力順に一件ずつVLM APIへ送信し、直前の応答完了後に次へ進む。同時送信や並列処理は行わない。`mock`では通信せず、指定済みの模擬回答を使用する。
5. 回答とVLMが返した要点を期待語句と照合し、網羅率、確認できた要点、読み落としを求める。
6. 網羅率が最高の画像のうちデータ量が最小の条件を推奨候補にする。
7. 入力、比較結果、学習メモを最大20件保存する。

## 出力と画面

画面には比較方法、モデル、推奨サイズ、保存状態、固定した指示と確認要点を表示する。各画像カードに実際の変換画像、縦横サイズ、JPEG品質、データ量、回答、要点網羅率、読み落としを表示し、その下に全条件を横並びで比較できる表を置く。

推奨表示は自動的な採用決定ではない。複数画像による再評価と人手確認が必要であることを併記する。

## API

| メソッド | パス | 用途 |
|---|---|---|
| GET | `/api/system27/metadata` | 画面名、既定入力、サンプルを取得 |
| POST | `/api/system27/execute` | 画像を変換し、VLMまたはmockで比較を実行 |
| GET | `/api/system27/runs` | 保存済みの比較履歴を取得 |

入力不備は `system27_input_invalid` として400を返す。VLM通信失敗は共通の外部サービスエラーとして処理し、mockへ自動的に切り替えない。

## 保存

比較結果は `data/ai_learning/system27_runs.json` にUTF-8のJSONとして保存する。最大20件を保持し、更新時は一時ファイルから置き換える。画像は比較結果内のデータURLとして保存されるため、個人情報・機密情報を入力画像へ含めない。

## 実行環境

StudyAIのbackendとfrontendはDockerで起動する。backendコンテナからLM Studioへは `http://host.docker.internal:5858/v1` で接続する。実VLM確認時は画像入力に対応したモデルをLM Studioへロードし、`model`をその識別子へ変更する。

## 完成条件

- 同じ元画像から複数の実画像を生成し、サイズとデータ量を確認できる。
- model時に各画像をVLMへ送信し、実際の回答を比較できる。
- mock時は通信しないことと模擬結果であることが画面で明示される。
- 回答、確認できた要点、読み落とし、網羅率、推奨候補を確認できる。
- 比較結果と学習メモが保存され、再起動後も履歴を取得できる。
