# System 26 基本設計

## 量子化方式の比較

## システムの構成

```text
利用者
  ↓ 比較条件と学習メモを入力
StudyAI画面
  ↓ POST /api/system26/execute
LearningSystemService
  ├─ 実モデル比較 → LLMClient → LM Studio OpenAI互換API
  └─ 明示的なモック → 登録済みの模擬回答
  ↓ 同一条件で評価・比較
比較結果を画面へ表示
  ↓
system26_runs.jsonへ保存
```

## 主な構成要素

| 構成要素 | 役割 |
|---|---|
| `catalog.py` | 既定の比較プロファイル、実行環境メモ、評価基準、サンプルを定義する |
| `service.py` | 入力検証、モデル通信、応答時間計測、品質評価、候補選択、履歴保存を行う |
| `router.py` | メタデータ取得、比較実行、履歴取得のAPIを提供する |
| `SystemLearningPage.tsx` | 比較条件の編集、実行、比較表、トレードオフ、学習メモを表示する |
| `system26_runs.json` | 最新20件の比較条件と結果を保存する |

## 入力

| 項目 | 内容 |
|---|---|
| `prompt` | すべての比較対象へ送る同一の指示 |
| `quantization_profiles` | 識別子、モデル名、表示名、量子化方式、モック回答 |
| `runtime_metrics` | プロファイルごとのメモリ使用量、モック用応答時間、実行環境メモ |
| `evaluation_rubric` | 必須語句、回答長、網羅率と簡潔さの重み |
| `selection_priority` | `memory`、`speed`、`quality`、`balanced` |
| `temperature` | 全モデルに共通で使うTemperature |
| `mode` | `model`または`mock` |
| `learning_note` | 観察結果、採用判断、残る注意点 |

## 処理

### 実モデル比較

1. 入力値と比較条件を検証する。
2. 各量子化プロファイルのモデル名でLM Studioへ入力順に一件ずつ通信し、直前の応答完了後に次へ進む。同時送信や並列処理は行わない。
3. 通信開始から応答取得までの時間を計測する。
4. 回答に含まれる必須語句と回答長から品質点を算出する。
5. 入力されたメモリ使用量、応答時間、品質点を正規化し、総合点を算出する。
6. 優先条件に従って採用候補を選ぶ。
7. 比較条件、結果、学習メモをJSONへ保存する。

### 明示的なモック

モデル通信を行わず、登録済みの模擬回答と模擬応答時間を使う。それ以外の評価、比較、表示、保存は実モデル比較と同じ構造にする。実モデル通信の失敗から自動的にモックへ切り替えない。

## 出力

| 項目 | 内容 |
|---|---|
| `comparison_mode` | 実モデル通信か明示的なモックか |
| `fixed_conditions` | 指示、Temperature、品質評価基準 |
| `profile_results` | モデル、回答、メモリ、時間、品質点、各正規化点、総合点 |
| `runtime_summary` | メモリ最小、最速、品質最高の各方式 |
| `selected_profile` | 優先条件に従って選んだ候補 |
| `selection_reason` | 候補を選んだ理由 |
| `tradeoff_note` | メモリ、速度、品質の違いを示す説明 |
| `learning_note` | 利用者が入力した学習メモ |
| `storage_status` | JSONへの保存状態 |

## API

| メソッド | パス | 目的 |
|---|---|---|
| GET | `/api/system26/metadata` | 既定値、サンプル、画面説明を取得する |
| POST | `/api/system26/execute` | 実モデルまたはモックで比較を実行する |
| GET | `/api/system26/runs` | 保存済みの比較履歴を取得する |

## 画面

- 入力JSONとサンプル選択
- 実行ボタンと実行状態
- 比較方法、優先条件、採用候補、保存状態
- 固定した比較条件
- 量子化プロファイル別の比較表
- 用途別の最良結果とトレードオフ
- 学習メモと確認上の注意
- 実行履歴

## 保存

- 保存先は `data/ai_learning/system26_runs.json` とする。
- Dockerではバックエンドのdataフォルダをホストへマウントし、コンテナ再作成後も保持する。
- 最新20件を保存する。
- UTF-8のJSONとして一時ファイルへ書き、置換して保存する。

## エラー時の扱い

- 入力形式、比較対象、測定値、評価基準が不正な場合は実行せず、理由を返す。
- 指定モデルがLM Studioに存在しない場合は通信エラーを返す。
- モデル通信失敗時にモック結果を返さない。
- 保存済みJSONが壊れている場合は、履歴を無視せず読み込みエラーとして扱う。
