# System 35 基本設計

## Prompt A/B比較

## 設計目的

Promptを変更した効果を、同じ実行条件と評価ケースで比較する。A/Bの回答を同じ規則で採点し、全体平均だけでなく改善したケースと悪化したケースを画面で確認する。採用または保留の判断、その理由、残る注意点を比較結果と一緒に保存する。

## StudyAI内の構成

system35は、system17以降で共用している学習システムの構成へ組み込む。

```text
SystemLearningPage
  ↓ POST /api/ai-learning/system35/runs
LearningSystemService._prompt_ab
  ↓ 入力・比較結果・採用判断をまとめる
data/ai_learning/system35_runs.json
  ↑ GET /api/ai-learning/system35/runs
実行履歴
```

テーマ定義と実行例は `ai_learning/catalog.py`、比較処理と保存は `ai_learning/service.py`、結果表示は `SystemLearningPage.tsx` が担当する。system35だけの別APIや別画面は作らない。

## 入力

| 項目 | 内容 |
|---|---|
| `experiment_name` | 比較結果を識別する実験名 |
| `prompt_a` | 変更前または比較元のPrompt |
| `prompt_b` | 変更後または比較先のPrompt |
| `fixed_conditions` | モデル、温度、最大出力トークン数、評価データ版 |
| `scoring_weights` | 正確性、根拠性、網羅性、簡潔性の重み |
| `evaluation_cases` | 質問、必要語、根拠語、禁止語、文字数上限、A/Bの記録済み回答 |
| `adoption_record` | 採用または保留の判断、理由、残る注意点 |

A/Bの回答は同じモデル設定と評価データ版で取得したものを記録する。外部AIを使用できない場合は、カタログに保存したサンプル回答を使用し、比較処理と保存を再現する。

## 採点処理

| 観点 | 判定方法 |
|---|---|
| 正確性 | 禁止語が回答に含まれなければ1、含まれれば0 |
| 根拠性 | 根拠語のうち回答に含まれる割合 |
| 網羅性 | 必要語のうち回答に含まれる割合 |
| 簡潔性 | 文字数上限以内なら1、超えた場合は上限文字数を回答文字数で割った値 |

ケースごとの合計点は、四観点の点数へ `scoring_weights` を掛けた合計とする。Promptごとの平均点は、全ケースの合計点を平均する。Bの点数からAの点数を引き、正なら「Prompt Bで改善」、負なら「Prompt Bで悪化」、0なら「同点」とする。

平均点が高いPromptを点数上の推奨とし、同点なら「保留」とする。利用者が記録した判断と点数上の推奨が一致しているかも表示する。点数だけで採用を確定せず、回答原文とケース別の採点根拠を併せて確認する。

## 画面

画面には入力JSON、実行例、実行結果、実行履歴、READMEを表示する。結果領域には次を順に表示する。

- 勝者、評価ケース数、A/B平均点、点差、改善件数、悪化件数
- Promptごとの四観点の平均点
- ケース別のA/B点数、点差、改善・悪化・同点
- A/B回答と、不足した必要語、根拠語、検出した禁止語
- 記録した採用判断、点数上の推奨、理由、残る注意点
- 固定した実行条件、採点の重み、評価方法、保存状態

## 保存

実行入力、比較結果、採用判断、実行日時を `system35_runs.json` にUTF-8で保存する。保存時は一時ファイルを置き換え、最大20件を保持する。再起動後は保存ファイルを読み込み、実行履歴へ戻す。

## エラー

- 実験名またはA/BのPromptが空の場合は実行を拒否する。
- 固定条件の必須項目がない場合、温度が数値でない場合、最大出力トークン数が1未満の場合は実行を拒否する。
- 採点の重みが四観点を含まない場合、負の値を含む場合、合計が1.0でない場合は実行を拒否する。
- 評価ケースが空の場合、ケース番号が重複する場合、必須文字列・必要語・根拠語・文字数上限が不足する場合は実行を拒否する。
- 採用判断がA、B、保留のいずれでもない場合、判断理由が空の場合は実行を拒否する。
- 保存ファイルがJSON配列でない場合は、対象ファイルを示して起動時にエラーとする。

## 実行環境

StudyAIの既存Docker構成でバックエンド、フロントエンド、PostgreSQLを起動する。system35の比較自体はバックエンドAPIで行い、外部AI APIを必須にしない。実際のモデルを使った比較では、同じ条件で取得したA/B回答を入力へ記録する。
