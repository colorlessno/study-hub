# System 36 要件定義
## Trace保存

## 1. 目的
AI処理の入力、検索根拠、モデル設定、Prompt、出力、評価を一つのTraceとして保存し、後から処理条件と回答理由を確認できるようにする。保存前に指定した機密値をマスクし、再現性と監査性を保ちながら記録へ残す情報を判断する。

## 2. 学習対象
- AIシステムの要件定義、基本設計、詳細設計、製造に進むための最小単位のテーマとして扱う。
- 商品・顧客・注文管理へ統合する最終ポートフォリオは対象外とし、この番号では土台となる観察、比較、評価、データ品質だけを扱う。
- 既存 `system01` から `system16` の成果物は変更しない。

## 3. 対象ユーザー
- AIアプリケーションの設計・実装を学習する開発者
- RAG、LLM評価、ローカルAI実行環境の判断材料を整理したい学習者

## 4. 入力

- Trace名
- 利用者入力
- 検索根拠
- モデル設定
- Prompt本文と版
- モデル出力
- 評価番号、評価状態、評価点、評価メモ
- マスクの有効・無効、置換文字列、マスク対象語
- 保存件数に関する説明

## 5. 出力

- Trace番号、記録日時、改変確認用ハッシュ
- マスク後のTrace JSON
- 評価結果との対応
- 不足項目と再実行可否
- マスク件数とマスクした項目
- 保存状態、保存方針、再実行メモ
- 保存済みTraceの一覧と詳細

## 6. 機能要件
- 1回のAI処理をTrace番号で識別し、JSONファイルへ保存できる。
- 同じ記録内容から同じTrace番号と改変確認用ハッシュを作れる。
- 検索根拠、モデル設定、Prompt本文・版、出力を一つの記録として残せる。
- 評価番号、評価状態、評価点をTraceへ紐付けられる。
- 必要項目が不足する場合は、不足項目と再実行できない理由を表示できる。
- 指定した機密値を保存前に置換し、元のマスク対象語を保存しない。
- 保存済みTraceを一覧から選択し、入力と結果の詳細を再表示できる。
- 最新20件を保存し、バックエンド再起動後に読み戻せる。

## 7. 非機能要件
- 実行済みAI処理の記録を扱う教材とし、外部AI APIを必須にしない。
- JSON保存は一時ファイルへ書き込んでから置き換え、書き込み途中のファイルを残さない。
- Docker に入れられる実装は `Dockerfile` または `docker-compose.yml` を用意する。
- 作成・更新するテキストファイルは UTF-8 BOMなしを原則とする。
- 保存するTraceにはマスク前の対象語を含めない。

## 8. 受入条件
- 既定値を実行すると、再実行に必要な項目が揃ったTraceをJSONへ保存できる。
- 不足項目の入力例では、Prompt本文・版と評価結果の不足を確認できる。
- マスクの入力例では、画面と保存ファイルの両方からマスク対象語が除かれる。
- 評価番号と評価結果をTraceの詳細で確認できる。
- バックエンド再起動後も保存済みTraceを一覧と詳細で確認できる。

## 9. 保存上の注意

- Traceへ残す情報は、障害調査や再実行に必要な範囲へ限定する。
- APIキー、認証情報、個人情報などの実値は入力例に使用しない。
- 学習用の保存件数は最新20件とし、本番運用では保持期限、削除、アクセス制御を別途設計する。

## 10. 対象外
- 本番クラウドへのデプロイ
- 課金が発生する外部APIを前提にした必須実装
- 保存済みTraceの更新・削除・全文検索
- 本番用途の暗号化、権限制御、保持期限管理
- 商品・顧客・注文管理の統合ポートフォリオへの組み込み
