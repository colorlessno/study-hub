# System 15 要件定義

## このテーマでできるようになること

- 要件定義で扱う「AIの役割範囲・ガードレール要件」を説明できる
- 基本設計で扱う「**VLM（マルチモーダル）設計**・複雑パイプライン設計・設定で選択したローカルモデルの逐次利用」を説明できる
- 詳細設計で扱う「システムプロンプト設計・チャンキング（ページ・セクション単位）・コンテキストウィンドウ制約」を説明できる
- 実装で扱う「**VLM実装（Qwen3-VL）**・**Tesseract OCR実装**・**OCR融合処理実装**・**Detectron2（レイアウト解析）実装**・**PyAutoGUI（画面自動操作）実装**・リトライ・エラーハンドリング・再開制御」を説明できる
- 検証で扱う「ガードレール検証（タイムアウト・過大出力隔離）」を説明できる
- Python（OpenCV・Pillow・画像処理）・パイプライン設計を横断的に使う構成を説明できる

## 電子書籍 セクション別自動要約システム

---

## システム概要

手元にある著作権フリーの電子書籍（画像・PDF・ePub等）を対象に、電子書籍リーダーを自動操作してページをキャプチャし、OCR・VLM・レイアウト解析を組み合わせてセクション（部・章・節・項）ごとに構造化テキストを抽出、図表・イラストの説明文と位置関係を把握した上でセクションごとの要約を自動生成するシステム。

既存実装（book_summarization_cli）を実用レベルに再開発する。

---

## 現状の課題

- 技術書・教科書の要点把握に時間がかかる
- セクションごとの内容を素早く把握したい
- 図表・イラストが多い書籍では、図表と本文の対応関係を把握しにくい
- 既存実装はパイプラインが複雑で処理の安定性に課題がある
- セクション境界の検出精度が書籍によってばらつく
- 図表検出・説明文生成の精度が不安定

---

## 対象ユーザー

- 個人学習者・読書家（技術書・教科書の要点把握）
- 研究者・教育関係者（書籍構造の把握・教材化）
- ローカル環境で要約パイプラインを運用・改善する開発者

---

## 対象書籍・入力対象

- 著作権フリーの電子書籍（青空文庫・技術書・教科書等）
- ユーザーが手元に持つ画像・PDF・ePub等のファイル
- 電子書籍リーダーで表示できるもの

---

## 処理パイプライン全体

```
【フェーズ1：ページ画像取得】
電子書籍リーダーを自動操作してページをキャプチャ

【フェーズ2：ページ前処理】
余白トリミング → 見開きページの左右分割

【フェーズ3：OCR・テキスト抽出】
Tesseract OCR + VLM OCR の融合処理

【フェーズ4：構造解析】
TOC（目次）検出 → セクション番号・タイトル検出 → セクション境界確定

【フェーズ5：図表・ビジュアル処理】
図表・イラスト領域検出 → 切り抜き → VLMによる説明文生成
→ 本文との位置関係記録

【フェーズ6：要約生成】
セクションごとに本文＋図表説明文を統合 → LLMで要約生成
→ 章要約・書籍全体要約のロールアップ
```

## 機能要件

### フェーズ1：ページ画像取得

**1-1. キャプチャ機能**

PyAutoGUIで電子書籍リーダーを自動操作し、ページ送りしながら全ページをキャプチャする。

| 設定項目 | 説明 |
|---------|------|
| ページ送りキー | 右矢印キー等（設定可能） |
| フルスクリーン待機時間 | 起動後の待機秒数 |
| ページ送り待機時間 | ページ切り替え後の待機秒数 |
| 最大ページ数 | キャプチャ上限（設定可能） |
| 差分検知 | 同一ページ連続検知で停止 |

**再開発での改善点**
- キャプチャ失敗（リーダーが前面にない等）の検知と自動リトライ
- キャプチャ済みページのスキップ（中断再開対応）
- ページ番号OCRによる自動停止精度の向上

---

### フェーズ2：ページ前処理

**2-1. 余白トリミング機能**

キャプチャ画像からUI要素・余白を除去してページ本体を切り出す。

- ヒートマップベースのページ領域推定
- 上下左右のパディング設定
- 推定結果のオーバーレイ確認画像の生成
- 全ページに対して同一のボックスを適用（統計的に安定した領域）

**2-2. 見開きページ分割機能**

見開き（2ページが1枚になっている画像）を自動検知して左右に分割する。

- 画像幅・中央輝度から見開き判定
- 分割閾値の設定（デフォルト輝度200）
- 分割後の左右ページを独立ファイルとして保存

---

### フェーズ3：OCR・テキスト抽出

**3-1. Tesseract OCR**

- 対応言語：日本語（jpn）+ 英語（eng）の混在対応
- グレースケール変換オプション
- 1ページごとのCSV出力・スキップ設定
- 出力：bbox座標・テキスト・信頼度スコア

**3-2. VLM OCR**

- LM Studio経由でVLMモデルを呼び出してOCRを実行
- 推奨モデル：qwen3-vl-32b-instruct / mistral-small-3.2
- Tesseractが苦手な複雑なレイアウト・崩れたフォントへの対応
- タイムアウト・リトライ設定
- 過大出力（9KB超）の自動隔離

**3-3. OCR融合処理**

TesseractとVLM OCRの結果を統合して精度を向上させる。

- bbox重複検出によるテキストの正規化統合
- フォールバック設定（VLM優先 / Tesseract行優先）
- 垂直方向の重複判定閾値設定
- 統合結果をCSV形式で出力

**再開発での改善点**
- VLM OCRの失敗時フォールバック（Tesseractに自動切り替え）
- 1ページあたりの処理時間上限設定とタイムアウト処理の安定化
- 融合結果の信頼度スコアの精度向上

---

### フェーズ4：構造解析

**4-1. TOC（目次）検出**

VLMでページ密度を分析し目次ページを特定してセクション一覧を抽出する。

- 目次ページの自動特定
- セクション番号・タイトル・ページ番号の抽出
- 抽出結果のJSON保存
- 実行状態ファイルによる途中再開対応

**4-2. セクション番号・タイトル検出**

OCR結果からセクション番号とタイトルを検出する。

| 処理 | 説明 |
|------|------|
| 正規表現マッチング | セクション番号パターン（1.1 タイトル / 1-1 タイトル等）でフィルタ |
| TOCボーナス | TOC一覧との類似度が高いものを優先 |
| LLMパターン推定 | 書籍固有の番号体系をLLMが学習して適用 |
| 章番号連結補完 | 章番号と節番号が分離している場合の自動連結 |

**4-3. セクションタイトル判定（VLM）**

検出候補をVLMが画像を見て最終判定する。

- 画像上でのタイトルの見た目・フォントサイズ・位置から判定
- TOCとの一致度スコアリング
- 判定結果のJSON保存

**4-4. セクション境界の確定（マッピング）**

セクションとページの対応関係（section_page_map）を確定する。

検出ルートは書籍の特性に応じて選択する。

| ルート | 説明 | 向いている書籍 |
|-------|------|--------------|
| toc_guided | TOC検出結果を主軸にセクション境界を決定 | 目次が明確な書籍（推奨） |
| toc_title | TOC＋タイトル検出の組み合わせ | 目次はあるがページ番号がずれやすい書籍 |
| ocr_anchor | OCRで検出したセクション番号アンカーで決定 | 目次なしで番号が明確な書籍 |
| vlm_page | VLMがページごとにセクション番号を判定 | 番号体系が複雑な書籍 |

**再開発での改善点**
- ルート選択の自動推定（書籍特性から最適ルートをLLMが提案）
- セクション連続性検証・自動補正の精度向上
- 各ルートの信頼度スコアの可視化

---

### フェーズ5：図表・ビジュアル処理

**5-1. 図表・イラスト領域検出**

以下の2方式を選択または組み合わせる。

| 方式 | 説明 |
|------|------|
| Detectron2（PubLayNet） | 学習済みモデルでFigure/Tableを自動検出。高速・安定 |
| VLM検出 | VLMが画像を見て図表・イラスト領域をbbox座標で返す。柔軟だが低速 |

検出設定：
- 最小領域サイズ（幅・高さ・面積）の閾値
- 最大検出数/ページ
- スコア閾値

**5-2. 図表領域の精緻化**

検出されたbboxをOCR情報と組み合わせて最適化する。

- キャプション（図の説明文）の自動検出（bbox下方・上方を探索）
- bbox拡張・パディング調整
- 複数の重複検出の統合
- 信頼度スコアが低い場合のVLMフォールバック

**5-3. 図表の切り抜き・エクスポート**

確定した図表領域を切り抜いてファイルに保存する。

- セクションごとにフォルダ分け
- 切り抜き画像・キャプションのインデックスCSV出力
- セクションとの対応関係（どのページのどの位置か）を記録

**5-4. 図表説明文生成（VLM）**

切り抜いた図表画像をVLMに渡して説明文を生成する。

- 推奨モデル：qwen3-vl-32b-instruct
- キャプション情報・周辺本文情報をプロンプトに付与
- タイムアウト時の自動隔離（quarantine）・スキップ設定
- 出力：各図表の説明文JSONL

**再開発での改善点**
- Detectron2とVLM検出の統合精度の向上
- キャプション検出の日本語対応強化
- 説明文生成のプロンプト改善（文脈付加による品質向上）

---

### フェーズ6：要約生成

**6-1. セクションテキスト構築**

セクションページマップに基づき、各セクションの本文テキストと図表説明文を統合する。

- 本文テキスト（OCR結果）をセクション別に集約
- 図表説明文をセクション内の位置情報とともに付与
- ノイズ行の除去・重複行の排除・段落の再構築
- 最大文字数制限（デフォルト24,000文字）によるトリミング

**6-2. セクション要約生成（LLM）**

各セクションの統合テキストをLLMで要約する。

| 設定 | 説明 |
|------|------|
| 使用モデル | qwen3-vl-32b-instruct（LM Studio経由） |
| 最大トークン数 | 320（セクション要約） |
| 入力最大文字数 | 6,000文字 |
| 温度 | 0.1 |

出力内容：
- セクションごとの要約テキスト
- コンパクト入力モード（本文2,200文字＋図表説明最大3件×260文字）

**6-3. 章要約・書籍全体要約のロールアップ**

セクション要約を積み上げて章要約・書籍全体要約を生成する。

| レベル | 入力 | 最大入力文字数 | 最大トークン数 |
|--------|------|--------------|--------------|
| 章要約 | セクション要約の集約 | 6,000文字 | 520 |
| 書籍全体要約 | 章要約の集約 | 12,000文字 | 700 |

**再開発での改善点**
- 要約プロンプトの改善（図表説明文の効果的な活用）
- リトライ時のトークン数自動増加設定の安定化
- コラムページ・巻末索引等の自動除外精度向上

## API仕様

本システムはCLI主体で実行するが、再開発版ではジョブ起動・状態取得・成果物参照を外部IFとして扱えるようにする。以下はローカル実行を前提とした要求インターフェースである。

### POST /jobs
書籍要約ジョブを開始する。

**リクエスト例**
```json
{
  "input_type": "pdf",
  "input_path": "C:/books/sample.pdf",
  "book_id": "sample_book",
  "max_pages": 500,
  "resume": true,
  "enable_visual_extraction": true,
  "output_formats": ["markdown", "json"],
  "rights_confirmed": true
}
```

**レスポンス例**
```json
{
  "job_id": "job_20260407_001",
  "status": "completed"
}
```

### GET /jobs/{job_id}
ジョブの進行状況を取得する。

**レスポンス例**
```json
{
  "job_id": "job_20260407_001",
  "status": "running",
  "current_phase": "section_summary",
  "processed_pages": 128,
  "total_pages": 320
}
```

### GET /jobs/{job_id}/sections
抽出されたセクション一覧と要約結果を取得する。

### GET /jobs/{job_id}/artifacts
OCR結果・図表一覧・最終要約などの成果物メタデータを取得する。

StudyHub連携サービスでは上記を`/api/jobs`配下で提供する。`POST /api/jobs`は既存CLIを一件ずつ順番に実行し、ジョブを`completed`または`failed`としてローカルJSONへ保存してからHTTP 200を返す。処理中は次のジョブをHTTP 409で拒否する。

## プロンプト仕様

### VLM OCR補助プロンプト

- ページ画像から本文・見出し・キャプションを抽出する
- 読み順を維持し、読めない箇所は推測で補完しない
- 出力は構造化JSONまたはCSV変換可能な形式に限定する

### セクション判定プロンプト

- OCR結果・TOC候補・ページ画像をもとに、見出し候補がセクションタイトルかどうかを判定する
- セクション番号・タイトル・信頼度を返す
- TOCとの不一致が大きい場合は低信頼度として返す

### 図表説明文生成プロンプト

- 図表画像と周辺本文を入力として、図表が何を示しているかを簡潔に説明する
- 画像から確認できない内容は推測しない
- 本文と図表の対応関係が曖昧な場合はその旨を明示する

### セクション要約プロンプト

- セクション本文と図表説明文を統合して要点を要約する
- 原文にない結論を追加しない
- 重要語・図表の意味・学習上のポイントを優先して残す

## ガードレール設計

### 1. 入力ガードレール

| チェック内容 | 対応 |
|-------------|------|
| 著作権・利用条件 | 著作権フリーまたは利用許諾済みの書籍のみ対象とする |
| DRM付きコンテンツ | 非対応として処理対象外にする |
| 入力形式 | `pdf` / `image_dir` / リーダー経由キャプチャのみに限定する |
| 最大ページ数 | 設定上限を超える場合はジョブ開始前に警告または中止する |

### 2. 処理ガードレール

| チェック内容 | 対応 |
|-------------|------|
| VLMタイムアウト | フェーズ単位でタイムアウトを設定し、超過時はリトライ後に隔離またはスキップする |
| OCR過大出力 | 9KB超などの異常出力は quarantine に隔離して再処理対象にする |
| ページ処理失敗 | ページ単位で失敗を記録し、他ページ処理は継続する |
| 再開制御 | 完了済みページ・フェーズはスキップして再開できるようにする |

### 3. 出力ガードレール

| チェック内容 | 対応 |
|-------------|------|
| 低信頼度のセクション境界 | `review_required` を付与し、手動確認対象として残す |
| 要約の幻覚 | 原文・図表説明文に根拠がない内容は出力しないようプロンプト制約を設ける |
| 図表説明文の不確実性 | 判読困難な図表は「不明」または低信頼度で返す |

## 再開発における主要課題と対応方針

### 課題1：セクション境界検出の不安定さ
書籍によってセクション番号の形式が異なり、単一ルートでは対応できない。

**対応方針**
- toc_guidedルートを主軸として優先的に使用
- TOCが取得できない・信頼度が低い場合のみ他ルートにフォールバック
- フォールバックの判断基準を信頼度スコアで自動化

### 課題2：VLM処理のタイムアウト・不安定さ
VLMの呼び出しが多く、タイムアウトや応答異常が多発する。

**対応方針**
- タイムアウト検出・自動隔離（quarantine）の強化
- リトライ上限と指数バックオフの設定
- 処理済みページのスキップ設定を全フェーズに適用

### 課題3：図表検出の精度
Detectron2とVLM検出の両方を使うが、誤検出・未検出が発生する。

**対応方針**
- Detectron2を第一選択（高速・安定）
- 低信頼度の検出結果のみVLMで再判定（fallback_vlm）
- bbox精緻化処理でキャプション付与の精度を向上

### 課題4：OCR融合精度
TesseractとVLMのOCR結果の統合でずれが発生する。

**対応方針**
- tesslineフォールバックの活用
- 統合結果の信頼度スコアによる自動フィルタリング
- VLM OCRの過大出力（9KB超）隔離・再処理設定の強化
