# System 03 要件定義
## プロジェクト文書 自然言語Q&Aシステム

---

## システム概要

要件定義書・設計書・議事録・運用手順書などのプロジェクト文書をRAGで読み込み、参画メンバーの質問に自然文で回答するシステム。「このAPIの認証方式は？」「バッチ実行手順はどこにある？」といった問い合わせに対して、根拠文書を提示しながら回答する。

---

## 現状の課題

- プロジェクト文書が複数ファイル・複数フォルダに分散していて探しにくい
- 同じ質問が繰り返し発生し、詳しいメンバーへの問い合わせ負荷が高い
- 回答者によって案内内容にばらつきが出る
- 新規参画者が必要情報へたどり着くまでに時間がかかる
- 夜間や不在時に確認したい内容をすぐ調べられない

---

## 対象ユーザー

- プロジェクト参画メンバー（問い合わせ側）
- ドキュメント管理者・リーダー（文書登録側）

---

## 機能要件

### 1. ドキュメント登録機能
プロジェクト文書をベクトルDBに登録する。

**対応形式**
- PDF・Word（.docx）・テキスト（.txt）・Markdown（.md）
- ファイルサイズ上限：1ファイルあたり50MB
- 複数ファイルの一括登録対応

**登録時の処理**
- テキスト抽出
- チャンキング（段落・セクション単位で分割）
- ベクトル化してpgvectorに保存
- メタデータ（ドキュメント名・カテゴリ・更新日・版数）の登録

**ドキュメントカテゴリ**

| カテゴリ | 例 |
|---------|---|
| 要件・仕様 | 要件定義書・業務仕様書・外部仕様書 |
| 設計 | 基本設計書・詳細設計書・DB設計書 |
| テスト | テスト計画書・テストケース・結果報告書 |
| 議事録 | 定例会議議事録・検討メモ・決定事項一覧 |
| 運用手順 | バッチ実行手順書・障害対応手順・リリース手順 |
| プロジェクトルール | 命名規則・ブランチ運用・レビュー手順 |
| 環境構築 | セットアップ手順・構成一覧・接続情報の案内 |
| その他 | 上記に該当しないプロジェクト文書 |

### 2. Q&A機能
参画メンバーの質問に対してRAGで関連ドキュメントを検索し、LLMが回答を生成する。

**回答の構成**

| 項目 | 説明 |
|------|------|
| 回答本文 | 質問に対する自然文での回答 |
| 根拠ドキュメント | 回答の根拠となったドキュメント名・セクション |
| 該当箇所の引用 | 根拠となる原文の引用（最大3件） |
| 関連質問 | 関連して確認されやすい質問（最大3件） |
| 信頼度 | 回答の確信度（高・中・低） |

**回答できない場合の処理**
- 関連ドキュメントが見つからない場合：その旨を明示し、確認先候補を案内
- 信頼度が低い場合：不確実であることを明示した上で回答

### 3. 会話履歴管理機能（メモリ）
同一セッション内での会話コンテキストを保持する。

- 直前の質問・回答を参照して文脈を維持する
- 「その手順の前提条件は？」のような指示代名詞を含む質問に対応
- セッションは1時間で自動終了

### 4. ドキュメント管理機能
登録済みドキュメントの管理を行う。

- ドキュメントの一覧取得・検索
- ドキュメントの更新（再ベクトル化）
- ドキュメントの無効化・削除
- 古い版や無効な文書の検出・警告

### 5. 質問ログ・分析機能
- 質問内容・回答・フィードバックをログとして保存
- よく聞かれる質問のランキングを取得できる
- 回答できなかった質問の一覧を取得できる
- ユーザーからの回答評価（役に立った / 役に立たなかった）を収集

---

## 非機能要件

| 項目 | 要件 |
|------|------|
| 応答時間 | 1質問あたり30秒以内 |
| 同時利用 | 最大20ユーザーの同時利用 |
| ドキュメント件数 | 最大500ファイル・100,000チャンク |
| セキュリティ | プロジェクト・権限によるドキュメントアクセス制御 |
| 対応言語 | 日本語 |

## システム構成

```
プロジェクト参画メンバー（クライアント）
        ↓
    FastAPI（APIサーバー）
        ↓
    セッション管理
    （会話履歴の保持）
        ↓
    ┌─────────────────────────────────┐
    │  RAG：関連ドキュメント検索        │
    │  質問をベクトル化                 │
    │  → pgvectorで類似チャンクを検索  │
    │  → 上位5件をプロンプトに差し込み  │
    └─────────────────────────────────┘
        ↓
    LLM（回答生成）
    ※ Qwen3-27B / LM Studio
        ↓
    出力バリデーション（Pydantic）
        ↓
    PostgreSQL（ログ・セッション保存）
        ↓
    JSONレスポンス返却

---（ドキュメント登録フロー）---

管理者
        ↓
    POST /documents
        ↓
    テキスト抽出（PyMuPDF / python-docx）
        ↓
    チャンキング（段落・セクション単位）
        ↓
    埋め込みモデルでベクトル化
        ↓
    pgvectorに保存
```

## API仕様

### POST /ask
質問を送信して回答を受け取る。

**リクエスト（JSON）**
```json
{
  "session_id": "sess_abc123",
  "user_id": "member_001",
  "question": "夜間バッチの実行手順はどこにありますか？事前確認事項も知りたいです。",
  "category_filter": ["運用手順"]
}
```

**レスポンス（JSON）**
```json
{
  "answer_id": 1,
  "session_id": "sess_abc123",
  "question": "夜間バッチの実行手順はどこにありますか？事前確認事項も知りたいです。",
  "answer": "夜間バッチの実行手順は「運用手順書_夜間バッチ.md」の『3. 実行手順』に記載されています。事前確認として、当日分の受信データ配置完了、前回バッチの異常終了がないこと、接続先DBの空き容量確認が必要です。",
  "confidence": "高",
  "sources": [
    {
      "document_name": "運用手順書_夜間バッチ.md",
      "section": "3. 実行手順",
      "excerpt": "実行前に受信データ配置、前回終了ステータス、DB空き容量を確認すること。"
    }
  ],
  "related_questions": [
    "異常終了時の再実行手順はどこですか？",
    "受信データの配置先フォルダはどこですか？",
    "実行ログの確認手順はありますか？"
  ]
}
```

### POST /ask/feedback
回答へのフィードバックを送信する。

**リクエスト（JSON）**
```json
{
  "answer_id": 1,
  "is_helpful": true,
  "comment": "必要な手順がすぐ確認できた"
}
```

### GET /projects
プロジェクト一覧を取得する。

**レスポンス（JSON）**
```json
{
  "items": [
    {
      "project_id": "project_001",
      "name": "ECサイトリニューアル"
    }
  ]
}
```

### POST /documents
ドキュメントを登録する。

**リクエスト**
```
Content-Type: multipart/form-data
file: アップロードファイル
category: カテゴリ
version: 版数
access_roles: アクセス可能な権限（JSON配列）
```

### PUT /documents/{document_id}
ドキュメントを更新する（再ベクトル化）。

### DELETE /documents/{document_id}
ドキュメントを無効化する。

### GET /documents
登録済みドキュメント一覧を取得する。

### GET /analytics/popular-questions
よく聞かれる質問ランキングを取得する。

### GET /analytics/unanswered-questions
回答できなかった質問の一覧を取得する。

## データモデル

### documentsテーブル
```sql
CREATE TABLE documents (
    id           SERIAL PRIMARY KEY,
    file_name    VARCHAR(255) NOT NULL,
    category     VARCHAR(50),
    version      VARCHAR(50),
    access_roles JSONB,
    is_active    BOOLEAN DEFAULT TRUE,
    created_at   TIMESTAMP DEFAULT NOW(),
    updated_at   TIMESTAMP DEFAULT NOW()
);
```

### document_chunksテーブル
```sql
CREATE TABLE document_chunks (
    id          SERIAL PRIMARY KEY,
    document_id INTEGER REFERENCES documents(id),
    chunk_text  TEXT NOT NULL,
    section     VARCHAR(255),
    chunk_index INTEGER,
    embedding   VECTOR(1536),
    created_at  TIMESTAMP DEFAULT NOW()
);
```

### sessionsテーブル
```sql
CREATE TABLE sessions (
    id         VARCHAR(50) PRIMARY KEY,
    user_id    VARCHAR(50),
    history    JSONB,
    created_at TIMESTAMP DEFAULT NOW(),
    expires_at TIMESTAMP
);
```

### question_logsテーブル
```sql
CREATE TABLE question_logs (
    id           SERIAL PRIMARY KEY,
    session_id   VARCHAR(50),
    user_id      VARCHAR(50),
    question     TEXT,
    answer       TEXT,
    confidence   VARCHAR(10),
    sources      JSONB,
    is_helpful   BOOLEAN,
    comment      TEXT,
    created_at   TIMESTAMP DEFAULT NOW()
);
```

## プロンプト仕様

### システムプロンプト
```
あなたはプロジェクト文書の案内担当AIです。
以下のプロジェクト文書の内容をもとに、参画メンバーの質問に正確かつ丁寧に回答してください。

ルール：
1. 提供されたドキュメントの内容のみを根拠に回答すること
2. ドキュメントに記載がない内容は「関連文書で確認できないため、担当者に確認してください」と答えること
3. 回答には必ず根拠となるドキュメント名・セクションを明示すること
4. 推測・憶測で回答しないこと
5. 回答は簡潔かつ分かりやすい日本語で返すこと
6. 必ず指定のJSONフォーマットで返すこと

参照ドキュメント：
{retrieved_chunks}

会話履歴：
{conversation_history}
```

### RAG検索設計
- 質問をベクトル化してpgvectorで類似チャンク上位5件を検索
- カテゴリフィルターが指定された場合はカテゴリで絞り込み後に検索
- 類似度スコアが0.7未満のチャンクは除外
- ハイブリッド検索（キーワード＋ベクトル）で精度を向上

---

## ガードレール設計

- JSON形式が壊れていた場合：最大3回まで再試行
- 関連ドキュメントが見つからない場合：確認先候補を案内
- 信頼度が低い場合：不確実であることを明示して回答
- 無効化された文書や旧版のみが参照された場合：警告を付与して回答
- 権限外のドキュメントが参照されないようにフィルタリング
- セッションが1時間経過した場合：自動終了して会話履歴を削除

## 対象外（スコープ外）

- 画面UI（フロントエンド）
- SlackやTeamsへの直接連携

- 音声での質問対応
- ドキュメントの自動改訂・バージョン管理
