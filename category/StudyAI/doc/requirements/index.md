## システム一覧（規模の小さい順）

ここで重要なのは題材名そのものではなく、そのシステムでAIに何の機能を持たせるかです。各Systemは、その機能を学ぶための題材として並べている。

### 基礎フェーズ（System 01〜04）
プロンプト設計・出力制御・RAGの基礎を体験する。エージェントは使わない。

| No | ファイル | システム名 | 主な習得項目 | 使用するAIの機能 |
|----|---------|-----------|------------|---|
| 01 | `system01_requirements.md` | 請求書・領収書 データ抽出システム | プロンプト設計・Few-shot・VLM・JSON出力固定・Pydantic | 文書種別判定、項目抽出、明細抽出、信頼度付与 |
| 02 | `system02_requirements.md` | 契約書・文書 リスク審査システム | 長文チャンキング・コンテキストウィンドウ制約 | 文書種別判定、リスク検出、修正提案、サマリー生成 |
| 03 | `system03_requirements.md` | プロジェクト文書 自然言語Q&Aシステム | RAG・埋め込みモデル・pgvector・LlamaIndex・ハイブリッド検索・メモリ（短期）・アクセス制御 | 質問応答、根拠検索、回答生成 |
| 04 | `system04_requirements.md` | 商品・サービス レビュー分析＆インサイト抽出システム | バッチ処理・非同期処理・大量データ分析 | 感情分析、トピック抽出、インサイト生成、比較分析 |

## 推奨学習順序

```
【基礎】
System 01 → 02
（プロンプト設計・出力制御の基礎を固める）
    ↓
System 03
（RAG・埋め込み・pgvector・ハイブリッド検索・メモリ・アクセス制御）
    ↓
System 04
（バッチ処理・非同期処理・大量データ分析）

【応用】
System 05 → 06 → 07
（RAGを本格活用。メモリ・アクセス制御・マルチモーダル）

【エージェント】
System 08 → 09
（シングルエージェント・LangGraph・Web検索ツール）
    ↓
System 10 → 11
（MCP・ファイルシステム操作・Human-in-the-loop）
    ↓
System 12
（マルチエージェント・オーケストレーター）

【発展】
System 13 → 14 → 15 → 16
（応用・専門領域）
```

## 技術スタック共通事項

全システム共通で使用する技術。

| 用途 | 技術 |
|------|------|
| APIサーバー | FastAPI |
| LLM | Qwen3-27B（Q4量子化）/ LM Studio経由（完全ローカル） |
| VLM | Qwen3-VL-32B / LM Studio経由 |
| 埋め込みモデル | nomic-embed-text / LM Studio経由 |
| 商用API代替 | `AI_PROVIDER=commercial` または `AI_PROVIDER=custom` で OpenAI互換APIに切り替え |
| ベクトルDB | pgvector（PostgreSQL拡張） |
| DB | PostgreSQL |
| ORM | SQLAlchemy |
| 出力バリデーション | Pydantic |
| トレース・ログ | MLflow |
| 音声文字起こし | faster-whisper（ローカル） |
| エージェントフレームワーク | LangGraph / LangChain |
| RAGフレームワーク | LlamaIndex |
| ファイルシステム操作 | MCP filesystem サーバー |
| GPU環境 | RTX3090（VRAM 24GB）/ Windows 11 |

## スコープ外（今後の課題）

| 項目 | 理由 |
|------|------|
| ファインチューニング・LoRA | コスト・専門性が高く別プロジェクトとして扱う |
| 機械学習（物体検知・画像分類） | AIシステム開発とは別の専門領域 |
