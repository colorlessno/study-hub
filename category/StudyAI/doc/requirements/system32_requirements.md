# System 32 要件定義

## RAG評価セット

### 目的

同じ評価セットとRAG設定を使って検索結果と生成回答を繰り返し評価し、変更前後の差を追えるようにする。単一の正答率だけでなく、検索に失敗したケースと、正しい根拠を取得できた後の回答生成に失敗したケースを分けて記録する。

### 利用者

- RAGの検索処理と回答生成を分けて評価したい学習者
- RAGの変更による改善と悪化を、固定した条件で比較したい開発者

### 入力

- 評価セット名と実行名
- 検索処理、回答生成、Promptの各バージョンと確認する検索件数
- ケース番号、質問、期待する回答、正解文書番号
- 各ケースで得られた検索結果と生成回答
- 観察結果、設計判断、残る注意点

### 必要な機能

- 1件以上100件以下の評価ケースを一括実行できる。
- 評価ケースごとに、正解文書が上位検索結果に含まれるか判定できる。
- 評価ケースごとに、生成回答が期待する回答を満たすか判定できる。
- 検索失敗、生成失敗、成功を区別して表示できる。
- 検索成功率、生成成功率、回答評価の平均、失敗件数を集計できる。
- 同じ評価セットの直前の実行と指標を比較し、悪化した指標を表示できる。
- 入力、ケース別結果、集計結果、比較結果、学習メモをJSONファイルへ保存できる。
- 保存した実行履歴を再起動後に読み込める。

### 入力の制約

- 評価セット名、実行名、RAG設定は省略できない。
- ケース番号は評価セット内で重複できない。
- 質問、期待する回答、正解文書番号は省略できない。
- 確認する検索件数は1以上の整数とする。

### 受入条件

- 既定の3ケースを実行すると、成功、検索失敗、生成失敗が1件ずつ表示される。
- 既定の3ケースの検索成功率と生成成功率が、それぞれ0.667と表示される。
- 同じ評価セットを再実行すると、直前の実行名、指標差分、悪化した指標が表示される。
- 実行履歴が `data/ai_learning/system32_runs.json` に保存され、再起動後も参照できる。
- 不正な評価セットやRAG設定は、実行せず入力エラーとして返される。

### 対象外

- 本番の検索エンジンや外部LLMを必須とする評価
- 人間による回答品質の主観評価
- 異なる評価セットを同一条件として比較する処理
