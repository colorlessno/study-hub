# System 16 要件定義

## このテーマでできるようになること

- 要件定義で扱う「AIの役割範囲の定義・RAG要件（過去案件実績）・ガードレール要件」を説明できる
- 基本設計で扱う「埋め込みモデル・pgvector・パイプライン設計（要件書とスキルシートの処理）」を説明できる
- 詳細設計で扱う「複数ドキュメント比較設計・スコアリング設計・JSON出力固定・Pydantic」を説明できる
- 実装で扱う「LLM API実装・スキルシートパース実装（Excel）・RAGパイプライン実装・pgvector・一件ずつの順次処理・MLflowトレース」を説明できる
- 検証で扱う「ガードレール検証（差別的評価除外・個人情報マスキング・Excel解析精度）」を説明できる
- FastAPI・PostgreSQL・SQLAlchemy・Pythonを横断的に使う構成を説明できる

## 案件マッチングシステム（プロジェクト・スキルシート）

---

## システム概要

プロジェクト要件書とスキルシートを読み込み、LLMがマッチ度・理由・懸念点を分析して返すシステム。案件に対する要員候補の比較工数を削減し、アサイン判断の材料を短時間で揃える。

利用シーンによって入力内容が異なる。

| 利用シーン | 要件側 | 候補側 |
|-----------|--------|--------|
| 新規案件アサイン | プロジェクト要件書 | スキルシート |
| 既存案件の増員判断 | 作業内容・必要スキル一覧 | スキルシート |
| 個人の案件適合確認 | プロジェクト概要・必要条件 | 自分のスキルシート |

---

## 現状の課題

- プロジェクト要件とスキルシートの照合作業に時間がかかる
- 担当者の経験によって評価品質にばらつきが出る
- 複数候補を短時間で比較しにくい
- スキルシートの表形式データを読み取って要件と照合する手作業が煩雑
- スキル名は一致していても、工程経験や役割の差を見落としやすい
- 懸念点・不足点を整理しないままアサイン判断に進んでしまう

---

## 対象ユーザー

- プロジェクトマネージャー・PMO
- 要員アサイン調整担当者
- 個人（自分のスキルシートと案件要件の適合確認用途）

## 機能要件

### 1. ドキュメント入力機能

**要件側（プロジェクト要件書）の入力形式**
- PDF・Word（.docx）・テキスト（.txt）・Markdown（.md）
- テキスト直接入力
- ファイルサイズ上限：10MB

**候補側（スキルシート）の入力形式**

| 入力種別 | 形式 | 主な利用シーン |
|---------|------|--------------|
| スキルシート | Excel（.xlsx） | 新規案件アサイン・増員判断 |
| 構造化済みスキルデータ | JSON | 外部前処理済みデータの再利用 |

---

### 2. スキルシート解析機能

スキルシートに含まれる情報を構造化して分析に使いやすい形に変換する。

> 📝 **スキルシートは Excel（.xlsx）形式を前提**とする。本要件定義では `.xlsx` を標準入力形式として扱う。

**スキルシートに含まれる情報項目**

プロジェクト単位で以下の情報が記録されていることを想定する。

| 項目 | 説明 |
|------|------|
| No | 案件番号 |
| 期間 | 開始年月〜終了年月 |
| 業務概要 | プロジェクト名・概要 |
| 業務詳細 | 役割・担当内容・規模（要員数）・担当範囲 |
| OS | 使用OS |
| DB | 使用DB |
| 言語 | 使用プログラミング言語 |
| ツール | 使用ツール・フレームワーク・インフラ等 |
| 工程 | 担当した工程（要件定義・基本設計・詳細設計・製造・単体試験・結合試験・総合試験・保守運用等） |

**解析時の処理**
- 期間から在籍期間（月数）を自動計算
- 言語・ツール・DB等を案件横断で集計してスキルサマリーを生成
- 担当工程を一覧化
- 業務詳細から役割・規模・担当範囲を抽出
- スキル名・ツール名は同義語辞書で正規化する（例：`JS`→`JavaScript`、`Lambda`→`AWS Lambda`）

**対応レイアウト方針**
- 標準レイアウトA: 見出し行 + 案件一覧表
- 標準レイアウトB: シート分割（職務経歴 / スキル一覧 / 資格）
- 非標準レイアウトは `review_required` を付けて人確認対象にする

**スキルサマリーの生成例**
```json
{
  "total_projects": 6,
  "total_experience_years": 10.5,
  "skills": {
    "languages": [
      {"name": "C言語", "projects": 3, "years": 5.2},
      {"name": "Python", "projects": 2, "years": 2.0},
      {"name": "SQL", "projects": 4, "years": 7.0}
    ],
    "databases": ["PostgreSQL", "Oracle", "DB2", "SQLServer"],
    "os": ["Linux", "Windows", "MacOS"],
    "tools": ["AWS", "Git", "Visual Studio", "SVN"]
  },
  "processes": {
    "要件定義": 2,
    "基本設計": 4,
    "詳細設計": 5,
    "製造": 4,
    "単体試験": 3,
    "結合試験": 2,
    "保守・運用": 2
  },
  "roles": ["SE", "プログラマー", "チームリーダー"],
  "domains": ["金融", "制御システム", "業務システム"]
}
```

### 3. 要件構造化機能（LLM）

プロジェクト要件書をLLMが構造化する。

**抽出する項目**

| 項目 | 説明 |
|------|------|
| プロジェクト概要 | 背景・目的・規模・期間 |
| 必須スキル | 絶対に必要なスキル・経験・経験年数 |
| 歓迎スキル | あると望ましいスキル・経験 |
| 必要な工程経験 | 担当してほしい工程 |
| 求める役割 | SE・PL・PG・テスター等 |
| 必要な業務ドメイン経験 | 金融・製造・流通等の業界経験 |
| 制約条件 | 勤務形態・期間・参画時期・必須資格など |

---

### 4. マッチング分析機能（LLM）

構造化された要件とスキルシート情報をLLMが比較分析してスコアリングする。

**マッチングスコア（100点満点）**

| 評価軸 | 重み | 説明 |
|--------|------|------|
| 必要技術スキル適合度 | 35% | 言語・DB・ツールの一致度 |
| 工程経験適合度 | 25% | 必要な工程の経験有無 |
| 業務ドメイン適合度 | 20% | 業界・業務領域の近さ |
| 役割・経験年数適合度 | 20% | 求める役割・年数との一致度 |

**判定補正ルール**
- 必須スキルの充足率が60%未満の場合、総合レベルは最大でも `B` とする
- 必須工程が未充足の場合、確認事項へ必ず出力する
- 解析信頼度が低い場合は `review_required = true` とし、自動判定で断定しない

**マッチングレベル**

| スコア | レベル | 推奨アクション |
|--------|--------|--------------|
| 80〜100 | S：高適合 | 優先候補として検討 |
| 60〜79 | A：適合 | 候補として検討 |
| 40〜59 | B：部分適合 | 不足点を確認の上で判断 |
| 0〜39 | C：低適合 | 要件との乖離が大きい |

---

### 5. 分析レポート生成機能（LLM）

マッチング結果の詳細レポートを生成する。

| 項目 | 説明 |
|------|------|
| 総合スコア | 100点満点のスコアとレベル |
| スコア内訳 | 評価軸ごとのスコア |
| マッチング理由 | なぜこのスコアになったかの説明 |
| 強み | 要件に対して特に優れている点 |
| 懸念点・ギャップ | 要件と経験の乖離・不足している点 |
| 確認事項 | 面談や確認時に見るべき論点 |
| 総評コメント | アサイン判断の参考コメント |

---

### 6. 一括評価・ランキング機能

1つの要件に対して複数のスキルシートを一括評価してスコア順にランキングする。

- 複数候補を選択順に一件ずつ評価
- スコア順・レベル別のランキング表示
- 候補ごとの強み・懸念点の比較サマリー
- 50件を超える場合も同じ要求内で一件ずつ処理し、全件保存後に結果を返す

---

### 7. 過去案件実績の参照機能（RAG）

過去のアサイン実績・評価結果をRAGで参照し、分析精度を向上させる。

- 過去案件でのアサイン結果
- 参画後の評価メモ
- 成功・失敗パターンのナレッジ
- 類似案件での判断実績

---

### 8. 結果保存・取得機能

- マッチング結果をPostgreSQLに保存する
- 過去の評価結果を取得・比較できる
- 結果をCSV形式でエクスポートできる
- 評価結果には `parse_confidence`、`review_required`、`review_reasons` を保持する

---

## 非機能要件

| 項目 | 要件 |
|------|------|
| 応答時間 | 1件あたり60秒以内 / 一括評価は件数分を順次処理 |
| セキュリティ | 個人情報（氏名・連絡先）はマスキングしてDBに保存 |
| 対応言語 | 日本語・英語 |
| プライバシー | スキルシートの内容は外部に送信しない（完全ローカル） |

## システム構成

```
クライアント（curl / 画面）
        ↓
    FastAPI（APIサーバー）
        ↓
    ┌────────────────────────────────────┐
    │  入力種別に応じた前処理             │
    │  スキルシート（Excel）              │
    │  → openpyxl でパース               │
    │  → セル結合解除・行正規化          │
    │  → スキルサマリー生成              │
    │                                   │
    │  プロジェクト要件書                │
    │  → テキスト抽出 → LLMで構造化     │
    └────────────────────────────────────┘
        ↓
    ┌────────────────────────────────────┐
    │  RAG：過去案件実績検索              │
    │  要件をベクトル化                  │
    │  → pgvectorで類似過去実績を検索   │
    │  → 過去実績をプロンプトに差し込み  │
    └────────────────────────────────────┘
        ↓
    LLM（マッチング分析・スコアリング・レポート生成）
    ※ LM Studioで選択したモデル
        ↓
    出力バリデーション（Pydantic）
    ※ JSON壊れ時は再試行（最大3回）
        ↓
    PostgreSQL（結果保存）
        ↓
    JSONレスポンス返却
```

## プロンプト仕様

### スキルシート構造化プロンプト
```
あなたはITエンジニアのスキルシート分析の専門家AIです。
以下のスキルシートデータを分析し、スキルサマリーを生成してください。

スキルシートデータ（構造化済み）：
{parsed_skillsheet_data}

ルール：
1. 各案件の期間から経験年数を正確に計算すること
2. 同じスキルが複数案件に登場する場合は合算すること
3. 業務詳細から役割・担当内容を正確に抽出すること
4. 担当ドメイン（金融・製造・流通等）を業務内容から推定すること
5. 必ず指定のJSONフォーマットで返すこと
```

### マッチング分析プロンプト
```
あなたは案件アサイン判断を支援する専門家AIです。
以下の要件とスキルシート情報を比較分析し、マッチング結果を生成してください。

要件（構造化済み）：
{structured_requirement}

候補情報（構造化済み）：
{structured_candidate}

過去の類似案件の実績：
{similar_cases}

ルール：
1. スコアは各評価軸を独立して評価すること
2. 強みと懸念点はそれぞれ具体的な根拠（スキル名・年数・工程等）を示すこと
3. 確認事項は面談・確認時に実際に使える形式にすること
4. 過去実績がある場合は総評コメントに反映すること
5. 推測で断言しないこと（「確認できない」「〜と考えられます」を使う）
6. 必ず指定のJSONフォーマットで返すこと
```

## ガードレール設計

- JSON形式が壊れていた場合：最大3回まで再試行
- 個人情報（氏名・メールアドレス・電話番号・住所）はDB保存前にマスキング
- 差別的・不適切な評価基準（年齢・性別・国籍等）が含まれる場合：該当部分を除外して処理し警告を付与
- 一括評価は件数にかかわらず、候補ファイルを一件ずつ順番に処理する
- スキルシートのパース失敗時：エラー箇所をログに記録しスキップして処理継続
