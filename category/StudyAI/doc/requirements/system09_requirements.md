- 要件定義で扱う「AIの役割範囲・ガードレール要件」を説明できる
- 基本設計で扱う「**マルチステップエージェント設計**・**ツール設計（Web検索・web_fetch）**・LangGraph・LangChain」を説明できる
- 詳細設計で扱う「**エージェントループ詳細設計（調査計画→検索→評価→追加検索）**・**停止条件**・**状態管理**」を説明できる
- 実装で扱う「**エージェントループ実装（LangGraph）**・**Web検索ツール実装**・**web_fetch実装**・MLflowトレース」を説明できる
- 検証で扱う「ガードレール検証（検索上限・タイムアウト・不適切コンテンツ除外）」を説明できる
- FastAPI・PostgreSQL・SQLAlchemy・Pythonを横断的に使う構成を説明できる

## 市場競合調査 エージェント

---

## システム概要

調査対象（企業名・業界・テーマ）を指定すると、エージェントがWeb検索で情報収集・分析・整形を自動で行い、競合分析・市場調査レポートを生成するシステム。営業・企画部門の調査業務を代替し、意思決定に必要な情報を短時間で提供する。

---

## 現状の課題

- 競合調査・市場調査に多大な時間と工数がかかる
- 調査担当者によって調査の深さ・切り口にばらつきがある
- 最新情報の収集が追いつかず、古い情報で判断してしまう
- 調査結果のレポート作成に時間がかかり、本来の分析に時間を割けない
- 複数の競合を横断的に比較する作業が煩雑

---

## 対象ユーザー

- 営業担当者（商談前の競合調査）
- マーケティング担当者（市場動向・競合分析）
- 経営企画担当者（新規事業・市場参入調査）
- コンサルタント（クライアント向けリサーチ）

---

## 機能要件

### 1. 調査依頼入力機能
調査対象・調査内容を入力する。

**入力項目**

| 項目 | 説明 | 必須 |
|------|------|------|
| 調査タイプ | 競合調査・市場調査・業界調査・企業調査 | ✅ |
| 調査対象 | 企業名・業界名・テーマ | ✅ |
| 調査目的 | なぜ調査するのか | 任意 |
| 比較対象 | 自社情報・比較する競合名 | 任意 |
| 調査の深さ | 概要・標準・詳細 | 任意 |
| 重点項目 | 特に詳しく調べたい項目 | 任意 |

**調査タイプ別の調査項目**

**競合調査**
- 企業概要（設立・資本金・従業員数・拠点）
- 事業内容・主要製品・サービス
- 価格帯・料金体系
- 強み・弱み
- 最新ニュース・動向
- 公開資料（技術スタック・組織規模の参考）
- 顧客レビュー・評判

**市場調査**
- 市場規模・成長率
- 主要プレイヤーとシェア
- 市場トレンド・技術動向
- 規制・法律の動向
- 参入障壁・成功要因
- 顧客ニーズ・課題

**業界調査**
- 業界構造・バリューチェーン
- 主要企業一覧
- 業界トレンド
- 課題・リスク

### 2. Web検索＆情報収集機能（エージェント）
エージェントがWeb検索を使って必要な情報を自律的に収集する。

**エージェントの動作フロー**
```
調査依頼受付
    ↓
調査計画の立案（LLM）
（何をどの順で調べるか）
    ↓
検索クエリを生成
    ↓
Web検索実行
    ↓
情報の評価・取捨選択（LLM）
    ↓
追加調査が必要か判断
    ↓（必要なら追加検索）
十分な情報が集まったら分析・レポート生成へ
```

**使用ツール**
- `web_search`：キーワード検索
- `web_fetch`：特定URLのページ内容取得
- `summarize`：取得した情報の要約

**停止条件**
- 調査計画のすべての項目が収集完了した場合
- 検索回数が上限（20回）に達した場合
- タイムアウト（10分）に達した場合

### 3. レポート生成機能（LLM）
収集した情報をもとに、LLMが構造化されたレポートを生成する。

**レポートの構成**

| セクション | 内容 |
|-----------|------|
| エグゼクティブサマリー | 調査結果の要約（3〜5行） |
| 調査概要 | 調査対象・目的・実施日 |
| 主要発見事項 | 重要なインサイトのリスト |
| 詳細分析 | 調査タイプ別の詳細情報 |
| 比較分析 | 複数対象の横断比較（表形式） |
| SWOT分析 | 強み・弱み・機会・脅威（競合調査時） |
| トレンド・動向 | 最新の動向・将来予測 |
| 情報ソース | 参照したURL・情報源 |
| 調査の限界 | 情報の信頼性・網羅性の注記 |

**出力形式**
- JSON（APIレスポンス）
- Markdown（人が読みやすい形式）
- 将来拡張：PDF・PowerPoint形式

### 4. 比較分析機能
複数の競合・市場を横断的に比較する。

- 最大5社・5市場の同時比較
- 比較項目を指定して表形式で出力
- 自社情報を入力した場合、自社との比較を含める

### 5. 結果保存・再利用機能
- レポートをPostgreSQLに保存する
- 過去のレポートを取得・参照できる
- 同一対象の過去レポートと比較できる（変化の追跡）
- レポートをMarkdown形式でエクスポートできる

---

## 非機能要件

| 項目 | 要件 |
|------|------|
| 応答時間 | Web検索込みで10分以内 |
| Web検索 | 1回の調査あたり最大20回まで |
| 対応言語 | 日本語・英語 |
| 情報の鮮度 | Web検索で取得する最新情報を優先 |

## システム構成

```
クライアント（curl / 画面）
        ↓
    FastAPI（APIサーバー）
        ↓
    調査依頼受付・前処理
        ↓
    ┌──────────────────────────────────────────┐
    │  LangGraph逐次ワークフロー                  │
    │                                          │
    │  State：{request, plan, queries,         │
    │           query_log, raw_sources,         │
    │           accepted_sources, search_count, │
    │           report_payload}                 │
    │                                          │
    │  ① 調査計画立案（LLM）                   │
    │  ② 検索クエリ生成（LLM）                 │
    │  ③ クエリ単位のWeb検索（最大20件）       │
    │  ④ 検索結果単位のページ取得              │
    │  ⑤ URL重複・本文長による情報評価         │
    │  ⑥ 深度別の採用上限で収集終了            │
    └──────────────────────────────────────────┘
        ↓
    LLM（レポート生成・SWOT分析・比較表作成）
    ※ Qwen3-27B / LM Studio
        ↓
    出力バリデーション（Pydantic）
        ↓
    PostgreSQL（レポート保存）
        ↓
    JSON / Markdown 返却
```

### GET /reports
過去のレポート一覧を取得する。

**クエリパラメータ**
```
research_type: 調査タイプ
target:        調査対象名（部分一致）
from_date:     開始日
to_date:       終了日
```

### GET /reports/{report_id}
レポートの詳細を取得する。

### GET /reports/{report_id}/export
レポートをMarkdown形式でエクスポートする。

## プロンプト仕様

### 調査計画立案プロンプト
```
あなたは市場調査・競合分析の専門家AIです。
以下の調査依頼に対して、効果的な調査計画を立案してください。

調査タイプ：{research_type}
調査対象：{targets}
調査目的：{purpose}
重点項目：{focus_areas}
調査の深さ：{depth}

ルール：
1. 調査項目を優先度順にリストアップすること
2. 各項目に対する検索クエリ案を提示すること
3. 必ず指定のJSONフォーマットで返すこと
```

### レポート生成プロンプト
```
あなたは市場調査・競合分析の専門家AIです。
以下の収集情報をもとに、構造化された調査レポートを生成してください。

調査タイプ：{research_type}
調査対象：{targets}
調査目的：{purpose}

収集情報：
{search_results}

ルール：
1. 収集した情報のみを根拠にすること
2. 推測・憶測は「〜と推測されます」と明示すること
3. 情報ソースのURLを必ず記載すること
4. 情報の限界・不確実性を必ず明示すること
5. エグゼクティブサマリーは経営層が読むことを想定して簡潔にすること
6. 必ず指定のJSONフォーマットで返すこと
```

## ガードレール設計

- JSON形式が壊れていた場合：最大3回まで再試行
- Web検索が20回を超えた場合：強制終了して収集済み情報でレポート生成
- タイムアウト（10分）に達した場合：収集済み情報でレポートを生成して返す
- 信頼性の低いソース（個人ブログ等）からの情報は注記付きで扱う
- 不適切なコンテンツが検索結果に含まれる場合：除外して処理
