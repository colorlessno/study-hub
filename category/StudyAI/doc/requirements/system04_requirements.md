## 商品・サービス レビュー分析＆インサイト抽出システム

---

## システム概要

ECサイトや口コミサイトのレビューテキストを収集・入力すると、LLMがポジティブ・ネガティブの分類、頻出課題の抽出、改善提案までを自動生成するシステム。大量のレビューから人手では気づきにくいインサイトを効率的に抽出し、商品改善・マーケティング施策に活用する。

---

## 現状の課題

- レビューが大量にあり、全件を人手で読むのが困難
- 感覚的な読み取りではなく、定量的な傾向把握がしたい
- ネガティブレビューの中に埋もれている具体的な改善ヒントを見逃している
- 競合商品のレビューと自社商品を比較して差異を把握したい

---

## 対象ユーザー

- 商品企画・開発担当者
- マーケティング担当者
- ECサイト運営者
- カスタマーサポート責任者

## 機能要件

### 1. レビューデータ入力機能
以下の2形式に対応する。

**ファイルアップロード**
- 対応形式：CSV・JSON・テキスト（.txt）
- CSVの必須カラム：レビューテキスト
- CSVのオプションカラム：評価スコア・投稿日・投稿者属性・商品名
- 最大件数：1回あたり10,000件

**テキスト直接入力**
- レビューテキストを改行区切りで直接入力
- 最大文字数：100,000文字

### 2. 感情分析機能
各レビューに対して以下を付与する。

| 分析項目 | 説明 |
|---------|------|
| 感情分類 | ポジティブ / ネガティブ / ニュートラル |
| 感情スコア | -1.0（最もネガティブ）〜 1.0（最もポジティブ） |
| 感情の強度 | 強い / 普通 / 弱い |

### 3. トピック抽出機能
レビュー全体から頻出トピックを自動抽出する。

**抽出対象トピック例**
- 品質・耐久性
- 価格・コスパ
- デザイン・見た目
- 使いやすさ・操作性
- 配送・梱包
- カスタマーサポート
- サイズ・フィット感

LLMがレビュー内容に応じてトピックを動的に生成する（固定カテゴリではない）。

### 4. インサイト生成機能
LLMがレビュー全体を分析して以下を生成する。

| 生成項目 | 説明 |
|---------|------|
| ポジティブサマリー | 高評価の主な理由・強みのまとめ |
| ネガティブサマリー | 低評価の主な理由・課題のまとめ |
| 頻出キーワード | ポジティブ・ネガティブ別の頻出語句 |
| 改善提案 | ネガティブレビューから導出した具体的改善案（優先度付き） |
| 特徴的なレビュー | 代表的なポジティブ・ネガティブレビューの抜粋（各3件） |
| トレンド分析 | 投稿日が含まれる場合、時系列での感情変化 |

### 5. 比較分析機能
複数の商品・サービスのレビューを同時に分析し、比較レポートを生成する。

- 自社商品 vs 競合商品の比較
- 旧バージョン vs 新バージョンの比較
- 地域・属性別の比較

### 6. 結果保存・取得機能
- 分析結果をPostgreSQLに保存する
- 過去の分析結果を取得・比較できる
- 分析結果をJSON・CSV形式でエクスポートできる

---

## 非機能要件

| 項目 | 要件 |
|------|------|
| 応答時間 | 100件あたり60秒以内 |
| 大量データ処理 | 1,000件超の場合はバッチ処理（非同期）で対応 |
| 対応言語 | 日本語・英語 |

---

## システム構成

```
クライアント（curl / 画面）
        ↓
    FastAPI（APIサーバー）
        ↓
    レビューデータ受付・前処理
    （CSV/JSONパース・クリーニング）
        ↓
    バッチ分割処理
    （50件ずつチャンキング）
        ↓
    LLM（感情分析・トピック抽出）
    ※ Qwen3-27B / LM Studio
        ↓
    出力バリデーション（Pydantic）
        ↓
    LLM（インサイト・改善提案生成）
    ※ 全レビューのサマリーを元に生成
        ↓
    PostgreSQL（分析結果保存）
        ↓
    JSONレスポンス返却
```

CSVファイルをアップロードして分析する。

### POST /compare
複数商品のレビューを比較分析する。

**リクエスト（JSON）**
```json
{
  "products": [
    {
      "product_name": "自社商品A",
```

### GET /analyses

### GET /analyses/{analysis_id}

## データモデル

### analysesテーブル
```sql
CREATE TABLE analyses (
    id               SERIAL PRIMARY KEY,
    product_name     VARCHAR(255),
    total_reviews    INTEGER,
    sentiment_summary JSONB,
    topics           JSONB,
    insights         JSONB,
    created_at       TIMESTAMP DEFAULT NOW()
);
```

### review_resultsテーブル
```sql
CREATE TABLE review_results (
    id              SERIAL PRIMARY KEY,
    analysis_id     INTEGER REFERENCES analyses(id),
    review_text     TEXT,
    review_score    NUMERIC(2,1),
    review_date     DATE,
    sentiment       VARCHAR(20),    -- positive・negative・neutral
    sentiment_score NUMERIC(3,2),
    intensity       VARCHAR(10),    -- 強い・普通・弱い
    topics          JSONB
);
```

## プロンプト仕様

### 感情分析プロンプト（バッチ処理用）
```
あなたはレビュー分析の専門家AIです。
以下のレビューリストを分析し、各レビューの感情分類・スコア・トピックを
指定のJSONフォーマットで返してください。

ルール：
1. 感情分類はpositive / negative / neutralの3種類
2. 感情スコアは-1.0〜1.0の数値で返すこと
3. トピックはレビュー内容から動的に判定すること
4. 必ず指定のJSONフォーマットで返すこと
5. レビューが日本語・英語混在でも対応すること
```

### インサイト生成プロンプト
```
あなたはマーケティングアナリストAIです。
以下のレビュー分析結果をもとに、商品改善に役立つインサイトと
具体的な改善提案を生成してください。

ルール：
1. 改善提案は具体的かつ実行可能な内容にすること
2. 改善提案には優先度（高・中・低）を付けること
3. 推測ではなくレビューの根拠に基づいて生成すること
4. 必ず指定のJSONフォーマットで返すこと
```

## ガードレール設計

- JSON形式が壊れていた場合：最大3回まで再試行
- 1,000件超の場合：非同期バッチ処理でジョブIDを返し、完了後に結果取得
- レビュー件数が0件の場合：即時エラーレスポンス
- 処理時間が上限を超えた場合：タイムアウトエラーとしてログに記録
