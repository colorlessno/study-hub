# system35 Prompt A/B比較

同じ実行条件と評価ケースで記録したA/B回答を採点し、Prompt変更による改善と悪化を区別するテーマです。比較結果と採用理由はJSONファイルへ保存されます。

## このテーマでできるようになること

- Prompt以外の実行条件を固定してA/Bを比較できる
- 正確性、根拠性、網羅性、簡潔性を別々に確認できる
- Prompt別の平均点とケース別の点差を対応させて読める
- 改善したケース、悪化したケース、同点のケースを区別できる
- 採用または保留の判断と、その理由、残る注意点を記録できる
- 比較結果が保存され、再表示できることを確認できる

## 最初に取り組むこと

1. StudyHubでsystem35を開く。
2. 「改善と悪化の両方を比較」を実行し、Prompt Bの平均点が高い一方で、悪化したケースも残ることを確認する。
3. 「Prompt Aが優れるケース」を実行し、誤った期限が正確性と勝敗へ反映されることを確認する。
4. 「同点で採用を保留」を実行し、同点の場合は点数上の推奨が「保留」になることを確認する。
5. 実行履歴から結果を再表示し、入力と比較結果が保存されていることを確認する。

## 画面で確認すること

- 実験名、A/BのPrompt、固定した実行条件、採点の重みが表示される
- Promptごとの平均点と四観点の点数が表示される
- 各ケースのA/B回答、点数、点差、改善・悪化・同点の判定が表示される
- 不足した必要語、不足した根拠語、検出した禁止語が採点理由として表示される
- 記録した採用判断と点数上の推奨が対応している
- JSONへの保存状態が表示される

## 入力項目の関係

`fixed_conditions` は比較中に変えないモデル、温度、最大出力トークン数、評価データ版です。`evaluation_cases` には質問、必要語、根拠語、禁止語、文字数上限、A/Bの記録済み回答を入れます。`scoring_weights` は四観点の重みで、合計を1.0にします。

記録済み回答を使うことで、外部AIが利用できない場合も同じ比較を再現できます。実際のモデルでA/B回答を生成した場合は、同じ条件で取得した回答を `output_a` と `output_b` へ記録して比較します。

## この比較で確認できる範囲

禁止語、根拠語、必要語、文字数上限を決めた規則で評価します。同じ入力から同じ結果を再現できますが、回答の意味上の妥当性を自動確定するものではありません。平均点だけで採用せず、悪化したケース、回答原文、採点根拠、残る注意点を併せて確認します。

## うまく動かないとき

- `prompt_a` と `prompt_b` が空でないか確認する
- `fixed_conditions` にモデル、温度、最大出力トークン数、評価データ版があるか確認する
- `scoring_weights` の四観点の合計が1.0か確認する
- `evaluation_cases` に必要語、根拠語、A/B回答、文字数上限があるか確認する
- `adoption_record` にA、B、保留のいずれかと判断理由があるか確認する
