# system24 複数モデルの比較

同じ指示と評価基準で複数モデルへ実際に問い合わせ、回答品質、応答時間、推定費用、運用条件を比較して採用理由と不採用理由を記録するテーマです。

## このテーマでできるようになること

- 同じ指示とTemperatureで複数モデルの回答を取得できる
- 固定した必須語句と回答長から、同じ規則で品質点を比較できる
- 実測応答時間、トークン数、設定単価から求めた推定費用を比較できる
- 品質、応答時間、費用、総合評価の優先条件を変えて採用候補を確認できる
- 採用理由、不採用理由、運用条件、残る注意点を記録できる

## 最初に取り組むこと

1. 「入力例」から「実モデルを比較」を選ぶ。
2. `models`の`model`を、OpenAI互換APIから指定できる2件以上のモデル名へ変更する。
3. `evaluation_rubric.required_terms`へ、回答に必要な語句を入力する。
4. 各モデルで同じ値になる`prompt`と`temperature`を確認する。
5. 「実行」を押し、各モデルの回答、品質点、応答時間、トークン数、推定費用を比較する。
6. `priority`を変えて実行し、採用候補と不採用理由の変化を確認する。
7. 観察結果、採用判断、残る注意点を`learning_note`へ記録する。

## 実行前の準備

既定の`model`モードは、StudyAIバックエンドから設定済みOpenAI互換APIの`/chat/completions`へ、指定したモデル名を入力順に一件ずつ送ります。直前の応答完了後に次のモデルへ進み、同時送信しません。LM Studioを使う場合は、比較するモデルをAPIから指定できる状態にしてください。モデルが一つしか使えない場合は、比較対象を準備してから実行します。

外部環境を使わず画面と比較手順だけを確認するときは、「比較手順を確認（明示的なモック）」を選びます。実モデルの通信失敗時にモックへ自動で切り替わることはありません。

## 画面で確認すること

- 比較方法が「実モデルへの通信」になっている
- 指示、Temperature、評価基準が全モデルで共通になっている
- 指定モデル名と実際に応答したモデル名が表示される
- 各回答に含まれる必須語句、網羅率、回答長、品質点を確認できる
- モデルごとの実測応答時間と入出力トークン数を確認できる
- 設定単価がある場合は推定費用、ローカルモデルを0とした場合は0が表示される
- 採用候補だけでなく、各候補の不採用理由も表示される
- 学習メモと比較結果がJSONへ保存されたことを確認できる

## 評価点の読み方

品質点は、必須語句の網羅率と、指定した回答長以内に収まったかを固定した重みで合成した教材用の点数です。人手による正確性、根拠、表現、業務適合性の評価を置き換えるものではありません。同じ規則で複数モデルを横並びにするために使います。

総合点は品質60％、応答時間20％、推定費用20％の教材用計算です。実際の選定では、端末要件、同時実行数、ライセンス、データ持出し可否、保守性も判断に加えます。

## 保存

比較結果、入力条件、採用・不採用理由、学習メモは、StudyAIバックエンドが`data/ai_learning/system24_runs.json`へ最新20件を保存し、起動時に読み戻します。画面内だけに保存する仕様ではありません。

## うまく動かないとき

- `models`が2件以上5件以下で、`id`と`model`が重複していないか確認する。
- 指定した各モデルをOpenAI互換APIから利用できるか確認する。
- `required_terms`が空でないか確認する。
- `coverage_weight`と`conciseness_weight`の合計が1になっているか確認する。
- 実モデルのエラーを確認する場合は`mode`を`model`のままにし、モックへ変更して隠さない。
