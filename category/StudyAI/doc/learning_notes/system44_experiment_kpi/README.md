# system44 AI KPI・実験評価ダッシュボード

基準側と変更側の事業KPI、AI品質、コスト、応答時間、失敗内容を比較し、改善内容と意思決定理由を記録するテーマです。

## このテーマでできるようになること

- 基準側と変更側の成果率を同じ条件で比較できる
- 成果率の差と相対改善率を区別できる
- AI品質、成果単価、応答時間、苦情率を同じ実験結果として確認できる
- 失敗を分類し、次の改善候補へ結び付けられる
- 自動判断と人間の意思決定を分けて記録できる

## 最初に取り組むこと

1. StudyHubでsystem44を開く。
2. 既定値で実行し、成果率、AI品質、成果単価、応答時間、失敗分類、自動判断を確認する。
3. variant_results、ai_quality_metrics、cost_metricsを一つずつ変更し、判断条件と改善候補の変化を確認する。
4. failure_casesの分類と件数を変更し、失敗分類から改善候補が作られることを確認する。
5. human_review_resultをdecidedに変更し、確認者、判断、理由、改善内容、次の実験が履歴へ保存されることを確認する。
6. バックエンドを再起動してsystem44を開き直し、意思決定を含む直前の実行履歴が復元されることを確認する。

## 画面で確認すること

- 基準側と変更側の人数、成果数、成果率が表示される
- 成果率の差と相対改善率が別々に表示される
- AI品質と最低品質、成果単価と上限を比較できる
- 応答時間と苦情率をそれぞれの上限と比較できる
- 失敗分類と改善候補を確認できる
- 自動判断と人間の判断、判断理由、改善内容、次の実験を区別できる
- decidedまたはarchivedの意思決定が実行履歴と監査記録に保存される
- JSON保存の成否、保存上限、保存件数を確認できる
- 再起動後に直近20件の実行履歴が新しい順で復元される

## 処理のつながり

画面の実験結果、AI品質、コスト、安全側の指標、失敗事例、人間の確認結果をAPIへ送ります。APIは事業KPI、品質、成果単価、条件違反を計算し、失敗を分類して改善候補を作ります。実験結果、評価指標、監査記録、確定した意思決定は `data/enterprise_ai/system44_runs.json` へUTF-8で保存し、新しい順の直近20件を再起動後も復元します。

## この実験で確認できる範囲

教材用の集計値を使った評価です。統計的有意差の検定、利用者の無作為割当、実サービスへの展開操作は行いません。実行履歴と監査記録には、この教材内で確定した評価と意思決定を保存します。

## うまく動かないとき

- variant_resultsにcontrolとvariantがあるか確認する
- users、conversions、accuracy、コスト、失敗件数が数値になっているか確認する
- decision_rulesの人数、改善率、品質、成果単価、応答時間、苦情率の条件を確認する
- 意思決定を保存するときはhuman_review_resultのstatus、reviewer、decisionを確認する
- 保存状態が失敗の場合は、`data/enterprise_ai` フォルダへ書き込めるか確認する
- 既定値へ戻してから再実行する
