# system10 構成管理補助・文書所在検索

教材用フォルダをMCP filesystemサーバー経由で読み取って文書の内容と保存場所を索引へ登録し、検索、構成マップ、重複候補、履歴、レポートを確認するテーマです。

## このテーマでできるようになること

- 全件スキャンと差分スキャンの結果を比較できる
- キーワード検索、意味検索、複合検索の違いを確認できる
- 文書名、保存場所、文書種類、要約、最新版かどうかを検索結果から確認できる
- 構成マップ、重複候補、スキャン履歴、構成管理レポートを確認できる

## 最初に取り組むこと

1. 「教材用入力を設定」を押し、`/mnt/scan/project`を全件スキャンする。
2. 「検索・構成確認画面」で「基本設計」をキーワード検索と複合検索の両方で検索する。
3. 構成マップを取得し、`requirements`、`design`、`archive`、`meeting`の配置を確認する。
4. 重複候補を取得し、内容が同じ設計文書2件と整理の基準にする文書を確認する。
5. 差分スキャンを実行し、「レポート・履歴画面」で履歴と構成管理レポートを確認する。

## 画面で確認すること

- 読み取れる範囲が`/mnt/scan/project`配下に制限されている
- MCPセッションで初期化とツール確認を行い、一覧、本文、メタ情報を一つずつ順番に取得する
- 全件スキャンでは索引から消えた文書を削除扱いにし、差分スキャンでは既存文書を無効化しない
- 設定済みLLMまたは教材内のローカル規則で文書種類と要約を作成する
- 設定済み埋め込みモデルまたは教材内のローカルベクトルで意味検索用の索引を作成する
- 検索結果に文書名、保存場所、文書種類、最新版、関連度、要約、重複候補が表示される
- スキャン履歴に対象件数、新規、更新、削除扱い、重複、処理時間、状態が表示される

## 処理のつながり

画面から送られたフォルダと実行方式を索引作成処理が受け取り、読取専用MCP filesystemサーバーから文書内容とメタ情報を順番に取得します。取得した保存場所、ハッシュ値、文書種類、要約、意味検索用ベクトルをPostgreSQLへ記録し、検索、構成マップ、重複検出、履歴、レポートは同じ索引を利用します。

## うまく動かないとき

- Docker DesktopとStudyAIの共有環境が起動しているか確認する。
- 対象が`/mnt/scan/project`配下か確認する。
- 検索、構成マップ、重複候補、レポートを確認する前にスキャンを完了する。
- LLMまたは埋め込みモデルを利用できない場合は、画面の処理メモにローカル代替処理が表示されているか確認する。
