# system37 取引実行型AIコンシェルジュ

希望条件、候補、本人確認、最終確認を照合し、取引を実行できるか判断するテーマです。

## このテーマでできるようになること

- 条件不足時に追加で確認する内容を特定できる
- 候補の比較と取引の実行可否を分けて確認できる
- 本人確認と最終確認が取引実行を止める条件になることを説明できる

## 最初に取り組むこと

1. StudyHubでsystem37を開く。
2. 既定値で実行し、候補の順位、価格、予算内か、変更可能かを確認する。
3. request_conditionsからrouteを削除して再実行し、追加で確認する内容を確認する。
4. identity_statusをunverifiedへ変更し、取引の状態と注意点を確認する。
5. user_confirmationをfalseへ変更し、最終確認前の実行が止まることを確認する。
6. transaction_requestのactionをchange、cancelへ変更し、それぞれの結果を確認する。
7. 実行履歴を確認し、StudyAIを再起動しても履歴が残ることを確認する。

## 画面で確認すること

- 利用可能な候補だけが価格順に並ぶ
- 予算内かどうかを候補ごとに確認できる
- 必須条件が足りない場合は候補を確定せず、確認内容を表示する
- 本人確認または最終確認が不足すると担当者確認へ移行する
- 実行結果と監査記録が同じ実行番号で残る
- 実行、変更、取消、失敗理由、KPIがJSONへ保存される
- 再起動後も保存済みの直近20件を実行履歴で確認できる

## 処理のつながり

画面の希望条件と候補をAPIへ送り、APIが必須条件、本人確認、最終確認、価格条件を順に確認します。結果には候補順位、実行状態、注意点、監査記録が含まれます。

## この実験で確認できる範囲

教材用のモックデータを使った候補比較、実行・変更・取消判定と、その実行履歴のJSON永続化です。実際の予約、決済、顧客情報は保存しません。

## うまく動かないとき

- request_conditionsにroute、date、budgetがあるか確認する
- candidate_inventoryが配列になっているか確認する
- 既定値へ戻してから再実行する
