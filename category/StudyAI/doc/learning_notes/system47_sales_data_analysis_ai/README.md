# system47 売上データ分析とAI説明

Docker内のPostgreSQLで売上データを集計し、AIには集計済みの結果だけを説明させる役割分担を確認します。

## このテーマでできるようになること

- 同じ売上データを月別、商品別、顧客区分別に集計できる
- 注文数、販売数、売上額を集計単位ごとに確認できる
- 集計用SQLがデータを変更しない理由を説明できる
- 更新を含むSQLを実行前に拒否できる
- 集計済みデータをローカルAIへ送り、説明結果を保存できる

## 最初に取り組むこと

1. Docker Desktopを起動し、StudyHubの「起動」を押してPostgreSQLと架空の売上データを準備する。
2. 「月別売上をSQLで集計」を実行し、1月から3月までの集計結果を確認する。
3. 「商品別売上をSQLで集計」と「顧客区分別売上をSQLで集計」を実行し、集計単位による結果の違いを確認する。
4. 教材欄でテーブル定義、初期データ、3種類のSQLを開き、実行結果の元になった列と式を確認する。
5. LM Studioの5858番ポートでチャット用モデルを読み込み、「SQL集計をAIで説明」を実行する。
6. AIが傾向、異常値、仮説、次の分析観点、注意点を分けて説明し、結果が `outputs/ai_explanation_latest.json` と `outputs/ai_explanation_latest.md` に保存されたことを確認する。
7. 「更新SQLを拒否」を実行し、読み取り専用の境界を確認する。
8. 「停止」を押し、system47専用のPostgreSQLを後片付けする。

## 操作と確認結果

| 操作 | 確認する結果 |
| --- | --- |
| 月別売上をSQLで集計 | PostgreSQLで月ごとの注文数、販売数、売上額が集計される |
| 商品別売上をSQLで集計 | PostgreSQLで商品区分と商品名ごとの集計が行われる |
| 顧客区分別売上をSQLで集計 | PostgreSQLで顧客区分と地域ごとの集計が行われる |
| SQL集計をAIで説明 | 3種類のSQL実行結果がローカルAIへ送られ、5区分の説明結果と保存先が表示される |
| 更新SQLを拒否 | `UPDATE` が検出され、読み取り専用ではないと表示される |

## 役割分担

- `docker-compose.yml` はsystem47専用のPostgreSQLを起動する。
- `scripts/sql_analysis.js` は読み取り専用検査後に3種類のSQLをPostgreSQLで実行する。
- `scripts/analyze_sales.js` はSQL結果と比較するためのCSV集計処理で、受入確認には使わない。
- `scripts/explain_sales.js` は3種類のSQL実行結果だけをLM Studioへ送り、必須5区分を検査してJSONとMarkdownで保存する。
- `checks/readonly_sql_check.js` は説明用SQLがデータを変更しないことを確認する。
- AIは集計済みの結果から傾向、考えられる要因、次に確認する内容を文章化する。

埋め込み専用モデルでは説明文を生成できません。LM Studioにはチャット用モデルを読み込んでください。
