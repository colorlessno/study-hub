# system23 検索結果の並べ替え比較

LM StudioのEmbedding検索順位と、初期候補だけを再評価した順位を比較し、正解順位の改善と追加コストを確認するテーマです。

## このテーマでできるようになること

- 実Embedding検索の初期順位とReranker適用後の順位を比較できる
- 正解文書の初期順位、再順位、順位改善数を確認できる
- 初期検索と再順位付けの遅延、Embedding入力件数、再評価候補数を比較できる
- Rerankerが有効な例、不要な例、初期候補外で改善できない例を説明できる
- 実モデルと明示的なモックを区別できる
- 比較結果と学習メモが保存され、再起動後も参照できることを確認できる

## 最初に取り組むこと

1. LM StudioでEmbeddingモデルを読み込み、「Rerankerが有効な例（実Embedding）」を選ぶ。
2. 検索文、ID付き候補文書、初期top-k、rerank top-k、正解文書IDを確認して「実行」を押す。
3. 正解文書の初期順位と再順位、各候補の点数内訳を比較する。
4. 初期検索と再順位付けの遅延、Embedding入力件数、再評価候補数を確認する。
5. 「Rerankerが不要な例（明示的なモック）」を選び、初期検索ですでに正解1位のときに追加処理が必要か判断する。
6. 観察結果、採用判断、候補制限の注意点を`learning_note`へ記録して再実行する。

## 画面で確認すること

- `model`は検索文と候補文書を一件ずつ順番にLM StudioのEmbedding APIへ送り、初期順位を作る
- Rerankerは初期top-kに入った候補だけを再評価する
- 再評価点は意味類似度、文字の重なり、検索文の完全一致加点から作られる
- 正解文書の順位が上がったか、変わらなかったか、下がったかを確認できる
- 正解文書が初期top-kの外にある場合はRerankerで改善できない
- 順位改善だけでなく、追加遅延と再評価候補数を確認できる
- 保存状態が「JSONファイルへ保存済み」となり、履歴APIから再取得できる

## 処理のつながり

画面から検索文と候補文書をStudyAI APIへ送ります。実モデルモードではBackendからLM StudioのEmbedding APIへ検索文、続いて各候補文書を一件ずつ順番に送り、cosine類似度で初期順位を作ります。初期top-kだけをローカル特徴Rerankerへ渡し、再順位付けします。正解順位、遅延、処理件数、学習メモはサーバーのJSONファイルへ保存されます。

## この実験で確認できる範囲

初期検索は実Embeddingを使えますが、RerankerはCross-Encoderではありません。意味類似度、文字の重なり、完全一致を組み合わせたローカル特徴Rerankerです。目的は候補を絞ってから再評価する構成、順位改善、追加遅延の関係を確認することです。

## うまく動かないとき

- `documents`が一意の`id`と空でない`text`を持つ2～20件の配列か確認する。
- `correct_document_id`が候補文書に存在するか確認する。
- `rerank_top_k`が`initial_top_k`以下か確認する。
- 実モデルモードではLM Studioのポート5858とEmbeddingモデルの読込状態を確認する。
- StudyAIの共有環境が起動しているか確認する。
