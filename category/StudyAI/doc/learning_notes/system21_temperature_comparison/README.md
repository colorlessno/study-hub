# system21 生成のばらつき設定（Temperature）の比較

同じ指示をLM Studioへ一件ずつ順番に送り、Temperatureが回答のばらつきと再現性へ与える影響を比較するテーマです。直前の回答が完了してから次の試行へ進みます。実モデルを使えないときは、利用者が明示的にモックを選んで画面と比較手順だけを確認できます。

## このテーマでできるようになること

- 複数のTemperatureを同じ指示で比較できる
- 各Temperatureを複数回試す理由を説明できる
- 変更する条件と固定する条件を分けて確認できる
- 実モデルの生成と明示的なモックを区別できる
- 定型業務と発想業務で設定判断を分け、理由を学習メモへ記録できる
- 保存した実験結果を実行履歴から再表示できる

## 最初に取り組むこと

1. 「定型業務を実モデルで比較」または「発想業務を実モデルで比較」を選ぶ。
2. `prompt`、`temperatures`、`trial_count`を確認する。
3. `learning_note`の観察結果、判断理由、注意点を入力して「実行」を押す。
4. Temperature、試行番号、モデル名、回答、トークン数を比較する。
5. Temperature別の異なる回答数、平均文字数、再現性の簡易比率と設定判断を確認する。
6. 実行履歴から保存した結果と学習メモを再表示する。

## 画面で確認すること

- Temperatureの値ごとに指定した回数の結果が表示される
- 比較中はTemperature以外の入力条件が同じである
- 実行結果の件数がTemperature数と試行回数の積になる
- 定型業務と発想業務に対応した設定判断が表示される
- `mode`が`model`なら実モデル名が、`mock`なら「明示的なモック」が表示される
- 保存状態が「JSONファイルへ保存済み」になり、履歴を再表示できる

## 処理のつながり

画面から指示、Temperatureの一覧、試行回数、実行方法、業務種別、学習メモを`/api/system21/execute`へ送ります。`mode=model`ではバックエンドがLM StudioのOpenAI互換APIへ、Temperatureの配列順、次に試行番号順で生成要求を一件ずつ送ります。回答と比較結果は学習メモと一緒に`data/ai_learning/system21_runs.json`へ保存され、`/api/system21/runs`から再取得されます。

## この実験で確認できる範囲

`mode=model`の出力は実際のAIモデルによる生成結果です。`mode=mock`は画面と比較手順を確認する模擬結果であり、モデル品質の評価には使いません。どちらの場合も、少数回の結果だけでTemperatureが品質や創造性を必ず向上させるとは判断できません。

## うまく動かないとき

- `temperatures`が数値の配列になっているか確認する。
- `trial_count`が1以上の整数になっているか確認する。
- `mode`が`model`または`mock`になっているか確認する。
- 実モデルを使う場合は、LM Studioで生成用モデルが読み込まれ、OpenAI互換APIが5858番ポートで利用できるか確認する。
- StudyAIの共有環境が起動しているか確認する。
