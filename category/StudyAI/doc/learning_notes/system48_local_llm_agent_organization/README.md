# system48 ローカルLLMによるAI組織運用

複数のAI役割を順番に使い、タスクボード、共有情報、役割別成果物、承認記録を通じて作業を引き継ぐ構成を確認します。明示的な模擬実行に加え、LM StudioのローカルAPIへ役割ごとに通信し、実行ごとの成果物とログを保存できます。

## このテーマでできるようになること

- タスクの状態、担当、必要な成果物、承認対象を一か所で管理できる
- 通常作業、承認が必要な作業、情報不足の作業を区別できる
- 計画、設計、レビュー、品質確認、安全確認、最終報告を役割別に残せる
- 承認が必要な操作を、承認前に実行済みとして扱わない理由を説明できる
- 実際のローカルLLM通信と模擬応答を区別し、実行結果を追跡できる
- 既定8役を設定ファイルで増減し、実行順・成果物・再試行上限を変更できる
- ファイル削除を承認が必要な操作として止め、承認前に実行済みにならないことを確認できる

## 最初に取り組むこと

1. 「通常作業を模擬実行」を実行し、8役の成果物と完了状態が実行フォルダへ保存されることを確認する。
2. 「承認対象を模擬実行」と「情報不足を模擬実行」を実行し、ファイル削除を含む承認待ちと不足情報の停止理由を確認する。
3. LM Studioでチャット用モデルを読み込んだ後に「LM Studioで実行」を選び、役割ごとの実通信と保存結果を確認する。
4. 6つの検証操作を実行し、入力・タスクボード・役割別成果物・承認境界の条件を確認する。
5. 教材欄で役割の定義、共有情報、実行処理、実行ログの記録形式を開き、役割間で受け渡す内容を確認する。

## 操作と確認結果

| 操作 | 確認する結果 |
| --- | --- |
| 通常作業を模擬実行 | 8役の成果物、タスクボード、実行ログが保存され、完了になる |
| 承認対象を模擬実行 | 未承認の操作を実行せず、承認待ちの内容と停止理由が保存される |
| 情報不足を模擬実行 | 目的または成果物の不足を記録して停止する |
| LM Studioで実行 | チャット用モデルへ役割ごとに順次通信し、モデル名と成果物が保存される |
| タスクボードを検証 | 状態、担当、実行回数、必要な成果物、承認対象が揃っている |
| 通常作業の入力を検証 | 目的と成果物があり、承認対象の操作がない |
| 承認が必要な作業を検証 | 承認対象の操作が含まれている |
| 情報不足の作業を検証 | 目的または期待する成果物が不足している |
| 役割別成果物を検証 | 役割ごとの成果物と必要な見出しが揃っている |
| 承認境界を検証 | 承認対象が記録され、秘密情報や実行済み表現が含まれていない |

## 構成

- `fixtures/` に役割定義、共有情報、作業入力を置く。
- `fixtures/role_catalog.json` で役割数、実行順、成果物、最大ラウンド数、ロールごとの再試行上限を変更する。既定は8役とする。
- `samples/` にタスクボードと役割別成果物を置く。
- `checks/` に作業入力、成果物、承認境界の検証処理を置く。
- `scripts/run_organization.js` が模擬応答またはLM Studioの応答で役割を順次実行する。
- `runs/` に実行ごとの入力、タスクボード、役割別成果物、検査結果、停止理由を保存する。
