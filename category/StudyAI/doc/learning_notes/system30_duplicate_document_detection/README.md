# system30 重複文書の検出

完全一致、版違いを含む類似文書、候補外を文書の全組み合わせから検出し、優先文書と除外文書の判断、検索偏り、保存履歴を確認するテーマです。

## このテーマでできるようになること

- 完全一致、正規化後一致、版違いの類似文書を区別できる
- 類似度のしきい値で候補件数が変わることを確認できる
- 重複候補をグループとして確認できる
- 優先文書と除外文書の判断を記録できる
- 重複文書が検索結果を偏らせる可能性を確認できる
- 候補検出と重複確定が別の処理であることを説明できる

## 最初に取り組むこと

1. StudyHubでsystem30を開く。
2. 「重複候補を検出して優先・除外判断を記録」を選んで実行する。
3. 四つの文書から六つの組み合わせが表示されることを確認する。
4. 完全一致、版違いの類似文書、候補外の判定を見比べる。
5. 重複グループと文書ごとの優先・除外判断を確認する。
6. 「しきい値を上げて完全一致だけを候補にする」を実行し、候補件数を比較する。
7. 「異なる文書だけを比較して候補なしを確認」を実行する。
8. 保存履歴から実行結果を開き直す。

## 画面で確認すること

- 文書の全組み合わせに題名、版、類似度、判定が表示される
- 同じ本文は完全一致、内容の近い版違いは類似文書として表示される
- しきい値を上げると版違いの文書が候補から外れる
- 優先文書と除外文書が入力した判断どおりに表示される
- 同じ重複グループの文書が検索偏りの一覧へ複数現れる
- 実行結果と学習メモがJSONへ保存され、再起動後も履歴に残る

## 処理のつながり

画面の文書集合、検索語、しきい値、判断、学習メモをStudyAI APIへ送ります。バックエンドは文書の全組み合わせについて完全一致、正規化後一致、文字列類似度を判定し、候補をグループにまとめます。入力した優先・除外判断と検索偏りの確認結果を返し、実行結果と学習メモをJSONへ保存します。

## この実験で確認できる範囲

NFKC、大小文字、空白・記号を整理した本文と、文字列の並びを使う類似度で候補を抽出します。意味が同じかどうかをAIで確定する処理ではありません。候補を自動削除せず、題名、版、本文、運用上の優先順位を人が確認します。

## うまく動かないとき

- documentsが2件以上20件以下の配列になっているか確認する
- 各文書のdocument_id、title、textが空でないか確認する
- document_idが重複していないか確認する
- similarity_thresholdが0から1の数値か確認する
- resolutionで指定した文書番号がdocumentsに存在するか確認する
- 既定の入力例へ戻してから再実行する
