# system43 制約最適化AI

仕事の場所・優先度・時間枠と担当者の開始位置・稼働時間を使って候補解を作り、ルート、制約違反、総コスト、人間調整を確認するテーマです。

## このテーマでできるようになること

- 担当者ごとの割当結果、訪問順、距離、時間枠を確認できる
- 未割当、所要時間超過、距離超過、時間枠超過、必須の仕事不足を別々に確認できる
- 距離・遅延・未割当・時間超過の重みから総コストを確認できる
- 人間が変更した割当と調整者を実行履歴・監査ログへ保存できる

## 最初に取り組むこと

1. StudyHubでsystem43を開く。
2. 既定値で実行し、優先度順の担当割当、訪問順、距離、時間枠、総コストを確認する。
3. jobsを追加してresourcesの合計上限を超え、未割当の仕事と調整候補を確認する。
4. constraintsのmax_durationまたはmax_route_distanceを小さくし、時間・距離の制約違反とコストを確認する。
5. time_windowsを短くし、訪問終了が時間枠を超えた仕事と遅延コストを確認する。
6. must_visitに存在しない仕事を追加し、必須の仕事が見つからない注意点を確認する。
7. human_adjustmentをappliedにし、担当者別のjobsとoperatorを入力して、人間調整した割当が実行履歴と監査ログへ保存されることを確認する。
8. バックエンドを再起動してsystem43を開き直し、人間調整を含む直前の実行履歴が復元されることを確認する。

## 画面で確認すること

- 担当者ごとに割り当てた仕事が表示される
- 割当件数と件数上限を比較できる
- 訪問順、開始位置、距離、時間枠、遅延、時間超過を確認できる
- 未割当の仕事と見つからない必須の仕事が別々に表示される
- 距離・遅延・未割当・時間超過の内訳と総コストを確認できる
- 制約違反ごとの調整候補を確認できる
- 人間調整の状態、調整者、割当、保存有無を確認できる
- JSON保存の成否、保存上限、保存件数を確認できる
- 再起動後に直近20件の実行履歴が新しい順で復元される

## 処理のつながり

画面の仕事、担当者、場所、優先度、時間枠、制約、コスト重み、人間調整をStudyAI APIへ送ります。APIは優先度と移動距離から候補解を作り、訪問順、時間枠、制約違反、総コスト、調整候補を返します。実行結果、評価指標、監査記録、人間調整は `data/enterprise_ai/system43_runs.json` へUTF-8で保存し、新しい順の直近20件を再起動後も復元します。

## この実験で確認できる範囲

教材用の座標と決定的な割当処理です。実際の地図サービス、交通状況、勤務契約、配車やシフト確定は扱いませんが、入力と人間調整はブラウザ内だけで処理せずStudyAI APIへ送信します。

## うまく動かないとき

- jobsとresourcesが配列になっているか確認する
- 各jobにid、duration、location、priorityがあるか確認する
- 各resourceにid、capacity、start_location、available_windowがあるか確認する
- constraintsにmax_duration、max_route_distance、must_visitがあるか確認する
- time_windowsが仕事IDと時間枠の対応になっているか確認する
- human_adjustmentのstatusがpending、applied、acceptedのいずれかになっているか確認する
- 保存状態が失敗の場合は、`data/enterprise_ai` フォルダへ書き込めるか確認する
- 既定値へ戻してから再実行する
