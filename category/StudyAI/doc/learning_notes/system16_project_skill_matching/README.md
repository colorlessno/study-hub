# system16 案件・スキルシートマッチング

案件要件と技術者のスキルを構造化し、適合度、根拠、不足条件、過去事例を確認するテーマです。

## このテーマでできるようになること

- 案件要件とスキルシートを入力して適合度を確認できる
- 必須条件、歓迎条件、経験工程、役割を分けて評価できる
- ファイル解析と複数候補の一括評価を操作できる
- 過去事例とマッチング履歴が評価に与える役割を説明できる
- 候補者情報をマスクして保存し、履歴をCSVで出力できる
- 評価結果と処理時間をMLflowで確認できる

## 最初に取り組むこと

1. 「単一マッチング画面」で案件要件とスキル情報を入力する。
2. 適合度、判定根拠、不足条件を確認する。
3. 「ファイル・一括評価画面」で解析と一括評価の入力形式を確認する。
4. 「過去事例・履歴画面」で事例登録と評価履歴を確認する。
5. 評価履歴をCSVで出力し、保存内容とMLflowの記録を確認する。

## 画面で確認すること

- 必須条件を満たさない場合は適合度が下がる
- 表記が異なる同義スキルを正規化して比較する
- 単一入力、ファイル入力、一括評価を使い分けられる
- 判定結果と実際の成否を過去事例として登録できる
- 氏名、メールアドレス、電話番号、住所がDB保存前にマスクされる
- ファイル名から作る候補IDが匿名化される
- 評価モード、適合度、処理時間、要レビュー判定がMLflowへ記録される

## 処理のつながり

画面からFastAPIへ入力を送り、案件要件構造化とスキルシート解析が共通形式へ変換します。スキル正規化と評価処理が適合度を計算し、過去事例検索とレポート作成が根拠や注意点を結果へ加えます。結果はPostgreSQLへ保存し、履歴画面から参照・CSV出力できます。埋め込み処理はLM Studio、類似検索はpgvector、評価記録はMLflowと連携します。

一括評価画面では、選択したスキルシートを件数にかかわらず一件ずつ順番に評価し、全件の保存後に結果一覧を表示します。

## うまく動かないとき

- 案件要件とスキル情報の両方が入力されているか確認する。
- ファイル形式が対応範囲に含まれるか確認する。
- 必須条件と歓迎条件が区別されているか確認する。
