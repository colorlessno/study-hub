# system22 RAGの文書分割比較

同じ文書と固定質問を使い、分割サイズと重複幅だけを変えて、検索結果と回答範囲の違いを比較するテーマです。

## このテーマでできるようになること

- 2件以上の分割条件を同じ文書と固定質問で比較できる
- 分割サイズと重複幅が分割数、検索順位、回答範囲へ与える影響を確認できる
- 回答に必要な語句が複数の文書断片へ分断された状態を確認できる
- 小さすぎる分割と大きすぎる分割の欠点を比較結果から説明できる
- 比較結果と学習メモが保存され、再起動後も参照できることを確認できる

## 最初に取り組むこと

1. 「小・中・大を比較」を選び、文書、固定質問、3件の分割条件を確認する。
2. 「実行」を押し、条件ごとの分割数、期待語句の平均保持率、根拠分断数を比較する。
3. 各条件の文書断片と質問別の検索・回答結果を確認する。
4. 推奨条件と理由を確認し、自分の判断を`learning_note`へ記録して再実行する。
5. 「重複幅を比較」を選び、重複なしと重複ありで根拠の保持がどう変わるか確認する。

## 画面で確認すること

- すべての条件で同じ文書と固定質問が使われている
- `step`は分割サイズから重複幅を引いた値になる
- 小さい分割では文書断片が増え、必要な語句が複数断片へ分かれる場合がある
- 大きい分割では根拠を保持しやすい一方、検索1件に含まれる情報量が増える
- 重複幅を増やすと根拠を保持しやすくなる一方、断片数と重複量が増える
- 実行結果に検索上位、抽出回答、保持した期待語句、保持率、根拠分断が表示される
- 保存状態が「JSONファイルへ保存済み」となり、履歴APIから再取得できる

## 処理のつながり

画面から文書、固定質問、比較条件、学習メモをStudyAI APIへ送ります。Backendは分割条件を入力順に一件ずつ処理し、その条件の各質問も入力順に一件ずつ評価します。条件ごとに文書を分割して質問と文書断片の簡易類似度を計算し、検索1位の断片を抽出回答として、期待語句の保持率と根拠の分断を評価します。入力と結果はサーバーのJSONファイルへ保存されます。

## この実験で確認できる範囲

検索は文字単位の簡易類似度、回答は検索1位の文書断片を使うローカル抽出方式です。外部LLMによる回答生成やEmbedding検索の品質を評価するテーマではありません。条件を比較するときは文書と質問を固定し、分割設定だけを変更します。

## うまく動かないとき

- `chunk_configs`が2件以上あるか確認する。
- 各`chunk_size`が1以上の整数か確認する。
- 各`overlap`が0以上かつ`chunk_size`未満か確認する。
- 各質問に空でない`question`と1件以上の`expected_terms`があるか確認する。
- StudyAIの共有環境が起動しているか確認する。
