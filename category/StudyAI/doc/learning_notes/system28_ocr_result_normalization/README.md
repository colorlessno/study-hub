# system28 OCR文字列の正規化

OCR後の文字列をStudyAIバックエンドへ送り、規則と誤認識辞書を順番に適用します。自動補正できる表記と、OCR元画像を見て確定する文字を分けて確認するテーマです。

## このテーマでできるようになること

- 空白、全角半角、誤認識辞書、英字Oの補正を別々に確認できる
- 規則の適用順と誤認識辞書を変え、正規化結果の違いを比較できる
- 信頼度の高い自動補正と、人手確認が必要な補正を区別できる
- 保存済み実行履歴を使って入力と結果を再確認できる

## 最初に取り組むこと

1. StudyHubでsystem28を開く。
2. 「全規則を適用」の入力例を選び、既定値で実行する。
3. 補正前後と、規則別の修正差分を確認する。
4. 誤認識辞書の補正と英字Oの補正で、信頼度と確認方法が異なる理由を確認する。
5. `ocr_o_zero` を外した入力例を実行し、人手確認対象がなくなることを確認する。
6. 誤認識辞書の値を変えて実行し、差分と保存済み履歴を確認する。

## 画面で確認すること

- `space` は行内の連続空白を一つへ統一する
- `zenkaku` は全角の英数字・記号を半角へ統一する
- `dictionary` は指定した誤認識辞書へ完全一致する文字列だけを補正する
- `ocr_o_zero` は数字に隣接する英字Oだけを補正し、OCR元画像との照合を求める
- 規則を外すと、その規則による差分は作成されない
- 実行結果がJSONへ保存され、実行履歴から再表示できる

## 処理のつながり

画面の入力は `POST /api/system28/execute` でStudyAIバックエンドへ送られます。バックエンドは規則を指定順に適用し、差分、信頼度、人手確認対象を作成して `system28_runs.json` へ最新20件を保存します。

## この実験で確認できる範囲

対象はOCRエンジンが出力した後の文字列です。画像から文字を読み取る処理は行いません。英字Oと数字0のように文脈だけでは確定できない文字は、自動補正の結果を採用せずOCR元画像と照合します。

## うまく動かないとき

- `rules` が1件以上の文字列配列になっているか確認する
- 使用できる規則が `space`、`zenkaku`、`dictionary`、`ocr_o_zero` であることを確認する
- `dictionary` を使う場合は `correction_dictionary` に置換前と置換後を指定する
- 既定値へ戻してから再実行する
