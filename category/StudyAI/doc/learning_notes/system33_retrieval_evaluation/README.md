# system33 検索評価の実行

複数の質問について順位付き検索結果を正解文書と照合し、検索指標、失敗ケース、chunk設定変更による差を保存して確認するテーマです。

## このテーマでできるようになること

- 質問ごとに検索順位と正解文書を照合できる
- Hit、Recall、Precision、逆順位の違いを説明できる
- 複数質問の指標を集計し、失敗ケースを分類できる
- top-kやchunk設定を変えた実行を比較できる
- 評価入力と結果がJSONへ保存され、再起動後も履歴を参照できることを確認できる

## 最初に取り組むこと

1. StudyHubでsystem33を開く。
2. 「既定の検索結果を評価」を選び、検索評価を実行する。
3. 全体指標、質問別の判定、失敗ケースを確認する。
4. 「小さいchunk設定と検索結果を比較」を選んで実行し、前回との差を確認する。
5. top_kや検索順位を変更し、指標と失敗分類の変化を確認する。
6. 実行履歴を更新し、入力、結果、学習メモが保存されたことを確認する。

## 画面で確認すること

- 評価ケース数とHit Rate、平均Recall、平均Precision、平均逆順位が表示される
- 質問ごとに見つかった正解文書、見つからなかった正解文書、失敗分類が表示される
- 先頭ケースでは、検索結果が入力した順位のまま表示される
- 同じ評価名で再実行すると、前回のchunk設定と指標差が表示される
- 保存状態が「JSONファイルへ保存済み」になり、実行履歴に結果が残る

## 処理のつながり

画面から評価名、chunk設定、top-k、質問ごとの正解文書と検索順位をAPIへ送ります。バックエンドは質問別指標と全体指標を計算し、失敗ケースを分類します。同じ評価名の前回実行があれば指標差を算出し、入力と結果をJSONへ保存します。

## この実験で確認できる範囲

登録済みの文書番号と順位を照合する検索評価です。実際の検索処理や類似度計算は行いません。評価ケースと検索結果を変えることで、検索方式やchunk設定の結果を同じ指標で比較します。

## うまく動かないとき

- query_casesが1件以上あり、各ケースにquestion、expected_evidence、retrieval_resultsがあるか確認する
- expected_evidenceとretrieval_resultsが文字列の配列か確認する
- top_kが1以上の整数か確認する
- 既定値へ戻してから再実行する
