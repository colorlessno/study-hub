# system25 出力上限とTemperatureの比較

同じ指示を実際のLLMへ複数回送り、出力上限による途中切れとTemperatureによる回答差を比較するテーマです。

## このテーマでできるようになること

- `max_tokens`が回答の出力上限を指定することを確認できる
- `finish_reason`から回答が途中で切れたかを判断できる
- Temperatureを変えた複数回の回答から、回答の異なり方を比較できる
- 出力トークン数、応答時間、途中切れを見て候補設定を判断できる
- 実通信の結果と明示的なモックを区別できる

## 最初に取り組むこと

1. LM Studioで入力JSONに指定したモデルを読み込む。
2. StudyHubでsystem25を開き、`mode`が`model`になっていることを確認する。
3. 指示、モデル、出力上限、Temperature、試行回数を確認する。
4. 実行し、試行ごとの回答と条件別集計を確認する。
5. 候補設定を見た後、自分の採用判断と残る注意点を学習メモへ記録する。

## 画面で確認すること

- 全条件で同じ指示とモデルが使われている
- 出力上限が小さい条件では`finish_reason=length`になる場合がある
- `finish_reason=length`の試行だけが途中切れとして集計される
- 同じTemperatureの複数回の回答が同じか異なるかを確認できる
- 条件ごとの平均出力トークン数と平均応答時間を比較できる
- 実行結果の保存状態が表示される

## 処理のつながり

画面のJSONはStudyAI APIへ送られます。APIは出力上限、Temperature、試行番号の順に一件ずつ共通LLMクライアントからLM Studioへ送信し、直前の応答完了後に次の試行へ進みます。LM Studioの回答、`finish_reason`、トークン数、応答モデルを集計し、画面表示と履歴ファイルへ反映します。

## modelとmockの違い

`model`は指定したモデルへ実際に通信します。`mock`はLM Studioを使わず、画面と比較手順だけを確認する模擬結果です。通信に失敗しても自動で`mock`へ切り替わりません。

## うまく動かないとき

- LM Studioのサーバーと指定モデルが起動しているか確認する
- JSONの角括弧、引用符、カンマを確認する
- `max_tokens_values`と`temperatures`が重複しない配列か確認する
- `trial_count`が1～5になっているか確認する
- 画面に表示された通信エラーを確認し、原因を直してから再実行する
