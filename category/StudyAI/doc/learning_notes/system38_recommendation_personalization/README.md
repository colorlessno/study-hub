# system38 リアルタイム推薦・パーソナライズ

利用者の関心、行動履歴、商品の鮮度から推薦順位を作成するテーマです。

## このテーマでできるようになること

- 関心の一致数と商品の鮮度から推薦点を確認できる
- 入力条件を変更して推薦順位の変化を比較できる
- 在庫切れなどの除外条件が推薦前に適用されることを確認できる
- A/Bテストの割当と、推薦後の反応ログを実行履歴で確認できる
- 再起動後も保存済みの推薦結果と反応ログを確認できる

## 最初に取り組むこと

1. StudyHubでsystem38を開く。
2. 既定値で実行し、商品ごとの関心点、鮮度点、合計点、推薦順位を確認する。
3. user_profileのinterestsを変更し、推薦順位の変化を比較する。
4. item_catalogの一商品をout_of_stockへ変更し、推薦対象から外れることを確認する。
5. 上位商品のタグを同じ内容へ寄せ、同質推薦の注意点を確認する。
6. experimentのuser_keyを変更し、割り当てられるvariantを比較する。
7. feedbackの商品と反応を変更し、実行履歴へ保存された内容を確認する。
8. StudyAIを再起動し、保存済みの実行履歴を選んで推薦結果と反応ログを再表示する。

## 画面で確認すること

- 関心タグと商品タグの一致内容が表示される
- 関心点と鮮度点の合計で順位が決まる
- 除外条件に該当する商品は順位表へ入らない
- 推薦内容が偏る場合は注意点が表示される
- A/Bテストの実験ID、利用者キー、割当variantが表示される
- 商品への反応が反応ID付きで保存される
- 実行履歴から以前の推薦結果を表示できる
- 履歴保存が「はい」、保存形式が「json」と表示される
- StudyAIの再起動後も以前の実行履歴を表示できる

## 処理のつながり

画面の利用者情報、行動履歴、商品一覧、除外条件、実験条件、反応内容をAPIへ送ります。APIは除外処理、採点、順位付け、variant割当を行い、推薦結果、反応ログ、監査記録、評価指標を同じJSON実行履歴へ保存します。保存済みの直近20件は再起動時に読み戻されます。

## この実験で確認できる範囲

タグの一致数と鮮度を使った簡易推薦です。反応ログの保存までは確認できますが、機械学習モデルによる再学習や実商品の配信は行いません。

## うまく動かないとき

- interestsとtagsが文字列の配列か確認する
- freshnessが数値か確認する
- 既定値へ戻してから再実行する
