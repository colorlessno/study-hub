# system20 コンテキスト上限の実験

長い文章のどこに重要情報を置くかによって、入力上限内に残る情報と回答可否がどう変わるかを比較するテーマです。

## このテーマでできるようになること

- 短い文章と、重要情報が先頭・中央・末尾にある長い文章を同じ入力上限で比較できる
- 入力上限内に残った文章と上限外になった文章を確認できる
- 重要情報が上限内に残ったかを回答可否と結び付けて確認できる
- 文章の分割、必要部分の検索、要約が必要になる条件を整理できる
- 実行履歴から入力条件と結果を再表示できる

## 最初に取り組むこと

1. 「短い文章」を選び、全文が上限内に残ることを確認する。
2. 「重要情報が先頭」を選び、上限内と上限外の文章、重要情報の位置、回答可否を確認する。
3. 「重要情報が中央」と「重要情報が末尾」も同じ上限で実行する。
4. 短い文章と三つの長い文章を比較し、重要情報が上限外になった条件を確認する。
5. `context_limit`を変更し、回答可否が切り替わる境界を確認する。
6. 実行履歴から過去の条件と結果を再表示する。

## 画面で確認すること

- 推定トークン数、入力上限、上限外になった推定トークン数
- 重要情報が文章の先頭・中央・末尾のどこにあるか
- 指定した重要語句が上限内へ完全に残っているか
- 上限内に残った文章と上限外になった文章の境界
- 重要情報の残存と回答可否の関係
- 長い文章を扱うために、分割・検索・要約のどれを検討するか

## 処理のつながり

画面から文章、入力上限、重要語句をStudyAIのAPIへ送ります。バックエンドは文章を学習用の規則で分割し、入力上限に対応する元の文章位置を求めます。その位置で文章を上限内と上限外に分け、重要語句が上限内へ完全に残ったかを判定します。入力条件と結果は、最新20件まで`data/ai_learning/system20_runs.json`へUTF-8で保存され、StudyAIの再起動後も読み戻されます。

## この実験で確認できる範囲

推定トークン数は学習用の簡易分割です。実際のAIモデルでは、モデル固有の分割規則、システム指示、会話履歴も入力上限を消費します。この画面の回答可否は、指定した重要語句が上限内へ完全に残ったかで判定し、AIモデルによる回答生成は行いません。

## うまく動かないとき

- `context_limit`が1以上の整数か確認する。
- `important_marker`が`text`内に同じ表記で含まれているか確認する。
- StudyAIの共有環境が起動しているか確認する。
