# system11 教材用ファイル整理

専用の教材用フォルダをMCP filesystemサーバー経由で読み取り、整理案を作り、選択した操作だけをMCP経由で実行して元に戻すまでを確認するテーマです。PC上の任意のフォルダは操作しません。

## このテーマでできるようになること

- ファイルを変更せずに整理案を作る処理と、選択した案を実行する処理を区別できる
- 移動、名前変更、保管、操作しないという整理案を確認できる
- 実行結果を履歴で確認し、移動や名前変更を元に戻せる
- 操作範囲、除外規則、実行形式の除外による安全設計を説明できる

## 最初に取り組むこと

1. 「教材用ファイルを初期状態へ戻す」を押し、用意されたファイルを確認する。
2. `*.log` を対象外にしたまま「整理案を作る」を押す。
3. 整理案の操作、元のファイル、操作後の場所、理由を確認する。
4. 実行する案を選び、確認欄にチェックを入れて実行する。
5. 実行履歴で結果を確認し、「元に戻す」を押して初期位置へ戻す。
6. 手動実行の既定値を保存し、自動実行を行わないことを確認する。

## 画面で確認すること

- 整理案を作っただけではファイルの場所や名前が変わらない
- 一覧、本文、メタ情報、移動、名前変更、復元がMCPツールで一つずつ順番に処理される
- AIを利用できない場合も教材用の規則で整理案を作れる
- `.cmd` は操作対象外になり、`*.log` は整理案に含まれない
- 選択しなかった整理案は実行されない
- 履歴にはファイルごとの結果と元に戻せるかどうかが表示される

## 処理のつながり

教材初期化処理が専用フォルダへサンプルを複製します。スキャン処理は読取専用MCPツールでファイルを列挙し、本文とメタ情報を順番に取得します。整理案生成処理が操作候補を作り、安全判定を通過した選択済み項目だけをMCPの移動ツールへ一つずつ渡します。結果と元に戻すための情報はPostgreSQLへ保存し、復元も同じMCPツールで逆順に行います。

## うまく動かないとき

- 最初に教材用ファイルを初期状態へ戻しているか確認する。
- 確認するフォルダと整理先が `/mnt/organize/work` 配下になっているか確認する。
- AIを利用できない場合は、整理案の生成方法が「教材用の規則」と表示されることを確認する。
- 同名ファイルがある場合は、実行結果のエラー内容を確認する。
