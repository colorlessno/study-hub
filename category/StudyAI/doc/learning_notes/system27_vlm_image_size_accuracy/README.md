# system27 画像サイズとVLM評価の比較

同じ画像をサイズとJPEG品質別に変換し、VLMの回答、読み取れた要点、読み落とし、データ量を比較するテーマです。

## このテーマでできるようになること

- 同じ画像を異なるサイズとJPEG品質へ変換して比較できる
- VLMへ実画像を送り、画像ごとの回答と読み落としを確認できる
- 回答を共通の要点で採点し、画像サイズを選ぶ根拠を整理できる
- 実VLMの結果と明示的なモック結果を区別できる

## 最初に取り組むこと

1. StudyHubでsystem27を開き、既定の `mock` で実行する。
2. 小・中・大の画像が同じ内容で、サイズとJPEG品質だけ異なることを確認する。
3. 回答、要点網羅率、読み落とし、データ量を画像ごとに比較する。
4. `image_variants` の横幅またはJPEG品質を一つだけ変更し、画像と集計結果の違いを確認する。
5. 画像対応モデルをLM Studioへロードした場合は、`mode` を `model`、`model` をロードしたモデル名へ変更して実行する。

## 画面で確認すること

- 比較方法が「明示的なモック」または「実VLMへの画像送信」と表示される
- 元の内容が同じ3種類のJPEG画像が実際に表示される
- 各画像の縦横サイズ、JPEG品質、データ量が表示される
- 各画像の回答、確認できた要点、読み落とし、要点網羅率が比較できる
- 要点網羅率が最高の画像のうち、データ量が最小の条件が推奨候補になる
- 比較結果と学習メモがJSONファイルへ保存される

## modelとmockの違い

`model`は、画面で生成した各画像を入力順に一件ずつOpenAI互換API経由でLM StudioのVLMへ送信します。直前の応答完了後に次の画像へ進み、同時送信しません。画像入力に対応したモデルをロードし、入力欄のモデル名を一致させてください。

`mock` は画像変換までは実際に行いますが、VLMへは送信しません。`mock_responses` に書かれた回答を使って画面と採点手順を確認します。mockの点数はVLMの性能を表しません。また、modelの失敗時にmockへ自動で切り替わることもありません。

## 評価の考え方

要点網羅率は、回答とVLMが返した要点に `expected_points` の語句が含まれる割合です。小さい画像で要点が欠けるか、圧縮率を上げたときに文字が読めなくなるかを確認します。

サイズの影響だけを確認するときはJPEG品質を固定し、JPEG品質の影響だけを確認するときは横幅を固定します。一度に両方を変えると、どちらが回答差の原因か判断できません。

## うまく動かないとき

- `model` で失敗する場合は、LM Studioに画像入力対応モデルがロードされているか確認する。
- モデル名エラーの場合は、LM Studioのモデル識別子と入力欄の `model` を一致させる。
- JSON形式のエラーの場合は、`image_variants` のIDが重複していないか、横幅とJPEG品質が範囲内か確認する。
- mockで失敗する場合は、全画像IDに対応する `mock_responses` があるか確認する。
