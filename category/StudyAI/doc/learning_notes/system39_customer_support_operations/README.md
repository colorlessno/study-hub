# system39 業務実行型カスタマーサポートAI

問い合わせへの回答と、住所変更などの業務操作を分けて判断するテーマです。

## このテーマでできるようになること

- 問い合わせ分類と回答内容を確認できる
- 回答と業務操作の実行可否を分けて確認できる
- 本人確認が必要な操作を停止し、担当者確認へ移す条件を説明できる
- 業務手続きの受付結果、問い合わせチケット、担当者への引継ぎを再起動後も実行履歴で確認できる

## 最初に取り組むこと

1. StudyHubでsystem39を開く。
2. 既定値で実行し、問い合わせ分類、回答、要求された操作、次の処理を確認する。
3. authenticatedをfalseへ変更し、住所変更操作が停止されることを確認する。
4. inquiry_textを一般的な質問へ変更し、回答だけを返す処理を確認する。
5. 注意点と監査記録から、操作を止めた理由を確認する。
6. order_infoのshipping_statusを変更し、出荷後の住所変更が停止されることを確認する。
7. 実行履歴を開き、手続き結果、チケット、引継ぎ要約が保存されていることを確認する。
8. StudyAIを再起動し、保存した実行履歴が復元されることを確認する。

## 画面で確認すること

- 問い合わせ文から住所変更か一般質問かを分類する
- FAQの回答と、実行する業務操作を別の列で表示する
- 本人確認が必要な操作では認証状態を確認する
- 本人確認が不足すると操作を実行せず担当者確認へ移行する
- 出荷後の住所変更は手続きを受け付けず、理由付きで担当者確認へ移行する
- 本人確認済みかつ出荷前の場合は、住所変更の受付結果と問い合わせチケットを記録する
- 担当者確認へ移す場合は、引継ぎ理由と問い合わせ要約を記録する
- 判断理由を監査記録から確認できる
- 保存形式がJSONになり、再起動後も同じ案件ID、チケット、引継ぎ、監査記録を確認できる

## 処理のつながり

画面の顧客状態、問い合わせ文、注文状態、FAQ候補、要求手続き、操作ルールをAPIへ送ります。APIは問い合わせ分類、回答選択、操作可否を判定し、業務手続きの受付結果、問い合わせチケット、必要な引継ぎ要約、監査記録、評価指標を同じJSON実行履歴へ保存します。

## この実験で確認できる範囲

文字列による簡易分類と、教材用の本人確認・注文状態による手続き判定です。受付結果、チケット、引継ぎはStudyAIバックエンドのJSON実行履歴へ保存しますが、実在する顧客情報や外部の問い合わせ管理システムは変更しません。

## うまく動かないとき

- inquiry_textが文字列か確認する
- customer_contextのauthenticatedが真偽値か確認する
- 既定値へ戻してから再実行する
