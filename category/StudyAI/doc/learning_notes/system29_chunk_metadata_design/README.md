# system29 文書断片のメタデータ設計

文書断片へ出典、ページ、章見出し、公開範囲、更新日時を付け、検索前フィルタと検索結果の根拠表示を確認するテーマです。

## このテーマでできるようになること

- 文書断片と追跡用metadataの関係を確認できる
- metadataフィルタで検索対象が変わることを確認できる
- 引用表示から出典、ページ、章見出しをたどれる
- 公開範囲の値を付けることと、検索前に絞り込むことの違いを説明できる

## 最初に取り組むこと

1. StudyHubでsystem29を開く。
2. 「公開範囲が一致する検索結果と根拠を確認」を選んで実行する。
3. 文書断片のmetadata、検索結果、引用表示が一致することを確認する。
4. 「公開範囲が一致せず検索対象外になる結果を確認」を実行し、対象外理由を確認する。
5. 「更新日時フィルタより古い文書が対象外になる結果を確認」を実行する。
6. 保存履歴から実行結果を開き直す。

## 画面で確認すること

- 文書断片番号と本文が表示される
- 出典、ページ、章見出し、公開範囲、更新日時が本文と同じ行に表示される
- 引用表示に出典、ページ、章見出しが含まれる
- 入力したメタデータが結果へ保持される
- 公開範囲と更新日時のフィルタ不一致時は検索結果が0件になる
- 実行結果と学習メモがJSONへ保存され、再起動後も履歴に残る

## 処理のつながり

画面の文書、検索語、metadata、metadataフィルタをStudyAI APIへ送ります。バックエンドは必須項目を検証し、文書断片番号を付け、検索前にmetadataフィルタを適用します。一致した文書だけを根拠付き検索結果へ含め、実行結果と学習メモをJSONへ保存します。

## この実験で確認できる範囲

一つの文書を一つの断片として扱い、検索語の包含とmetadataの完全一致を確認します。自動分割、意味検索、利用者認証、組織階層を考慮した認可は行いません。公開範囲フィルタは認可設計の最小例であり、本番の権限制御そのものではありません。

## うまく動かないとき

- metadataがJSONオブジェクトになっているか確認する
- source、page、section、permission、updated_atが揃っているか確認する
- pageが1以上の整数、updated_atがISO 8601形式か確認する
- permissionがpublic、internal、restrictedのいずれかか確認する
- 既定の入力例へ戻してから再実行する
