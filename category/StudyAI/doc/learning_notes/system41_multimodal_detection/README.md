# system41 コンピュータビジョン・マルチモーダルAI

棚・レシート画像の情報、OCR結果、商品マスタ、センサーイベントを照合し、検出商品と数量、異常候補、確認待ちを判断して人間確認結果を保存するテーマです。

## このテーマでできるようになること

- 画像、OCR、商品マスタ、センサーを同じ商品判定へ組み合わせられる
- 各入力の数量を照合し、推定数量と異常候補を確認できる
- 低信頼、マスタ未登録、センサー不一致を確認待ちへ分け、人間確認結果を保存できる

## 最初に取り組むこと

1. StudyHubでsystem41を開く。
2. 既定値で実行し、itemが商品マスタ、OCR、センサーと一致して数量2と推定されることを確認する。
3. unknown_boxがマスタ未登録かつセンサーの裏付けなしとして確認待ちになることを確認する。
4. image_inputs.shelf_imageのqualityをlowへ変更し、画像品質不足の注意点を確認する。
5. product_master、ocr_results、sensor_eventsの数量を変更し、数量不一致と異常候補を確認する。
6. human_review.statusをconfirmed、reviewerを任意の名前、decisionsに確認結果を設定し、確認結果が実行履歴と監査記録へ保存されることを確認する。
7. 画面の保存状態でJSONへの保存成功、保持上限20件、現在の保持件数を確認する。
8. バックエンドを再起動し、実行履歴から保存済みの人間確認結果を再表示できることを確認する。

## 画面で確認すること

- 検出候補ごとに商品ID、各入力の数量、推定数量、信頼度が並ぶ
- 商品マスタ、OCR、センサーの一致状況が候補ごとに表示される
- 低信頼、マスタ未登録、センサー不一致、数量不一致の理由が確認待ち一覧と異常候補に表示される
- 人間確認が未実施ならreview_required、確認済みならconfirmed、却下ならrejectedになる
- 人間確認の状態、確認者、候補ごとの確認結果、履歴への保存有無が表示される
- 「既定の照合」「低画質例」「数量不一致例」「高いしきい値例」「人間確認済み例」で入力を切り替えられる
- JSONへの保存成否、保持上限20件、現在の保持件数が表示される
- バックエンド再起動後も保存済みの実行履歴を選び、照合結果と人間確認結果を再表示できる

## 処理のつながり

画面の画像情報、検出候補、OCR結果、商品マスタ、センサーイベント、しきい値、人間確認結果を`POST /api/system41/execute`へ送ります。APIは候補を商品マスタへ照合し、画像・OCR・センサーの数量と信頼度から推定数量、異常候補、確認待ち一覧を作ります。照合結果、人間確認結果、監査ログ、KPIはUTF-8の`data/enterprise_ai/system41_runs.json`へ直近20件保存され、起動時に`GET /api/system41/runs`で再表示できる履歴へ復元されます。

## この実験で確認できる範囲

実画像の解析ではなく、画像を表すメタデータ、OCR結果、商品マスタ、センサーイベントを教材用データとしてAPIへ送信します。カメラや外部センサー自体には接続しませんが、ブラウザ内だけで処理せず、照合結果と人間確認結果はStudyAIバックエンドへ送信して実行履歴へ保存します。

## うまく動かないとき

- image_inputs.shelf_imageにwidth、height、qualityがあるか確認する
- detection_candidates、product_master、ocr_results、sensor_eventsが配列になっているか確認する
- confidence_thresholdが0から1の範囲か確認する
- human_reviewのstatusがpending、confirmed、rejectedのいずれかになっているか確認する
- 保存状態が失敗の場合は、`data/enterprise_ai`フォルダへ書き込めるか、`system41_runs.json`がUTF-8のJSON配列になっているか確認する
- 既定値へ戻してから再実行する
