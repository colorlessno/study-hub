# system34 回答内容の評価

質問、必要な回答要素、根拠、AI回答を照合し、回答不足、根拠のない主張、不要な補足を区別するテーマです。評価した条件と結果はJSONファイルへ保存されます。

## このテーマでできるようになること

- 正確性、根拠性、網羅性、簡潔性を別々に確認できる
- 必要な回答要素と、回答内の主張を分けて確認できる
- 回答内の主張がどの根拠を参照しているか確認できる
- 回答不足、根拠のない主張、不要な補足を判別できる
- 点数、判定理由、改善内容を対応させて読める
- 評価結果が保存され、再表示できることを確認できる

## 最初に取り組むこと

1. StudyHubでsystem34を開く。
2. 「必要事項を満たす回答」を実行し、四観点の点数と各表を確認する。
3. 「回答不足を確認」を実行し、不足した回答要素と網羅性を確認する。
4. 「根拠のない主張を確認」を実行し、主張と根拠性を確認する。
5. 「不要な補足を確認」を実行し、質問との関連と簡潔性を確認する。
6. 実行履歴から結果を再表示し、入力と評価結果が保存されていることを確認する。

## 画面で確認すること

- 四つの点数と採点理由が対応している
- 必要な回答要素ごとに、語句の有無と矛盾する表現が表示される
- 回答内の主張ごとに、参照した根拠、質問への必要性、判定が表示される
- 問題の種類に応じた回答分類と改善内容が表示される
- 学習メモと保存状態が表示される

## 入力項目の関係

`expected_points` は質問へ答えるために必要な要素を定義します。`answer_claims` はAI回答を主張単位に分け、どの回答要素と根拠へ対応するかを記録します。`support_terms` は、参照した根拠文で主張を確認するための語句です。

この対応を明示することで、単に期待する回答全文が含まれるかを見るのではなく、何が不足し、どの主張に根拠がなく、どの補足が質問に不要かを個別に確認できます。

## この評価で確認できる範囲

必要語句、矛盾語、主張と根拠の対応を決めた規則で評価します。同じ入力から同じ結果を再現できますが、言い換えや文脈を含む意味上の妥当性を自動確定するものではありません。点数だけで判断せず、質問、回答、根拠、各表の判定理由を併せて確認します。

## うまく動かないとき

- `question`、`expected_answer`、`generated_answer` が空でないか確認する
- `expected_points`、`evidence`、`answer_claims` が配列になっているか確認する
- 回答要素番号、根拠番号、主張番号が重複していないか確認する
- 主張の本文が `generated_answer` に含まれているか確認する
- 主張が参照する根拠番号と回答要素番号が入力内に存在するか確認する
