# system02 契約書のリスク審査

契約書を登録し、AIが検出した条項ごとのリスクと根拠を確認するテーマです。単一文書の審査、文書比較、審査履歴を同じ画面群で扱います。

## このテーマでできるようになること

- PDF、docx、txtまたは画面へ入力した契約書をLM StudioのローカルLLMで審査し、リスクの種類、重要度、根拠箇所を確認できる
- 2つの契約書を順番に審査・比較し、追加・削除・変更された条項とリスク差を確認できる
- 条件を指定してPostgreSQLへ保存した審査結果を検索し、詳細を確認できる
- 保存済みの異なる2件を選び、追加・解消された指摘と推奨度の変化を比較できる
- LLM実行、Pydantic検証、PostgreSQL保存、MLflowトレース、画面表示のつながりを説明できる
- AIの審査結果を法的判断そのものとして扱わない理由を説明できる

## 最初に取り組むこと

1. Docker DesktopとLM Studioを起動し、StudyAI共有環境とローカルLLMを利用可能にする。
2. 単一審査画面で疑似契約書を入力し、審査視点を指定して実行する。
3. 検出されたリスクの重要度、根拠条文、説明、修正案を入力原文と照合する。
4. 比較審査画面で疑似比較文書を用意し、追加・削除・変更を確認する。
5. 審査履歴画面で期間・文書種別・総合リスクを指定して検索し、詳細を開く。
6. 異なる2件を選択して保存済み結果を比較する。

## 画面で確認すること

- 実行直後はリスクの説明に対応する原文抜粋が表示される
- 推奨度が低リスク=`そのまま締結可`、中リスク=`要修正後締結`、高リスク=`締結不推奨`になる
- 比較結果から、どちらの文書にどの条項があるか判別できる
- 履歴から過去の審査結果を再表示し、2件比較できる
- 履歴詳細では原文・原文抜粋が再表示されず、ファイルハッシュと審査結果だけが保存される
- 画面上部と結果に、法的確定判断ではないことが表示される

## 処理のつながり

```text
契約書登録 → 審査API → 条項抽出 → LM Studio → Pydantic検証 → 原文を除く結果をPostgreSQLへ保存 → MLflow記録 → 表示
2文書登録 → 文書A審査 → 文書B審査 → 条項対応付け → 差分審査 → 結果保存・表示（各処理は順次実行）
```

## うまく動かないとき

- 対応する文書形式であることを確認する
- 20MB以内、PDFは1文書50ページ以内であることを確認する
- LM Studioにチャット用モデルが読み込まれ、ローカルサーバーが起動していることを確認する
- 結果が空の場合は、文書から文字列を取得できているか確認する
- 表示された根拠が原文と一致しない場合は、実行ログとリスク判定処理を確認する
