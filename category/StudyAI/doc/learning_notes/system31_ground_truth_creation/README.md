# system31 評価用正解データの作成

質問、期待する回答、根拠文書、引用文、評価観点、人による確認記録を一つの正解データとして固定するテーマです。

## このテーマでできるようになること

- 評価用正解データに必要な情報を確認できる
- 根拠文書と引用文を追跡できる
- 評価観点と重みを評価前に固定できる
- 不足や不一致がある正解データを評価対象から外せる
- 人による承認と確認記録を残せる

## 最初に取り組むこと

1. StudyHubでsystem31を開く。
2. 「根拠付きの正解データを承認して保存」を選び、実行する。
3. 質問、期待する回答、根拠文書、引用文、評価観点、レビュー履歴を確認する。
4. 「根拠なしの下書きを作り不足を確認」を実行し、不足項目と利用可否を確認する。
5. 「文書に存在しない根拠を指定して差戻し」を実行し、引用不一致と差戻し記録を確認する。
6. 実行履歴から保存した結果を再表示する。

## 画面で確認すること

- 評価ケース番号、データセット名、確認状態、評価への利用可否が表示される
- 根拠文書番号と引用文の一致結果が表示される
- 正確性と根拠性の評価観点と重みが表示される
- 承認済みで不足がない正解データだけ評価へ利用可能になる
- 空の根拠や原文にない引用文は不足項目として表示される
- 確認者、確認記録、学習メモ、JSON保存状態が表示される

## 処理のつながり

画面から入力した正解データをStudyAI APIへ送ります。バックエンドは根拠の参照先、引用文、評価観点の重み、レビュー内容を確認し、評価ケース番号、品質確認、不足項目、利用可否を返します。結果と学習メモはsystem31専用のJSONへ保存します。

## この実験で確認できる範囲

正解データの構造、原文との文字列一致、評価観点、レビュー記録を確認します。回答の意味が正しいか、引用箇所だけで十分かは自動確定せず、人が確認します。

## うまく動かないとき

- evidenceが根拠文書番号と引用文を持つ配列になっているか確認する
- 引用文がsource_document.textに含まれているか確認する
- evaluation_viewpointsのweight合計が1になっているか確認する
- 承認または差戻しではreviewerとcommentを入力する
- 既定値へ戻してから再実行する
