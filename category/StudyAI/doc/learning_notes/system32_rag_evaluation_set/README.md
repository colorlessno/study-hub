# system32 RAG評価セットの実行

固定した正解データとRAG設定を使って検索結果と生成回答を評価し、失敗した段階と前回実行からの変化を確認するテーマです。

## このテーマでできるようになること

- 評価ケースごとに検索結果と生成回答を記録できる
- 検索失敗と生成失敗を分けて確認できる
- 検索成功率、生成成功率、回答評価の平均を確認できる
- 同じ評価セットの直前実行と指標を比較できる
- 実行結果がJSONへ保存され、再起動後も残ることを確認できる

## 最初に取り組むこと

1. StudyHubからsystem32を開く。
2. 「基準実行を保存」を選び、「実験を実行」を押す。
3. 3件のケースに、成功、検索失敗、生成失敗が1件ずつ表示されることを確認する。
4. 検索成功率と生成成功率がそれぞれ0.667になることを確認する。
5. 「検索結果を悪化させて前回との差を確認」を実行し、検索成功率の差と悪化した指標を確認する。
6. 実行履歴を更新し、保存した2回の実行が表示されることを確認する。

## 画面で確認すること

- 評価セット名、実行名、RAG設定が表示される
- 正解文書と上位検索結果を照合した結果がケースごとに表示される
- 生成回答と期待する回答を照合した結果がケースごとに表示される
- 失敗箇所が検索失敗または生成失敗として表示される
- 同じ評価セットの初回実行では比較対象なしと表示される
- 2回目以降は直前の実行名、指標差分、悪化した指標が表示される
- 保存状態に「JSONファイルへ保存済み」と表示される

## 入力データの見方

`dataset_name` は同じ条件で比較する評価セットの名前です。`rag_config` は検索処理、回答生成、Promptの各バージョンと、評価対象にする上位検索件数を固定します。

`ground_truth_cases` の各ケースには、質問、期待する回答、正解文書番号、実際の検索結果、実際の生成回答を記録します。検索結果や生成回答を変更すると、どの段階で評価が悪化したかを比較できます。

## 処理のつながり

画面から評価セットをAPIへ送ると、バックエンドが入力を検証し、ケース別の検索評価と生成評価を行います。その後、全体指標を集計し、同じ評価セットの直前実行との差を計算して、入力と結果をJSONへ保存します。

## うまく動かないとき

- `ground_truth_cases` が1件以上の配列になっているか確認する
- 各ケースの `case_id` が重複していないか確認する
- 質問、期待する回答、正解文書番号が入力されているか確認する
- `rag_config.top_k` が1以上の整数になっているか確認する
- 既定値へ戻してから基準実行をやり直す
