# system42 不正検知・異常検知AI

取引、ログイン、端末、過去の履歴を加点し、取引を許可、保留、拒否へ分け、確認後にfalse positive（誤検知）とfalse negative（見逃し）を記録するテーマです。

## このテーマでできるようになること

- リスク点を構成する取引・ログイン・端末・過去履歴の判定根拠を確認できる
- リスク点と保留・拒否の二つのしきい値を分けて確認できる
- 確認結果から誤検知・見逃しを判定し、それぞれの業務コストと監査記録を確認できる

## 最初に取り組むこと

1. StudyHubでsystem42を開く。
2. 「拒否判定例」を選んで実行し、金額倍率と各判定根拠の加点、リスク点、保留・拒否しきい値、拒否判定、アラートを確認する。
3. 「通常取引例」を選んで実行し、金額・端末・ログイン履歴の加点と許可判定を確認する。
4. 「保留判定例」を選んで実行し、同じリスク点でも拒否しきい値によって保留へ変わることを確認する。
5. 「誤検知例」を選んで実行し、正常取引を止めた結果がfalse positiveと誤検知コストとして記録されることを確認する。
6. 「見逃し例」を選んで実行し、不正取引を許可した結果がfalse negativeと見逃しコストとして記録されることを確認する。
7. 保存状態がJSON、保存済み、上限20件として表示され、実行結果を履歴から再表示できることを確認する。
8. StudyAIバックエンドを再起動し、再起動前の実行履歴と監査ログを再び表示できることを確認する。

## 画面で確認すること

- 金額、国、時間帯、端末、IP評価、ログイン履歴、過去履歴の加点が別々に表示される
- 加点の合計がリスク点として表示される
- リスク点と保留・拒否の二つのしきい値を比較できる
- 許可、保留、拒否の判定とアラートの有無が表示される
- 確認結果、false positive／false negative、誤判定コストが表示される
- 判定、アラート、確認結果、評価結果がStudyAIバックエンドの実行履歴と監査ログへ保存される
- JSON保存の状態と保存件数が表示され、再起動後も直近20件の履歴が復元される

## 処理のつながり

画面の取引情報、通常時の傾向、端末情報、ログイン履歴、過去パターン、判定ルール、確認結果、誤判定コストをStudyAI APIへ送ります。APIは各根拠を加点してリスク点を算出し、許可、保留、拒否を決めます。人間の確認結果がある場合は誤検知または見逃しを判定し、そのコストと監査記録を`data/enterprise_ai/system42_runs.json`へUTF-8で保存します。履歴は新しい順に20件まで保持され、StudyAIバックエンドの起動時に復元されます。

## この実験で確認できる範囲

教材用の規則に基づくリスク点の算出です。実際の決済停止や外部の不正検知サービスとの通信は行いませんが、入力と確認結果はブラウザ内だけで処理せずStudyAI APIへ送信し、判定・アラート・誤検知・見逃し・コストをバックエンドの実行履歴へ保存します。

## うまく動かないとき

- transaction_eventとaccount_profileにamountがあるか確認する
- login_historyにfailed_attemptsとnew_locationがあるか確認する
- rule_thresholdsにamount_multiplier、risk_hold、risk_rejectがあるか確認する
- risk_holdとrisk_rejectが0から1の範囲か確認する
- confirmation_resultのstatusがpendingまたはreviewed、actual_outcomeがlegitimateまたはfraudになっているか確認する
- 既定値へ戻してから再実行する
