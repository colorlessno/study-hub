# system18 文章の類似検索

検索文と候補文書をLM StudioのEmbeddingモデルでベクトル化し、cosine類似度と検索順位を確認するテーマです。

## このテーマでできるようになること

- 検索文に近い候補文書を類似度順に確認できる
- 使用したEmbeddingモデル、ベクトル次元、保存件数を確認できる
- 取得件数を変えたときの結果の違いを確認できる
- 類似度が高いことと、質問へ正しく答えられることを区別できる
- 同じ単語を含まない言い換えでも、意味が近い文章を検索できることを確認できる

## 最初に取り組むこと

1. 「実験条件」の`query`に検索したい文章を入力する。
2. `documents`に比較する候補文書を複数入力する。
3. `top_k`に取得件数を入力して「実行」を押す。
4. 順位、根拠文、cosine類似度を確認する。
5. 使用モデル、ベクトル次元、JSONファイルへの保存結果を確認する。

## 画面で確認すること

- 検索文と同じ単語を含まない言い換えが、意味の近さによって上位になる
- 結果が類似度の高い順に表示される
- `top_k`を小さくすると表示件数が減る
- 関係のない文章は類似度が低くなる
- 根拠文とEmbeddingベクトルがJSONファイルの実行履歴に保存される
- StudyAIを再起動しても保存した実行履歴を読み戻せる

## 処理のつながり

画面から検索文と候補文書をStudyAI APIへ送ります。サーバーは検索文をLM StudioのEmbedding APIへ送って応答を受け取り、その後に候補文書を入力順に一件ずつ送ります。返されたベクトル同士のcosine類似度を計算し、検索結果と文書ベクトルをJSONファイルの実行履歴へ保存して、類似度の高い順に指定件数まで画面へ返します。

## この実験で確認できる範囲

この画面はLM Studioで読み込んだ`text-embedding-nomic-embed-text-v1.5`を使用します。検索結果とEmbeddingベクトルは`data/ai_learning/system18_runs.json`へ最新20件を保存し、StudyAI再起動後も読み戻します。ベクトルデータベースは使用していないため、大量文書や本番検索の性能確認は対象外です。検索品質を評価するときは、正解文書を決めて検索結果と照合します。

## うまく動かないとき

- `documents`がJSONの配列になっているか確認する。
- `top_k`が候補文書数を超えていないか確認する。
- StudyAIの共有環境が起動しているか確認する。
- LM Studioが5858番ポートで起動し、`text-embedding-nomic-embed-text-v1.5`が読み込まれているか確認する。
