# system36 実行Traceの保存

入力、検索根拠、モデル設定、Prompt、出力、評価を一つのTraceにまとめ、機密値をマスクしてJSONへ保存するテーマです。

## このテーマでできるようになること

- 一回の実行に関係する条件、根拠、出力、評価を一つのTraceとして確認できる
- 再実行に必要な情報の不足を見つけられる
- 機密値をマスクしてから保存する理由を確認できる
- 保存済みTraceを一覧から開き、記録内容を再確認できる

## 最初に取り組むこと

1. StudyHubでsystem36を開く。
2. 「再実行できるTrace」を実行し、記録内容、評価との対応、保存状態を確認する。
3. 「不足項目があるTrace」を実行し、不足項目と再実行できない理由を確認する。
4. 「機密値をマスクするTrace」を実行し、連絡先が`[MASKED]`へ置き換わることを確認する。
5. 実行履歴から各Traceを開き、入力と結果を再表示する。

## 画面で確認すること

- 入力、検索根拠、モデル設定、Prompt本文・版、出力、評価が一つの表に表示される
- 評価番号、評価状態、評価点がTraceと対応している
- 必要な情報がない場合は、不足項目と再実行条件が表示される
- マスク対象語はTrace詳細に残らず、マスク対象語そのものも保存されない
- Trace番号、改変確認用ハッシュ、保存状態、保存方針が表示される
- バックエンドを再起動しても最新20件の履歴が読み戻される

## 処理のつながり

画面から実行済みAI処理の情報とマスク方針をAPIへ送ります。APIは型を検証し、指定した値を置換してからTrace番号と改変確認用ハッシュを作り、最新20件をJSONへ保存します。画面は保存済み履歴をAPIから読み、選んだTraceの入力と結果を再表示します。

## この実験で確認できる範囲

実行済みの情報をTraceとして保存・再表示する範囲を扱います。AIモデルの再実行、保存済みTraceの更新・削除・全文検索、本番用の暗号化、権限制御、保持期限管理は扱いません。

## うまく動かないとき

- 入力欄全体がJSONオブジェクトか確認する
- retrieved_contextが配列、model_configとevaluationがJSONオブジェクトか確認する
- masking_policyのtermsが文字列の配列か確認する
- 既定値へ戻してから再実行する
